# SnapDrill 数据契约

- 状态：首版数据与安全要求
- 最后确认：2026-07-25

本文承接 [PRD.md](PRD.md)，定义所有采集、编辑、导入、备份和恢复路径必须共同遵守的数据
不变量。当前没有外部用户，因此可以删除旧开发格式；首次外部分发前必须实现并冻结正式格式。

## 1. 所有权与范围

产品只有一个本地资料库，不含用户可见或备份可见的 Profile / Workspace 身份。

完整资料库包含：

- 已保存资料的稳定 ID、正文、答案文字和时间；
- 每条资料的主图与答案图；
- 分类、来源、级别、标签及其关联；
- 仍处于五秒撤销窗口内的删除截止时间；
- 解释上述内容所需的 schema 和完整性 metadata。

未保存草稿、设备偏好、缓存、临时导出、诊断和恢复事故材料不属于资料库。清空资料库不能
顺带删除这些内容。Review、SmartPaper、Pro、Profile 或其他仅因旧实现存在的状态不进入正式
备份；新增备份内容必须先由 PRD 或本文明确批准，不能由现有 model 反向扩大 wire。

## 2. 资料与字段

- 每条资料至少有非空正文或一张主图。
- `nil` 与用户明确保存的空字符串语义不同，必须原样往返。
- 每条资料最多一张主图和一张答案图；未知或重复图片 role 在写入前拒绝。
- 字段和值使用稳定 UUID 作为身份，名称不是关系键。
- 字段名在资料库内唯一；值名在所属字段内唯一。比较保存后的 UTF-8 字节，不自动做大小写
  折叠或 Unicode normalization。
- 内建字段为 `category`、`source`、`level` 和 `tag`。`tag` 是多值，其余为单值。
- `single -> multi` 可直接转换；`multi -> single` 只有在所有资料最多关联一个值时整体提交，
  否则零部分修改并报告违反数量。

## 3. 接受边界

| 数据 | 上限 |
|---|---|
| 正文、答案文字 | 每个字段最多 1 MiB UTF-8 |
| 字段名、值名 | 最多 1,024 byte UTF-8 |
| SF Symbol 名称 | 最多 256 byte UTF-8 |
| 规范化 JPEG | 每张最多 50 MiB；宽、高各不超过 2,000 pixel |

无效 UTF-8、整数溢出或规范化后超限必须在 mutation 前拒绝。不得静默截断、丢字段、部分
写入或把防御性运行时限制宣传为用户资料库总量上限。

## 4. 图片

- 内容真相是用户确认裁剪和方向后的 App-managed JPEG，不承诺保留来源原始字节。
- 入库前烘焙方向和颜色，透明像素铺白，并移除 EXIF GPS / 位置信息。
- 持久化路径必须是安全相对路径：非空、使用 `/`、无绝对路径、反斜杠、空组件、`.`、`..`
  或控制字符。
- 读、写、删和恢复都要校验路径与可信根的 containment；词法合法不等于文件可信。
- 数据行与必需图片必须一致提交。不可读主图不能被解释为成功或静默置空。

## 5. 草稿与删除

- 未保存采集草稿支持崩溃恢复，不按时间自动删除。
- 草稿只在正式保存成功或用户明确丢弃后删除。
- 删除资料后提供五秒绝对撤销期限；后台和重启不能缩短。
- 期限结束后硬删除必须幂等，并同时处理 App-managed 图片和关联。

## 6. 完整操作

完整备份、恢复、清空资料库和 store recovery 是互斥的 complete operation。开始前必须取得
稳定 prestate 并阻止新的资料库 mutation；成功或失败都给出 all-or-nothing 结果。

选中资料导出 PDF / CSV 是 partial export，只读取稳定选择快照，不得宣称代表完整资料库。
CSV 所有用户输入或 OCR 文字先按 CSV 规则转义；若字段以 `=`、`+`、`-` 或 `@` 开头，必须在
字段前加 tab 使表格软件按文本处理。四种前缀都要有回归测试，不能依赖调用方自行净化。

## 7. 备份

首版必须提供用户管理的单文件完整备份：

- 格式有明确版本、完整性校验和容量防护；
- 不包含 Profile 身份；
- writer 成功生成的文件必须能被同版 reader 恢复；
- 恶意、损坏、未知版本或超限文件在修改现有资料前拒绝；
- 读取外部路径和文件时拒绝 traversal、symlink 和异常节点；
- 大图片和大资料库使用有界、流式 I/O，不全量物化到内存；
- 恢复失败时现有资料库保持不变；
- 导出文件可以不加密，但分享前提示可能包含私人文字与图片。

正式 wire 的 schema、版本和 golden fixtures 必须随实现放在 Data 代码与测试中。外部分发前，
代码、fixture 和本文共同评审；不再维护脱离实现的候选 wire 文档或审计语料。

## 8. 启动与恢复

- 只有确认不存在任何资料库、事务或恢复材料时，才能创建首次使用的空库。
- selector 损坏、store 打不开、恢复中断或回滚失败都进入明确恢复状态，不能伪装成空库。
- 损坏 store 或恢复双失败后，用户可以选择以空库继续，但相关源材料默认保留，直到用户明确
  删除或成功“导出并删除”。
- 缓存和临时目录不能保存唯一 rollback 副本或用户数据真相。

## 9. 兼容起点

当前尚未向 PO 以外的用户提供构建，因此：

- 开发期 Profile 数据和旧备份可以被明确拒绝或重置；
- 不需要为未发布格式编写迁移；
- 不得把旧 Profile wire 带入正式版本。

首次让外部用户获得可下载构建之前，必须冻结本机升级、正式备份和恢复兼容策略。从那一刻
开始，后续版本不能静默丢弃已保存资料或拒绝由正式旧版生成的合法备份。
