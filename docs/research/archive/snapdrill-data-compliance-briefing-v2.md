## 1. 背景与主体现状【事实】

- **产品**：iOS 家庭教育 app。家长拍照存档孩子练习题 → OCR 文字识别 → 多维分类 → 间隔复习 → PDF 导出。
- **发布模式**：一个产品两区域发行版 —— 中国大陆"小本本-智能错题本" + 海外"SnapDrill"（非两个独立产品）。
- **主体现状**：
  - 中国大陆：**暂无公司主体**，当前用**个人** Apple Developer 账号（YIMING LIAO，Team `W5A8THDKW8`）
  - 海外：NotBad Labs L.L.C.（美国，已成立）
  - 所有 Firebase 资源现挂在美国 LLC 名下（Google 项目）

## 3. 核心问题一：Firebase 跨境

**【复核收敛·高可信】**（多份独立分析一致）：
1. 国内版只要向 Firebase（Google 美国）发送**可识别或可关联到自然人**的信息，开发者即构成 PIPL 下「个人信息处理者」+「跨境/出境」，**责任在开发者，不因数据"经由 Google"或"存于 Apple 设备"转移给 Apple**。
2. Firebase Installation ID（FID）、崩溃设备元数据属「**去标识化**」而非「**匿名化**」，PIPL「识别+关联」双路径下仍应按**个人信息**处理。
3. **技术盲点**：`FirebaseApp.configure()` 在 SDK 初始化时即可能生成并上报 FID。**仅在 UI 层 opt-in 关闭不足以阻止出境**，需禁用所有 FID 依赖服务的 auto-initialization。
4. 跨境的「**单独同意 + 增强告知（境外接收方）+ PIPIA**」属基础义务，**无流量豁免**。
5. "国内个人账号 → 美国 LLC 的 Firebase"是跨实体+跨境结构，法律上不禁止，**落地几乎不可行**（个人难以作为 PIPIA 申报主体、与 Google 的数据处理协议跨法域执行性弱）。

**【待裁定】**：
- 跨境豁免门槛的**具体数字与单位**：复核分析引用《促进和规范数据跨境流动规定》第5条第(四)项为"年累计 <10 万**人**非敏感 PI 可豁免标准合同/安全评估/认证；敏感（含儿童）适用 1 万人门槛"。**请确认该数字、单位、适用条件**（不同复核来源对此曾有"人/人次"的不一致，我们不敢自行采信）。

## 4. 核心问题二：主体 + App 备案（我们认为这才是公开上架的真正瓶颈）

**【复核收敛·高可信】 + 引用待您核验**：
1. Apple 自 **2023-09-29** 起要求中国大陆区**新提审** App 提供 ICP 备案号；**2024-04-01** 起强校验"App 名称 + ICP 备案号"与工信部记录一致。
2. 阿里云/腾讯云的 App 备案**要求购买中国大陆地域服务器（ECS 包年包月）**作为接入主体 —— **即便是零后端的纯本地 app 也必须挂一台境内服务器**才能备案。
3. **教育类目需"前置审批"**，据 2019 教育部办法仅签发给"教育行政部门/学校/企业/社会组织"，**自然人无法获取**；而"智能错题本 + 辅导孩子练习题"**极易被认定为教育服务**。
4. **国际开发者（全球账号+境外服务器）目前"提示但不强制"备案**，但多家律所（Linklaters 引述 AppInChina CEO）判断该豁免**不可持续**。
5. **"双减"政策风险**：禁"拍照搜题"类。SnapDrill 是"拍照**存档错题**"非"搜答案"，但**命名+功能需在 App Store 描述与隐私政策明确"不提供答案/解析"**，降低被误归类下架的风险。

**【待裁定】（对您的关键提问，见 §9）**：
- 个人主体能否以**非教育类目（工具/效率）**完成备案并规避教育前置审批？尺度因省而异。
- 一旦定性为教育服务，个人主体路径是否实际走死？

## 5. 核心问题三：儿童/未成年人信息（多源裁定为保守对待）

**【复核收敛·高可信】**（注：一份较乐观的分析认为"无身份信息即非个人信息"，但更严谨的深度复核与我们均倾向保守，理由如下）：
- 虽不收集姓名等直接标识，但**题目图片 + OCR 文本 + 笔迹 + 年级/学校上下文**组成的题库，在"识别+关联"执法实践下**很可能被认定为儿童个人信息**（尤其 OCR 文本含学校/班级/手写姓名时）。
- **监护人代为处理不改变信息本身"儿童个人信息"的定性**；监护人同意是合法性基础，非豁免特殊保护的依据。
- PIPL 第28条（不满14周岁=敏感个人信息）、第31条（监护人同意+专门处理规则）、《儿童个人信息网络保护规定》（2019）、《未成年人网络保护条例》（2024-01-01 生效）逐层加码。
- **同业模板**（小猿搜题/作业帮/题拍拍）：14周岁弹窗确认 + 监护人同意 + 独立《儿童隐私保护政策》 + "境内数据不出境"承诺 + 学生/家长双模式。

**【待裁定】**：
- "练习题内容"是否构成"儿童个人信息"**无直接判例**；实际执法是否认定取决于具体场景。**请给出本场景下的定性与最低合规动作**（是否需独立儿童处理规则、14周岁年龄门、监护人同意机制）。

## 6. 端侧 AI 备案【复核收敛·高可信：不需要】

- 端侧 Apple Vision（OCR）+ Foundation Models（分类）+ 间隔复习本地排序，**不向境内公众"生成"内容、不具舆论属性/社会动员能力** → 不触发《生成式 AI 服务管理暂行办法》算法备案/生成式 AI 备案。
- **重新评估触发条件**：未来若引入**云端**生成式 AI（自动讲题）、面向公众的题库/社区、个性化推荐流 —— 需另行评估。
- 建议在隐私政策**主动写明"端侧本地 AI、不向公众提供生成式服务"**，消除监管误判。

## 7. 隐私政策修正【事实 + 必备要素】

**现状硬伤**：①仍提 ATT（须删）②未区分中国大陆/海外数据流向（违反 PIPL 第17条"真实准确完整告知"）。

**PIPL 第17条必备 + 加项**（请您补全/校正）：处理者名称及联系方式、处理目的/方式/种类/保存期限、个人行权方式和程序；自动化决策（间隔复习排序）的拒绝/调整选项（第24条）；跨境加项（第39条，仅方案B）；PIPIA（第55条，仅方案B）；儿童专门处理规则 + 监护人同意。

**建议双轨**：中国大陆版（本地处理、无 Firebase、iCloud/GCBD 披露、儿童信息提示、备案号、PIPL 必备要素）/ 海外版（Firebase opt-in 披露、GDPR/CCPA 权利）。
> 注：官网 URL 结构已定为产品级子目录 `notbadhq.com/snapdrill/privacy`（含中英 + 区域差异附录），非根级。

## 8. 拟议路线图（分阶段）—— 产品方方案，请评估

**关键区分：TestFlight（内测）不需要 ICP 备案；ICP 备案是公开上架 App Store 的要求。** 因此可分两阶段，当前阶段不被备案/主体卡死：

| 阶段 | 主体 | ICP备案 | Firebase | 商业化 | 可立即执行？ |
|---|---|---|---|---|---|
| **Phase 1：TestFlight 验 PMF** | 个人账号 | **不需要** | **移除**（否则国内测试者数据当场跨境）| 免费 | ✅ 现在即可 |
| **Phase 2：国内公开上架** | **需中国公司主体** | 需要（+挂境内服务器 + 避开教育类目 / 或办教育前置审批）| 已移除 | 视主体定 | PMF 验证后 |

**方案 A（推荐基线）：中国大陆版彻底移除 Firebase**
- 跨境义务：**无**（不触发 PIPL 第38-39条跨境章节）
- 剩余 PIPL 主义务收缩为：隐私政策合规（第17条）+ 用户权利响应（零账号下提供"清空本地数据"）+ 安全保护义务（第51条，个人可简化）+ 儿童特殊规则
- 崩溃诊断替代：用 Apple 原生 **MetricKit / Xcode Organizer**（设备→Apple，不跨境第三方），不必为此保留 Firebase
- 实现：①**运行时止血**（半天内）—— `NoOpAnalyticsService` + 换 `DependencyContainer` 一行 + 不调 `FirebaseBootstrap` + 删 plist；②**合规基线**（更彻底）—— 国内 build target **编译层不链接** Firebase SDK（`#if` 分支 / Release-CN 配置）+ **抓包验证首启无 Google 域名请求**

**方案 B（不推荐当前阶段）：保留 opt-in Firebase + 完整跨境手续**
- 即便豁免标准合同备案，仍需：单独同意 + 增强告知 + PIPIA 留档 + 必要性证明 + 与 Google 数据处理协议 + 安全保障措施（约 0.5–1 个 PIPIA 项目工作量），且个人主体跨境位置弱。

## 9. 给执业律师的问题清单（决策优先排序）

**第一组：方案 A（国内无 Firebase）后的剩余义务**
1. 国内版不集成/不初始化 Firebase、错题图片/OCR/分类均端侧、无后端服务器，开发者对这部分是否仍构成"对外提供"？最低合规动作有哪些？
2. 纯本地 + 用户自有 iCloud（中国区 GCBD 运营）场景下，隐私政策应如何界定开发者 / Apple / 云上贵州的角色边界？

**第二组：主体与备案（最关键）**
3. 个人主体能否以**非教育类目**完成 App 备案、规避教育前置审批？本产品被认定为"教育"的风险有多高？
4. "智能错题本"是否需在描述/政策中明确"不提供答案/解析"以规避"拍照搜题/双减"政策风险？
5. 是否建议**新设中国大陆公司主体**？若是，注册地/类型/对备案与商业化的影响？
6. 跨境豁免门槛的准确数字、单位与适用条件（§3 待裁定项）？

**第三组：儿童/未成年人**
7. 本场景（家长拍练习题、不收集姓名）是否触发儿童个人信息特殊保护？需要哪些最低动作（独立处理规则 / 14周岁年龄门 / 监护人同意 / 合规审计）？

**第四组：未来**
8. 未来上线云端 AI 讲题、学习画像、社区/推荐，会新增哪些备案/未成年人义务？
