# M-000 Meta-Vision

## §1 定位

M-000是元规则的元规则：规定规则系统如何可靠、演进、溯源；具体动作下沉M-001~M-006。

## §2 认识论

可复现是冗余的基础，独立趋同是高质量冗余的目标。不同先验路径趋同才是高质量冗余；单一模型稳定复现错误不构成证据。多方价值不在多数投票，而在让差异暴露假设、边界、错误。

## §3 适用范围

任何任务默认多方；这是价值选择：质量优先于效率，同时承认token、时间、注意力成本。用户可显式豁免为单方，不预设判据矩阵。豁免写入裁决日志并归类，允许3-6个月后自然涌现判据。数据流转最小化：跨厂商共享须用户批准；脱敏策略由用户定义。

## §4 失败/降级/裁决

失败：无法达成共识、污染、退化；结构性同源一致见§7。降级：默认至少两方独立判断；降级是受限保底。用户>24小时无响应时保守降级：双核仅可执行可逆操作；不可逆事项等待。裁决：用户最高。裁决智能体清单当前为Claude+Codex，由用户维护；变更记入裁决日志，不视为M-000修订。双核同意默认通过；任一方不可用时自动通过权失效，所有事项回退用户。不可逆=跨本地工作区边界、产生外部副作用、对外承诺；修改M-000、法律/财务承诺、产品方向实质改变也必须上交。可量化事项叠加自动化测试；平局或不可量化时回到裁决规则。

## §5 元规则的元规则

智能体有提案权，用户有批准权。M-000正文（不含frontmatter、§8指针表、changelog）≤1500字。新增条款必须证明无法下沉到M-001~M-006或skill。不强制一进一出，允许新情况进入，由硬上限约束总量。M-001~M-006采用触发场景、4周试用、周期精简；长尾经验进按需加载技能。M-001~M-006实质性修订（非笔误、格式、引用更新）须经用户批准，与M-000一致。M-000每12个月强制review，与`max_age_days`联动。裁决日志为`docs/meta/user-decision-log.md`，append-only，字段=时间/冲突/裁决/理由/是否触发修订。新裁决若冲突历史，必须显式声明Overrule，否则无效。

## §6 与产品 vision 关系

M-000与产品vision平级：前者定义协作可靠性，后者定义产品方向。冲突时不预设倾向，必须上交用户，并附结构化分析：冲突性质、可逆性、双方拉锯点、推荐路径、理由。裁决沉淀为先例，但不自动改写元规则；改写仍走正式流程。

## §7 风险接受与外部冲击

主笔轮换有认知摩擦与质量波动风险，但不构成放弃轮换的理由；单一主笔累积偏向代价更高。系统提醒轮换，是否轮换由用户裁决，不强制。异源=独立模型权重+独立训练谱系；智能体=独立模型+独立运行实例+独立上下文；独立=中间产物互不可见+独立推理路径。伪共识=训练同源+一致结论。辅助方沉默不构成认同；关键决策须辅助方明确表态，无表态默认上交。异源辅助方提出强烈、具体、可证伪反对时，双核自动通过权失效并触发用户裁决。识别细则见M-001、M-005。服务发生重大或持续变化（关停、严重降级、价格跳变、能力实质漂移）时，自动触发M-000 review；历史裁决日志保留，适用性可复审。

## §8 演进愿景与下游派生

系统保持核心稳定、中层演化、长尾外置；概念单一权威，结论可追溯证据、分歧、裁决；反对规则堆叠、术语漂移和仪式化流程。M-001~M-006不得与M-000冲突；冲突以M-000为准。

| 文档 | 职能 |
|---|---|
| M-001 协作工作流规约 | 规定多方分工、独立工作、上下文加载（含主笔轮换提议机制） |
| M-002 分歧裁决与裁决日志 | 规定裁决流程、证据等级、变更记录 |
| M-003 技能库治理 | 规定经验如何沉淀、加载、淘汰 |
| M-004 降级操作手册 | 规定服务受限时的降级路径与停止等待判据 |
| M-005 质量判据与退化检测 | 规定产出质量度量、伪共识识别、自动警报 |
| M-006 数据治理 | 规定跨厂商数据共享、最小化、脱敏、prompt injection 防御 |
