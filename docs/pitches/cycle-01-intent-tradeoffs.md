## 第一组 · 身份与边界（最高杠杆，答案塑造其余一切）

**Q1 · Cycle 1 打磨到哪算"够好"？** `耐久`
当前你"打磨好再发"，但核心闭环是零用户的未验证赌注。
- **A** 打磨**全表面**（采集+管理+导出+复习+Multi-Profile+动态维度）到质量地板再上 TF——发一个完整连贯的产品。
- **B** 只把**采集→管理→导出主干**打磨到地板就发；复习/SmartPaper/高级统计**冻结为"在但未验证"**，让真实使用决定要不要投入打磨。
- *为什么*：价值链 `采集>管理>导出`、复习/组卷被 vision 标"附加"。把未验证的附加功能也打磨到地板 = 可能在拖反馈、且烧 appetite。
- *何时推翻*：dogfood 发现复习才是让你回来用的留存钩子 → A；发现你自己从不开复习/组卷 → B。

**Q2 · 主操作者身份：定了还是暂定？** `⚠️population`
"小学家长是主用户"(H2) 是你要 design 整个 app 的**定论**，还是 Cycle 1+ 要主动验证、保持可重开的**暂定赌注**？
- **A** 定论——parent-first 的 UI/文案/默认/路线全押"家长操作"，不再为"学生自己操作"留两手。
- **B** 暂定——设计偏家长，但**显式标 H2 未验证**、留住"学生自用"（尤其初中自用）路径，等真实人群数据再定。
- *附带真矛盾*：H2-SM2 假设"孩子自评复习"，但唯一写出的复习旅程是初三生、家长几乎不复习——**身份在复习这里自相矛盾**，这题一并裁。
- *为什么*：几乎每个 UI 语气/onboarding/复杂度决策都从这条派生。
- *何时推翻*：TF/访谈显示一批 12-15 岁学生自己在用，或家长报告"孩子根本不碰" → 重置。

**Q3 · 产品能不能"评判"孩子？** `耐久`
"存档不辅导"已钉死，但**边界**没画：app 能不能对孩子下判断？
- **A** 只做归档——难度是用户自己的标签、AI 只是可确认的预填、"薄弱"只从用户自己的复习自评里派生，**app 绝不独立判断能力**。
- **B** 允许轻度评判——让 AI 推断难度成为一等信号、让"薄弱分析"框定孩子能力（"几何薄弱"），以此让 Smart Paper / 高级统计更有说服力。
- *为什么*：AI 自动标难度 + 薄弱排行已经游走在"评判 vs 归档"的线上；这条决定 Pro 转化引擎的语气底线。
- *何时推翻*：家长在 dogfood 里对"app 说这题难/你娃几何弱"反应正面并主动要 → 松向 B。

**Q4 · 不贩卖焦虑 vs Pro 转化的说服力。** `耐久`
P5 钉了"不卖教育焦虑"（无 streak/倒计时/比较），但 Pro 漏斗**故意靠**"薄弱排行→一键生成针对练习卷"去打动家长。线画哪？
- **A** 严格中立——薄弱分析只给中性事实（"几何 N 题待加强"），绝不暗示孩子有缺陷/制造紧迫，接受这会削弱 Pro 转化。
- **B** 有节制地说服——允许"针对薄弱环节"这类**激励性**框定做转化引擎，只在"编造的紧迫/倒计时"处划线。
- *为什么*：两个钉死的值（不焦虑 vs 故意设计的转化引擎）正面冲突，转化的说服力恰恰依赖家长感到"有差距要补"。
- *何时推翻*：中性框定转化率几乎为零（家长对"待加强"无感）→ 被迫松向 B；或家长反感任何缺陷暗示 → 锁死 A。

## 第二组 · 核心闭环形态

**Q5 · 采集单元：手动逐题裁剪 vs AI 整页拆题。** `形态`
QuestionSplittingService（PoC #626、80% 准确门槛）整套建好但**没接进任何 UI**；今天每道多题页都得逐题 crop→OCR→存、重复 N 次。
- **A** 只保留手动逐题裁剪——"裁剪"本身就是人"这道值得留"的刻意动作；**冻结/删掉**没用的拆题器（简洁 > 自动化）。
- **B** PoC 过了就上 AI 整页拆题——家长拍一张整卷、app 提议 N 道、家长删减；高频"一张图 4 道题"场景少点很多重复 tap。
- **C** 先搁——服务冻在 PoC 门后，只有 dogfood 证明"逐题裁剪是头号摩擦"才重启。
- *为什么*：采集域最大的产品形态分叉——手动=低量刻意错题归档，整页拆=高量作业数字化，两者是不同的英雄工作流。
- *何时推翻*：dogfood 数一次 session 裁几次——反复对一张卷裁 5+ 次 → B 的拉力变真；大多 1 题/张 → A。

**Q6 · 复习"入列"：全自动 vs 用户挑。** `形态·实证最重要`
**当前是被数据模型默认值偷偷定的**：`ReviewItemModel.nextReviewAt = .distantPast` = 存即"今天到期"。存 200 题 = 200 张"今天到期"。
- **A** 全自动入列（现状）——零摩擦填充复习，但纯归档用户被塞一个他没要的、令人愧疚的巨大 backlog。
- **B** 用户挑/策展——归档 ≠ 报名复习；用户显式标某些题为复习卡（或复习只拉一个"学习集"）；护住"纯归档工具"定位。
- **C** 懒加载——存了不算到期，首次进复习才变"到期"，或软上限不让 backlog 爆。
- *为什么*：复习域最大形态分叉，且现在是个 SwiftData 默认值在替你做产品决策，正面撞 H3"需求是存档不是刷题"。
- *何时推翻*：归档 100+ 题后，"N 道待复习"感觉是有用提示还是唠叨负担？测试家长问"怎么关掉" → B/C。

**Q7 · SmartPaper 组卷的定位。** `形态`
生成按钮整体 Pro-gated、免费"随机选题"路径根本没接（实际调了 SM-2 选题）、StoreKit 没上线——**组卷现在 100% 点不到**。
- **A** 核心打印价值（免费化）——"把题库变成可打印练习卷"才是家长真要的导出 payoff；现在就接免费随机路径、免费发，精准选题作为唯一 Pro delta。
- **B** Pro 转化引擎（保持 gated）——组卷是 ADR-001 的 Pro 招牌，接受它在 StoreKit(#479) 前点不到，本 cycle 不投免费路径。
- **C** 冻结的 niche——组卷是建在"未验证复习"之上的未验证赌注，冻结（入口"敬请期待"）、Cycle 1 完全不碰。
- *为什么*：Cycle 1 是"打磨核心闭环、不加功能"。组卷若是核心打印价值，坏掉的免费路径就是 Cycle-1 质量地板 bug；若是 Pro/niche，就正确地在范围外。
- *何时推翻*：dogfood 你/家长真去打印练习卷且想要选题帮助 → 核心；没人碰组卷、都用普通 PDF 导出 → B/C。

**Q8 · OCR 失败时：静默存图 vs 给补救路径。** `形态·补漏`
真实世界烂卷（昏暗/揉皱/红蓝黑笔）OCR 出空/乱码时——
- **A** 静默存图——绝不打断录入生命线，纯图片项也 OK，OCR 失败不打扰。
- **B** 暴露缺口——OCR 失败时给一个一键"补可搜索文字"的路径，否则这题进了库永远搜不到、组卷/复习也用不上。
- *为什么*：采集↔检索的接缝；静默护生命线但留下搜不到的死项，暴露则护下游价值但加一步。
- *何时推翻*：dogfood 大量纯图片项后来完全搜不到、找不回 → B；补救步几乎没人用 → A。

## 第三组 · 复习的定位

**Q9 · 复习是边缘附加值，还是暗藏的留存引擎？** `耐久`
- **A** 就是边缘附加值——接受低使用率是**预期**（不是 bug），冻结复习功能开发、保持薄 tab，把打磨预算转给采集/管理/导出。
- **B** 暗藏核心留存——复习可能是唯一把用户在归档后**带回来**的东西；投入做粘，把低 dogfood 使用率当可修的漏斗问题而非确认。
- *为什么*：决定复习在 Cycle 1+ 拿不拿 appetite，以及"低复习使用率"被读成系统正常还是坏了。"是否过度投入"全系于此。
- *何时推翻*：首批 TF 里相当比例的回访 session 是复习 → B；几乎无人回来复习 → A。

**Q10 · Cycle 1 给不给复习 appetite？** `Cycle-1 scoping`
复习有已知正确性 bug（GAP-R1：软删的题仍可能在 session 中出现）+ 上面那些结构未决。
- **A** 只修不重设计——只花力气关 GAP-R1，复习按现状发，**不**现在重开入列/上限/评分/重学设计（Shape Up appetite 纪律）。
- **B** 现在 shape 一个小复习赌注——GAP-R1 是"入列/backlog 模型(Q6)欠定"的症状，TF 前先解决结构分叉，让 dogfood 测对的设计而非占位。
- *为什么*：把抽象的"是否过度投入"变成对一个真 bug 的具体花费决定。
- *何时推翻*：只关 GAP-R1 就能诚实 dogfood → A；一修就被迫先定义"到期"是什么 → B。

## 第四组 · 导出 / 打印

**Q11 · 系统打印：一等专属流程 vs 分享菜单里的一项。** `耐久`
vision 反复叫打印"价值链终点/核心 payoff"，但代码只生成 PDF 再丢进 ShareLink/系统分享。
- **A** 打印就是 payoff——建专属打印流（UIPrintInteractionController + 真 1/2/4 每页排版），"打印"作为独立动词/按钮，Cycle 1 打磨到地板。
- **B** 打印是导出附属——继续搭车系统分享菜单（AirPrint 只是其中一项），不投专属打印管线，现状够发。
- *为什么*：决定价值链终点配不配一等待遇。
- *何时推翻*：家长在打印步卡顿（多 tap、排版错、AirPrint 不明显）→ A；导出后基本不打印 → B。

**Q12 · ShareCard 的角色。** `耐久`
ShareCardView 渲染带"SnapDrill 错题卡"品牌标的卡片——这是 app 里**唯一**对外（给别人）的出口。
- **A** 增长杠杆——当作有意的口碑获客面，留品牌标、优化到值得分享，接受它是唯一对外面（尽管"不是社交产品"）。
- **B** 私人工具/去品牌——只是把一道题发给别人（如发给家教）的便利；弱化/去掉 SnapDrill 品牌、不为传播优化。
- **C** 砍掉——ShareCard 是不服务采集/管理/导出的 vanity scope、额外渲染路径，按 Cycle 1 不加功能+简洁优先冻结/移除。
- *为什么*：唯一的对外增长面 vs "不是社交产品"的钉死立场冲突。
- *何时推翻*：上线后自然增长弱、且 ShareCard 分享与安装相关 → A；基本没人用 → C。

## 第五组 · 商业与发布

**Q13 · Pro 锚点：iCloud 同步定了吗？** `use-dependent`
免费层是完整单机产品，business-model 自己警告"手动 .zip + 单机可能已够用 → Pro 转化可能趋零"。
- **A** 定了——iCloud 同步就是 Pro 核心引擎，承诺它，低转化风险上线后再管。
- **B** 留口——投 CloudKit(#485) 前把 Pro 锚点当未决；愿意让更重的导出/打印/批量能力（而非同步）成为主付费价值，若多设备需求被证明弱。
- *为什么*：决定先投哪个被阻塞功能（#485 同步 vs 更强导出），以及 Pro 故事押在哪。
- *何时推翻*：dogfood/访谈显示单机+手动备份完全够（不觉得要为同步付费）→ B；明确的多设备付费意愿 → A。

**Q14 · CN-first 盲验 vs 提前上 global 做埋点。** `use-dependent`
ADR-003 说 global 在"PMF 验证后"才上；但 CN 是 Firebase-free → 验 PMF 的阶段**零行为埋点**（只有 ASC+访谈+TF）。
- **A** 保持 CN-first——接受盲验（靠 ASC+访谈），global+Firebase 延后到 PMF 验证后。
- **B** 提前 global——正因 CN 故意盲，提前/并行上 global（带埋点）build 让 PMF 真能量化，接受双地区工程成本提前。
- *为什么*：结构性矛盾——本该验 PMF 的阶段恰恰看不到行为数据。
- *何时推翻*：CN TF 信号太少/太噪、合理窗口内做不出自信的 PMF 判断 → 盲验路线被证伪 → B。

**Q15 · Multi-Profile：发布 Must vs 可延后 Could。** `⚠️population`
Multi-Profile 被钉为多孩家庭"刚需"且放免费层，但这建在"多孩家庭(a)真实存在(b)想要单设备按孩子分库"的未验证人群赌注上；它还带真复杂度（per-Profile 容器/目录/UserDefaults，且是数据丢失 #3/#4 的来源）。
- **A** 发布 Must——多孩家庭是核心，按孩子分库是刚需，Cycle 1 把 Multi-Profile 打磨成精致免费基线。
- **B** Could（去风险）——n=1 的你验证不了多孩需求；当作"维护但不主推"的能力，Cycle 1 不为它花打磨预算，让真实多孩注册决定它配不配一等地位。
- *为什么*：决定是否为一个 n=1 验不了的人群赌注，烧 Cycle-1 打磨预算和复杂度。
- *何时推翻*：TF 看创建第 2 个 Profile 的账号占比——近零 → B（过度投入）；可观 → A 确认。

## 第六组 · 假设台账（带参数 · 答案=暂定默认 · 由 dogfood 定 · 不冻结为原则）

**Q16 · 采集默认展示哪些字段？**（⚠️ 代码 vs spec 实打实分叉）

- *为什么*：录入摩擦（#1 原则）的最大单一杠杆——每个采集时多一个默认字段都是对生命线的税。

**Q17 · AI 自动标注：静默 vs 可见建议 vs 设置。**
- **A** 静默自动填（现状，最少 tap）｜ **B** 可见建议要确认（"AI：数学？"，信任+控制）｜ **C** 显式设置（默认开、可关）。

**Q18 · 采集 metadata-rich vs capture-light。**
- **A** 采集即填全（现状，存下就井井有条）｜ **B** 采集只存图+OCR、分类全延到库里 ｜ **C** AI 预填学科、其余折进"添加详情"可选披露。

**Q19 · 检索：搜索为主-薄筛选 vs 筛选为主-富分面。**
- **A** 搜索优先、筛选只留学科/标签/难度（= spec）｜ **B** 每个维度都是筛选分面（= 当前 L3 代码），多轴筛选是检索模型。

**Q20 · 复习每日上限 N vs 不设上限。**
- **A** 不设上限（现状，加载全部到期，可能数百，令人却步）｜ **B** 每日 N 张（Anki/多邻国式，短可完成，但加配额概念）。

**Q21 · "不记得"的卡：同 session 重学 vs 留到次日。**
- **A** 同 session 10 分钟后重现（现状，真重学但拉长 session）｜ **B** 留到次日（session 严格"每张一次"，短可完成干净利落）。

**Q22 · 导出默认：去答案 vs 看意图。**
- **A** 去答案恒为默认（现状，标准导出=给娃重做的空白卷）｜ **B** 默认看意图/记住上次（练习卷去答案 vs 答案存档含答案的清晰二分）。

## 第七组 · 已持有立场复核（confirm-or-reopen · 不是重答）
