# UX 设计原则

> 适用于所有涉及 UI/UX 的改动。

## 核心标准

**35 岁妈妈第一次打开 App 能顺利使用。初三学生能自主操作。**

> 用户画像详见 `docs/product/product-vision.md`「目标用户」
> 用户旅程详见 `docs/product/product-journeys.md`「旅程」（旅程 0-12）

## 设计原则

### Apple HIG 核心（SnapDrill 适配）

1. **清晰性**：内容优先于装饰，每个元素都有存在理由
2. **遵从性**：流畅动效帮助用户理解内容，不与内容竞争
3. **深度**：层次分明的视觉层传达层级关系

### Airbnb 交互三原则

1. **渐进式披露**：不在第一屏塞满所有选项
2. **可逆操作**：用户永远可以回退
3. **即时反馈**：每个操作都有视觉响应

## 交互设计检查清单

- [ ] 用户完成任务需要几步？能减少吗？
- [ ] 每个页面的主要目标是什么？有没有干扰元素？
- [ ] 导航结构：用户知道自己在哪、能去哪、怎么回去吗？
- [ ] 空状态：无数据时用户看到什么？有引导文案吗？
- [ ] 错误状态：操作失败时用户看到什么？能重试吗？
- [ ] Apple 原生 App 是怎么解决同类问题的？

## 用户体验终审检查清单

### 文案检查
- [ ] 有没有技术术语？（SM-2 -> 「智能复习」，OCR -> 「文字识别」）
- [ ] 错误提示说人话？（不暴露 error code）
- [ ] 按钮文案明确？（「保存」vs「完成」vs「确认」）

### 可发现性检查
- [ ] 核心功能（拍照录题）一步可达？
- [ ] 新功能需要引导？（首次使用提示）
- [ ] 设置项容易找到？

### 情感化检查
- [ ] 加载状态有反馈？（不静止不动）
- [ ] 操作成功有正向反馈？（不弹窗打扰）
- [ ] 删除操作有反悔机制？（toast undo 5 秒撤销 或 破坏性操作 `confirmationDialog`；默认首选 toast undo，详见下方第 6 条）

### 家长友好检查
- [ ] 界面语气成熟、不幼稚？
- [ ] 流程足够简单（妈妈不需要学习）？
- [ ] 多孩家庭场景考虑了？（Profile 切换）

## Gotchas

1. **禁止把整行 HStack 作为 Menu label**：会导致弹出框锚点错误 + 内容闪烁消失，Menu label 仅覆盖右侧控件（值+chevron）
2. **控件语义必须精确**：`Picker(.menu)` = 原地选值，`NavigationLink` = 跳页导航，`confirmationDialog` = 破坏性操作/分享确认
3. **复习是增值但非核心必要能力**：家长场景下复习功能几乎不被使用——「存下来」本身就是全部价值
4. **字段默认最少化**：新用户开箱仅开启「学科」一个系统字段，其余按需开启
5. **多孩 Profile 切换可发现性**：两个孩子的题库需有明确视觉区分
6. **删除撤销给用户安全感**：误删后 5 秒挽回窗口
7. **批量操作进入/退出要直观**：选择模式通过编辑按钮进入，完成后退出
8. **语言切换需重启**：App 内直选语言后提示重启生效
