# ADR-002: 云同步方案选型

## 状态
已接受 (Accepted) - 2025-09-12

## 决策者
技术团队

## 背景
NotBad错题本应用需要实现跨设备数据同步功能，以便用户在iPhone、iPad等设备间无缝使用。根据PRD v4.0要求，基础的iCloud同步对所有用户免费开放，高级同步功能（多平台、历史版本、实时协同）作为Pro功能提供。

## 决策
选择 **CloudKit作为主要同步方案**，并保留自建后端的扩展接口。

## 考虑的选项

### 选项1: 纯CloudKit方案
**优点:**
- 与iOS生态深度集成，用户体验一致
- 苹果提供基础设施，无需维护服务器
- 支持私有和公共数据库
- 自动处理用户身份验证（Apple ID）
- 符合苹果隐私标准

**缺点:**
- 仅限苹果生态系统
- 存储和API调用有配额限制
- 对复杂查询支持有限
- 无法实现实时协同编辑

### 选项2: 自建后端方案
**优点:**
- 完全控制数据结构和业务逻辑
- 支持跨平台同步
- 可实现复杂的数据分析和AI功能
- 支持实时协同

**缺点:**
- 需要维护服务器基础设施
- 开发和运维成本高
- 需要处理用户身份验证和隐私合规
- 增加安全风险

### 选项3: 第三方BaaS (Firebase/Supabase)
**优点:**
- 快速开发
- 跨平台支持
- 实时数据同步

**缺点:**
- 与第三方服务强耦合
- 数据隐私控制受限
- 长期成本不可预测

## 决策理由

1. **MVP优先**: 对于初期用户，CloudKit的功能已足够满足基本同步需求
2. **成本控制**: 避免早期的服务器运维成本
3. **用户体验**: 与iOS生态无缝集成，符合用户期望
4. **合规简化**: 利用苹果的隐私基础设施降低合规复杂度
5. **渐进式架构**: 通过接口设计保留后续扩展能力

## 实现策略

### 阶段一: CloudKit基础同步
```swift
protocol SyncServiceProtocol {
    func syncToCloud() async throws
    func syncFromCloud() async throws
    func handleConflicts(_ conflicts: [SyncConflict]) async throws
}

class CloudKitSyncService: SyncServiceProtocol {
    // CloudKit具体实现
}
```

### 阶段二: 混合架构
- CloudKit处理基础数据同步
- 自建API处理教师/班级功能
- AI分析通过云端API提供

### 配额监控和降级策略
```swift
class QuotaMonitor {
    func checkDailyStorage() -> QuotaStatus
    func checkAPICallRate() -> QuotaStatus
    func triggerGracefulDegradation()
}
```

## 监控指标
- CloudKit同步成功率 (目标: >99%)
- 同步延迟 (目标: <30秒)
- 配额使用率 (告警阈值: 80%)
- 冲突解决成功率 (目标: >95%)

## 风险和缓解措施

### 风险1: CloudKit配额超限
**缓解**: 实现数据压缩、去重机制，配额预警系统

### 风险2: 仅限iOS生态
**缓解**: 在架构设计中保留ServerRepository接口，便于后续扩展

### 风险3: 复杂查询限制
**缓解**: 优化本地数据结构，减少对复杂云端查询的依赖

## 后果
- 短期内专注iOS平台开发
- 降低了初期技术复杂度和运维成本
- 为后续扩展保留了技术债务
- 需要在Pro功能开发时重新评估架构
