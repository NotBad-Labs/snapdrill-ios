# ADR 0005: 统一项目的 iOS 目标版本下限为 iOS 18.0

## 状态

已被取代 (Superseded) — 项目已升级至 iOS 26.0+（2026-03-04），本 ADR 记录的 iOS 18.0 下限不再适用。

## 上下文

在项目初期，由于对 iOS 17 的 `SwiftData` 和 `@Observable` 宏有初步兼容性需求，最低部署版本被设定为 iOS 17.0。
然而在实际开发和真机调试过程中发现：

1. **框架稳定性**：iOS 18 对 `SwiftData` 的并发模型和 `Observation` 框架的底层实现进行了显著加固，修复了 iOS 17 中存在的多个难以复现的可观测性 Bug。
2. **并发基准**：本项目全面采用 Swift 6.2 严格并发检查。iOS 18 提供了更原生的分布式隔离支持，能够简化大量针对旧版系统的 `@preconcurrency` 或 `#available` 保护代码。
3. **开发效率**：消除代码库中随处可见的版本判断逻辑，使 AI 管理代码变得更加直观，减少了因版本差异导致的生成的“幻觉”代码。
4. **长远规划**：本项目定位为 AI 原生的高性能工具，iOS 18 的新特性（如全新的控制中心插件和系统级集成）是未来扩展的重点。

## 决策

1. **强制对齐**：将本项目全量代码（App Target）、所有本地 Swift Package 模块的最低部署版本统一设定为 **iOS 18.0**。
2. **清理冗余**：删除源码中所有为了兼容 iOS 17 而添加的 `#available(iOS 18.0, *)` 宏及相关降级逻辑。
3. **元数据更新**：同步更新 `project.pbxproj`、`Package.swift` 以及 `.agent/skills/` 下的所有规则文件。

## 后果

- **优势**：
  - 极大地简化了代码维护成本。
  - 提高了 SwiftData 持久层在复杂并发场景下的可靠性。
  - 确保了 AI 生成代码的 100% 现代性，无过时 API 负担。
- **代价**：
  - 放弃了 iOS 17 用户群体。鉴于本项目为全新的学习工具，优先保障核心体验的稳定性和前瞻性高于用户覆盖度。
