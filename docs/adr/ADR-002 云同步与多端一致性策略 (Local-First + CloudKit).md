# ADR-002: 云同步与多端一致性策略 (Local-First + CloudKit)

* **状态**: 已采纳
* **日期**: 2025-09-10
* **决策者**: 架构负责人 / iOS 工程组
* **取代**: -

## 上下文
应用需要在多设备间保持错题集合、学习进度与掌握度状态同步，同时保障离线可用与低冲突率。早期团队人员有限，需要利用平台级能力减少自建服务投入。

## 决策驱动因素
1. 初期研发/运维成本最小化。
2. 离线优先 (Local-First) 用户体验流畅性。
3. 冲突发生概率与解决策略简洁度。
4. 隐私合规（题目图片含可能敏感手写内容）。
5. 可扩展性：未来支持 Web / Android 方案留白。

## 备选方案
- 自建后端 (REST/GraphQL) + 自定义同步层
- CloudKit + 本地持久化（SwiftData）
- 第三方后端即服务 (Firebase 等)

## 决策结果
采用 Local-First 模式：设备先写入本地 SwiftData，后台异步与 CloudKit 同步；冲突以 "最新更新时间 + 域特定合并规则" 解决。

## 理由
- CloudKit 原生集成，省去服务器搭建与认证复杂度。
- Local-First 提升交互即时性，降低网络波动影响。
- 领域数据大多是 append/update 类型，合并规则简单。

## 冲突解决策略概要
| 数据类型 | 合并策略 | 备注 |
|----------|----------|------|
| 错题条目 (Item) | 字段粒度：较新的 updatedAt 覆盖；图片列表合并去重 | 图片去重基于哈希指纹 |
| 掌握度状态 | 取最大掌握度等级与最新复习时间 | 避免回退 |
| OCR 识别文本 | 若重处理标记为新，替换旧文本；保留历史版本快照 | 可用于质量回溯 |

## 后果
### 正面
- 低后端成本，快速上线。
- 高可用离线体验。
- 简化 MVP 阶段架构复杂度。

### 负面 / 风险
- 复杂跨平台（未来 Web/Android）需重新设计同步接口。
- CloudKit 查询调优需要经验；可能出现性能瓶颈。
- 冲突策略需充分测试防止静默数据丢失。

## 风险缓解措施
- 针对关键模型构建冲突合成单元测试集。
- 为删除操作设计软删除标记，避免误删同步扩散。
- 监控同步失败与重试指标 (retry count, latency)。

## 后续行动
- 定义同步失败告警阈值。
- 文档化字段级合并策略细则。
- 评估未来公共 API 抽象层（为跨端预留）。
