# ADR-004: 错题重做功能方案选型

**状态**: 已接受 (Accepted)

**日期**: 2025-09-13

## 背景 (Context)

产品需求文档 (PRD v4.0) 中定义了“错题重做”功能 (用户故事 US-202)，旨在让学生能真正检验自己是否掌握了错题。

PRD 中最初的验收标准 (AC-202.1) 描述为：“系统应能自动识别并遮蔽原图中的答案区域，生成一张干净的题目模板”。这个描述指向了一个技术上非常复杂的“智能擦除”方案。

在技术评审中，我们识别到该方案对于MVP（最小可行产品）阶段存在以下显著风险：
*   **高技术不确定性**: 智能擦除依赖计算机视觉算法，对于不同质量的图片、光照条件、手写风格，其效果难以保证，可能导致用户体验不可预测。
*   **高研发成本**: 实现一个可靠的智能擦除引擎需要投入大量的研发时间和资源进行算法调研、模型训练和效果调优。
*   **潜在的云服务依赖**: 为了达到较好的效果，可能需要依赖云端AI服务，这会增加架构复杂度和运营成本，并与应用的“本地优先”原则产生冲突。

因此，我们需要在“理想效果”和“MVP可行性”之间做出权衡，选择一个既能满足核心用户需求，又能在有限时间内高质量交付的方案。

## 决策 (Decision)

我们决定，在产品的MVP阶段，**采用“并排视图”方案**来实现“错题重做”功能。

该方案的具体实现如下：
1.  当用户选择“重做”一道错题时，系统将呈现一个分屏界面。
2.  界面的左侧（或上侧）完整显示原始的错题图片和内容，作为参照。
3.  界面的右侧（或下侧）提供一个空白的作答区域（如文本框），供用户重新作答。
4.  用户完成后，可以方便地对照原始答案，并手动标记本次重做的掌握情况。

此决策已同步更新至 PRD v4.0 和 TDD v4.0。

## 后果 (Consequences)

### 正面

*   **显著降低MVP风险**: 规避了“智能擦除”方案带来的所有技术不确定性和研发成本，确保了功能可以按时、高质量交付。
*   **用户体验清晰可控**: “并排视图”的交互方式简单、直观，用户能够明确地进行参照和作答，不会因算法识别错误而感到困惑。
*   **实现成本低**: 该方案可完全使用标准的SwiftUI组件（如`HStack`, `TextEditor`）实现，无需引入任何第三方依赖或复杂的算法。
*   **保留未来可能性**: “智能擦除”功能可以作为一项技术储备或未来的Pro增值功能，在产品核心价值得到验证后再投入资源进行探索。

### 负面

*   **缺少“惊艳”效果**: 与“智能擦除”可能带来的“魔法般”的体验相比，“并排视图”功能上显得较为基础。
*   **用户操作略有增加**: 用户需要自己对照答案并手动标记掌握状态，而非系统自动判断。但这在MVP阶段是完全可以接受的。

## 备选方案 (Options Considered)

### 方案A: 并排视图 (Side-by-side View) - (已采纳)

*   **描述**: 如“决策”部分所述，提供一个参照区和一个作答区。
*   **优点**: 风险低，成本低，实现快，体验稳定。
*   **缺点**: 功能基础，不够“智能”。

### 方案B: 智能擦除 (Smart Erase) - (已拒绝)

*   **描述**: 尝试通过图像处理或AI模型，自动识别并移除用户在原图上的手写答案，生成一个“干净”的题目模板供用户直接作答。
*   **优点**: 如果成功，用户体验会非常流畅和智能。
*   **缺点**: 技术风险和研发成本极高，效果不可控，可能严重影响MVP的交付进度和质量。
