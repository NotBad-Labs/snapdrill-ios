# ADR-001: 本地数据层与持久化框架选型 (SwiftData)

* **状态**: 已采纳
* **日期**: 2025-09-10
* **决策者**: 架构负责人 / iOS 工程组
* **取代**: -

## 上下文

应用需要一个现代、与 SwiftUI 及并发模型深度整合、便于未来与 iCloud/CloudKit 同步的持久化层。需要快速迭代 MVP，减少样板代码，同时保持可测试性与可维护性。

## 决策驱动因素

1. 与 SwiftUI/Observable 模型的融合良好程度。
2. 原生 async/await 支持。
3. 与 CloudKit 同步的开销与复杂度。
4. 学习曲线与团队生产力。
5. 未来维护与生态成熟度。

## 备选方案

* Core Data
* SwiftData
* Realm

详见模板中的优劣对比；此处不重复。

## 决策结果

采纳 SwiftData 作为首选持久化框架。

## 理由

* 减少大量样板代码，模型声明简洁。
* 与 SwiftUI 生命周期、属性包装器及状态驱动渲染天然整合。
* CloudKit 同步配置路径短，降低早期实现成本。

## 后果

### 正面

* 提升开发效率与可读性。
* 更少粘合层代码，降低缺陷面。
* 更快实现离线优先能力。

### 负面 / 风险

* 生态新，潜在未知缺陷。
* 遇到边缘问题时资料少，需要内部探索。
* 需要设计降级策略（必要时封装抽象层以备切换）。

## 决策后行动项

* 建立数据模型命名规范与版本迁移策略文档。
* 对关键模型编写最小持久化/查询单元测试。
* 监控 SwiftData 版本更新与破坏性变更公告。
