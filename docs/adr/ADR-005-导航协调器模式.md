# ADR-005: 导航协调器模式 (Navigation Coordinator Pattern)

**状态**: 已接受  
**日期**: 2025-09-13  
**决策者**: Tech Team  

## 背景 (Context)

在iOS应用开发中，随着应用功能的增长和复杂度提升，传统的视图控制器导航模式会导致以下问题：

1. **视图控制器职责过重**：既要处理UI逻辑，又要处理导航逻辑
2. **紧耦合**：视图之间直接相互引用，难以测试和维护
3. **导航逻辑分散**：导航代码散布在各个视图控制器中，难以统一管理
4. **依赖注入困难**：视图控制器需要知道如何创建和配置其他视图控制器

## 决策 (Decision)

我们决定采用**导航协调器模式 (Navigation Coordinator Pattern)** 来管理应用的导航流程和依赖注入。

### 核心组件

1. **AppCoordinator**: 应用级协调器，管理整个应用的生命周期和主要流程
2. **FlowCoordinator**: 功能流程协调器，管理特定功能区域的导航（如复习流程、设置流程）
3. **AppFlow**: 应用流程枚举，定义应用的主要状态和流程

### 架构设计

```swift
// 应用流程定义
enum AppFlow {
    case splash      // 启动画面
    case main        // 主界面
    case onboarding  // 引导流程
    case settings    // 设置界面
}

// 应用协调器
@MainActor
class AppCoordinator: ObservableObject {
    @Published var isLoading = true
    @Published var currentFlow: AppFlow = .splash
    
    // 依赖容器
    private let dataManager: DataManager
    private let syncService: CloudSyncService
    
    func navigateToFlow(_ flow: AppFlow) {
        currentFlow = flow
    }
}

// 协调器视图
struct AppCoordinatorView: View {
    @ObservedObject var coordinator: AppCoordinator
    
    var body: some View {
        Group {
            switch coordinator.currentFlow {
            case .splash:
                SplashView()
            case .main:
                MainTabView()
            case .onboarding:
                OnboardingView()
            case .settings:
                SettingsView()
            }
        }
    }
}
```

## 优势 (Consequences)

### 正面影响

1. **职责分离**：
   - 视图专注于UI展示
   - 协调器负责导航和依赖管理
   - 应用入口保持简洁

2. **解耦合**：
   - 视图之间不直接依赖
   - 通过协调器进行间接通信
   - 便于单元测试

3. **统一管理**：
   - 所有导航逻辑集中在协调器中
   - 便于调试和维护
   - 支持复杂的导航场景

4. **依赖注入**：
   - 协调器作为依赖容器
   - 统一管理服务实例
   - 支持测试时的依赖替换

5. **可扩展性**：
   - 新功能通过扩展AppFlow枚举添加
   - 支持嵌套协调器处理复杂流程
   - 便于A/B测试和功能开关

### 负面影响

1. **初期复杂度**：需要额外的协调器代码
2. **学习成本**：团队需要理解协调器模式
3. **样板代码**：简单场景可能过度设计

## 实现细节

### 文件组织

```
Sources/
├── Core/
│   ├── AppCoordinator.swift           # 应用协调器
│   ├── AppCoordinatorView.swift       # 协调器视图
│   └── AppFlow.swift                  # 流程定义
├── Features/
│   ├── Review/
│   │   ├── ReviewCoordinator.swift    # 复习流程协调器
│   │   └── ReviewViews/
│   └── Settings/
│       ├── SettingsCoordinator.swift  # 设置流程协调器
│       └── SettingsViews/
```

### 与Clean Architecture的集成

协调器模式完美契合Clean Architecture：

- **Presentation Layer**: 协调器和视图
- **Application Layer**: 协调器调用用例 (Use Cases)
- **Domain Layer**: 领域实体和服务接口
- **Infrastructure Layer**: 具体实现注入到协调器

### 依赖注入示例

```swift
class AppCoordinator: ObservableObject {
    // 依赖注入
    private let reviewRepository: ReviewItemRepository
    private let syncService: CloudSyncService
    private let ocrService: OCRService
    
    init(
        reviewRepository: ReviewItemRepository = SwiftDataReviewRepository(),
        syncService: CloudSyncService = CloudKitSyncService(),
        ocrService: OCRService = VisionOCRService()
    ) {
        self.reviewRepository = reviewRepository
        self.syncService = syncService
        self.ocrService = ocrService
        setupApplication()
    }
}
```

## 替代方案 (Alternatives Considered)

1. **传统MVC/MVVM**：视图控制器直接管理导航
   - 缺点：紧耦合，难以测试
   
2. **SwiftUI Navigation**：使用系统提供的NavigationStack
   - 缺点：复杂场景支持有限，依赖注入困难
   
3. **第三方路由库**：如XCoordinator
   - 缺点：引入外部依赖，学习成本高
