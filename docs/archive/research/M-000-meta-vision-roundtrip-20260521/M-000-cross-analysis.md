## 4. 各家独特贡献（融合金矿，无冲突）

各家有自己不可替代的贡献，consensus 应把这些**全部吸纳**：

### Codex 独特贡献
- **「裁决权 = 提案权 + 批准权」拆分**（修正第 6 条）：智能体可以提修订案，但顶层原则的生效应由用户批准
- **下游派生 10 项细化清单**：智能体角色 / 独立工作 / 任务分级 / 降级 / 裁决 / 证据等级 / 变更 / 技能 / 上下文加载 / 失败复盘

### Gemini 独特贡献
- **Token 水位监测机制**：智能体在每轮高阶协同前应主动查询/记录速率限制与剩余额度，作为降级硬触发器（不是请求报错后被动熔断）
- **一进一出制**：新增一条规则必须废除一条旧规则或合并两条同类规则（最激进的防膨胀）
- **CI/CD 法官**：双核分歧时先用基准测试（性能/内存/耗时）跑分裁决，跑分平局或涉及美学才升用户
- **三档协作模式**：全员多方冗余 / 双核协同 / 单方降级——给出可执行的层级表

### DeepSeek 独特贡献
- **「五分钟有效响应 + 连续三次失败 = 不可用」具体技术判据**
- **降级顺序表**：Claude > Gemini > Codex > DeepSeek（明确优先级）
- **裁决权可问责性**：双核裁决事后被证明有重大偏差，应记录案例并探讨是否调整裁决权分配
- **强制异议制**：关键节点指定某方扮演反驳者，不管它自身倾向

### Claude (Desktop) 独特贡献
- **核心命题升级**：「我相信」→「我有理由相信」（认识论升级，非工程描述）
- **冗余本质重新定义**：跨先验独立趋同（贝叶斯模型平均）+ 失败模式覆盖；明确**「可复现是必要不充分的」**
- **可逆性 + 代价判据**：替代任务难度作为多方/单方的划分依据
- **反直觉判据**：极端时间压力下可逆决策，多方反而有害
- **「草稿模式」**：跌至单方时标记待复核，另一方上线立即补审（既不阻塞又保留协作本质）
- **失败三形态**：显性分歧（不是失败）/ 隐性同谋（最危险）/ 质量退化
- **裁决权 ≠ 通过权**：即便双核同意，不可逆/跨元/法律财务仍上交用户
- **训练相关性警告**：Claude + Codex 在训练对齐上相关，二者一致不等于两个独立证据源
- **触发场景修改阀门**：无具体真实场景的修改默认不采纳
- **新规则四周试用期**：防止「加上去就下不来」
- **时间错位复审**：同一智能体不同时间审视同一产出，作为半独立的二次来源

**这些独特贡献无内在冲突，可以全部吸纳。**

## 5. 真正的冲突点（四家分歧，需取舍）

### 冲突 A：冗余的本质定义

| 立场 | 主张方 |
|---|---|
| 冗余 = **可复现**（用户原话） | 用户原话第 1 条 |
| 冗余 = **可复现 + 有意义的不一致** | Codex |
| 冗余 = **跨先验独立趋同**（可复现是必要不充分） | Claude |
| 冗余 = **异构的确定性消弭单体的随机性** | Gemini |
| 冗余 = **同一推理空间多采样 vs 不同推理空间交叉验证** | DeepSeek |

**主笔建议**：Claude 的「跨先验独立趋同」最准确（单模型稳定输出错误也复现，但不是证据），但需要用户拍板是否接受**对原话第 1 条的实质修正**。

### 冲突 B：冲突时是否给"默认倾向"

| 立场 | 主张方 |
|---|---|
| 任何冲突都必须交用户裁决 | 用户原话第 7 条；Codex；Gemini；DeepSeek |
| 给默认倾向：不可逆/高代价→元规则优先；可逆/时间敏感→产品 vision 优先；用户裁决可覆盖 default | Claude |

**主笔建议**：Claude 的 default 能减少打扰，但**违反用户原话**「必须交给用户本人裁决」。是否接受 default 需用户拍板。

### 冲突 C：双核同意时是否一律不打扰用户

| 立场 | 主张方 |
|---|---|
| 双核同意即可，不询问用户（用户原话） | 用户原话第 5 条；Gemini |
| 双核同意默认通过，**但不可逆/跨元/法律财务仍上交** | Claude；Codex（间接） |
| 双核同意 + 自动化 CI/CD 跑分裁决，跑分通过才执行 | Gemini（更强约束）|

**主笔建议**：Claude 的"裁决权 ≠ 通过权"应该接受——这是对用户原话第 5 条的合理细化，不是颠覆。

### 冲突 D：是否警告 Claude+Codex 训练相关性

| 立场 | 主张方 |
|---|---|
| 不警告 | 用户原话；Gemini；DeepSeek |
| **明确警告 Claude+Codex 训练相关**，二者一致 ≠ 两个独立证据源 | Claude |
| 类似但表述为「天然共谋」 | Gemini 盲点段（自评） |

**主笔建议**：Claude 这条是真问题。两家都是 RLHF + Constitutional AI 谱系，先验高度相关。**这条应该进 consensus**。

### 冲突 E：下游派生数量与结构

| 立场 | 主张方 |
|---|---|
| 10 项细化清单 | Codex |
| 3 层线性派生（分支管理 → 接口协议 → CI 度量） | Gemini |
| 5 项一级派生（协作会话 / 分歧裁决 / 技能加载 / 降级手册 / 质量度量） | DeepSeek |
| 5 项有序派生（工作流 → 裁决日志 → 技能库 → 提示基线 → 评估度量） | Claude |

**主笔建议**：DeepSeek + Claude 收敛在 5 项相似结构，最优雅。Codex 的 10 项可作为 5 项展开后的子项。Gemini 三层过于线性。

### 冲突 F：是否要"一进一出"硬约束防膨胀

| 立场 | 主张方 |
|---|---|
| 「触发场景 + 试用期 + 周期精简」（柔性） | Claude |
| **「一进一出制」+ 动态技能沉淀**（刚性） | Gemini |
| 必要性论证 + token 成本评估 | DeepSeek |
| 必要性 + 证据 + 影响可追溯 | Codex |

**主笔建议**：Gemini 的「一进一出」过于刚性（可能阻碍真正必要的新增）；Claude 的「试用期 + 周期精简」更平衡。但**「触发场景」+「试用期」+「token 成本评估」**可以三合一。

## 8. 元层级反思（这次工作流的复盘素材）

这次 M-000 起草本身就是一次 worktree+异源对抗实战。沉淀几条观察：

1. **同源警告应该是常态机制**：Claude CLI 主笔 + Claude Desktop chat 起草同源风险已经验证，下次主笔应轮换（让 Codex 或用户主笔）
2. **盲点自评机制非常有价值**：四家盲点段加起来覆盖了主笔自己难以发现的真实风险（特别是 Claude 的「利益相关方论证」自我质疑）
3. **修正意见的密度反映独立性**：Claude 提了 3 条对原话的修正，密度最高，说明它最敢挑战 prompt；Gemini 只提 2 条且都在执行层，独立性相对弱
4. **字数与质量不成正比**：Gemini 2400 字，Claude 1800 字，但 Claude 凝练度更高——后续 prompt 可以加「短即是优」的引导
5. **prompt 中「不要参考其他家产出」起作用了**：四家结构相近但论证完全独立，没出现引用其他家的现象（特别是 Claude Desktop chat 不知道其他三家草案）
