## 硬约束

### 1. 字数硬上限
**正文 ≤ 1500 字**（不含 frontmatter 和指针表格）。这是用户裁决的硬约束，不可突破。

### 2. 文档定位
M-000 是**元规则的元规则**（顶层宪法），不是元规则本身。
- 只讲「规则系统怎么运行」
- 不讲「具体协作机制是什么」
- 具体机制（失败定义 / 降级 / 裁决细则）**全部下沉**到 M-001~M-005

### 3. 分层结构

```
Layer 0: M-000 元规则的元规则（你正在起草，≤ 1500 字）
Layer 1: M-001~M-005 元规则（中层，可演化）

```

## 已收敛的决策（直接写入，不要再讨论）

### 冲突 1：冗余的本质 ✅

采用三家共识 + Codex round 2 措辞：

> **可复现是冗余的基础，独立趋同是高质量冗余的目标。**
>
> 冗余的本质是不同先验路径下的独立趋同；可复现是必要不充分条件——单一模型稳定复现错误也满足复现，但不构成证据。

### 冲突 2：双核同意时的上交清单 ✅

B 为骨架 + C 为子机制：

- **双核同意默认通过**
- **例外（即使双核同意仍上交用户）**：
  - 不可逆操作
  - 跨元层级修改（修改 M-000 自身）
  - 法律或财务承诺
  - 产品方向实质改变
- **可量化事项额外用自动化测试**（性能 / 内存 / lint）作为子机制——跑分通过 + 双核一致才放行；跑分平局或不可量化时回退到双核 + 例外清单判断

### 冲突 3：与产品 vision 冲突 ✅

采用 Claude E 方案：

- **维持平级承诺，不预设倾向**
- 冲突上交用户时，智能体必须附**结构化分析**：冲突性质 / 可逆性 / 双方拉锯点 / 推荐路径 / 理由
- 裁决沉淀为**先例**，但**不自动改写元规则**——改写仍走正式修订流程

### 冲突 4：训练相关性 ✅

通用条款，不点名具体厂商：

- 写入「**伪共识**」通用风险条款
- 任何两个智能体共享相似训练语料 / 对齐目标 / 中间结论时，其一致都可能是「天然共谋」
- **触发条件**：当辅助智能体（异源方）提出强烈、具体、可证伪的反对意见时，自动触发用户裁决，双核自动通过权失效

### 冲突 5：防膨胀机制 ✅

按「修改对象的层级」分配硬度（用户明确否决「一进一出制」）：

| 层级 | 防膨胀机制 |
|---|---|
| M-000 顶层 | **字数硬上限 1500 字** + 新增条款必须证明无法下沉到中层或 skill；**不强制一进一出**（允许新情况发生，字数上限自然约束总量） |
| M-001~M-005 中层 | 触发场景 + 4 周试用期 + 周期精简 |
| 长尾经验 | 不进规则文档，做按需加载技能 |

### 冲突 6：下游派生骨架 ✅

5 项一级主干 + 10 项作为二级展开。**M-000 仅列主干名 + 一句话职能描述**，不展开二级：

- **M-001 协作工作流规约**——规定多方分工、独立工作、上下文加载（含主笔轮换提议机制）
- **M-002 分歧裁决与裁决日志**——规定裁决流程、证据等级、变更记录
- **M-003 技能库治理**——规定经验如何沉淀、加载、淘汰
- **M-004 降级操作手册**——规定服务受限时的降级路径与停止等待判据
- **M-005 质量判据与退化检测**——规定产出质量度量、伪共识识别、自动警报

### Round 2 新增条款 ✅

**用户裁决日志**（写入 M-000，因为这是元规则的元规则）：

- 文件 `docs/meta/user-decision-log.md`（append-only）
- 字段：时间 / 冲突描述 / 裁决 / 理由 / 是否触发元规则修订
- 智能体检测到当前裁决与历史冲突时，**温和提醒**（不阻断执行）

**外部冲击兜底**（写入 M-000）：

- 当某家智能体服务长期不可用（>2 周）或商业模式根本变化（关停 / 重大降级 / 价格跳变）时
- **自动触发 M-000 review**，不是被动降级
- 历史裁决日志保留，不因服务变更失效

**默认多方**（写入 M-000 §适用范围）：

- 任何任务默认多方协作
- 用户可显式豁免特定场景为单方
- **不预设判据矩阵**——用户当时当下判断
- 用户原话："任何时候多方都是值得的，几行代码花费的 token 其实很少"

**主笔轮换**（M-000 埋伏笔，细则在 M-001）：

- 用户原话："不能因为每年都有交通事故而不学驾照不开车，就算是坐车也会遇到交通事故。"
- **这个类比可直接收入 M-000 §风险接受度或演进愿景段**
- 用户拥有「是否轮换」的最高裁决权
- 系统提醒但不强制

## 用户口述八点（核心命题，凝练用，不要重复）

1. **为什么单智能体不够**：模型能力差异 + 服务可用性波动 + 冗余的本质是能够复现、能比较优劣、择优录取
2. **适用边界**：服务可用时坚持多方冗余，不希望降级
3. **降级条件**：不希望降级，保持至少两方，Claude + DeepSeek 兜底
4. **失败定义**：无法达成共识；污染 / 退化 / 共谋可采取独立工作环境缓解
5. **裁决机制**：用户最高裁决；Claude + Codex 有裁决权；其他无；双核同意可不询问用户；双核分歧让用户裁决
6. **元规则的元规则**：实事求是、奥卡姆剃刀、可溯源
7. **与产品 vision 关系**：平级最高指导；冲突必须交用户裁决
8. **期望与最怕**：每次能加载、能进化、层层递进单一权威源；最怕变大杂烩
