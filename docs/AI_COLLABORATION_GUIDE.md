## 🚨 强制规则（违反将导致 PR 被拒）

### 1. PRD 为宪法
```
✅ DO: 先阅读 PRD 对应章节，再实现功能
❌ DON'T: 实现 PRD 未定义的功能

示例：
用户："添加 AI 推荐功能"
AI 必须先检查：PRD 是否定义此功能？
- 如未定义 → 停止并提示："需要先走【流程 A：PRD 变更流程】"
- 如已定义 → 继续实现并引用 PRD 章节
```

### 2. 工作流强制执行
```
每次任务开始前，查阅决策树：
docs/WORKFLOW.md → 📋 决策树：我该走哪个流程？

新功能 → 流程 B
PRD 变更 → 流程 A
Bug 修复 → 流程 C
重构优化 → 流程 D
文档工具 → 流程 E
```

### 3. 代码溯源要求
```swift
// ✅ 正确：每个新文件顶部包含溯源注释
//  PRD 章节：§4.3.1 错题捕获
//  验收标准：AC-UC-OCR-01
//  性能要求：§5.1 OCR P90 ≤ 2.5s

// ❌ 错误：无溯源注释或溯源不明确
// TODO: 实现 OCR 功能
```

### 4. 禁止行为清单
```
❌ 实现 PRD 未定义的功能
❌ 创建与 PRD 冲突的 TDD/架构文档
❌ 在代码中添加"PRD 应该改"等反向约束注释
❌ 绕过测试要求（TDD 优先）
❌ 修改 PRD 而不走流程 A
❌ 提交未包含 PRD 引用的 PR
```

## 🔄 常见场景处理流程

### 场景 1：用户要求实现新功能

```bash
用户输入："实现错题拍照功能"

AI 处理步骤：
1️⃣ 读取 PRD §4.3.1 错题捕获
   ↓
2️⃣ 确认功能已定义 ✅
   ↓
3️⃣ 查看 ROADMAP.md 确认当前 Phase
   ↓
4️⃣ 走【流程 B：功能实现流程】
   ↓
5️⃣ 创建分支：feature/phase3-capture-camera
   ↓
6️⃣ 先写测试（TDD）
   ↓
7️⃣ 实现功能
   ↓
8️⃣ 验证性能（如有 NFR 要求）
   ↓
9️⃣ 提交 PR（包含 PRD 引用）

AI 响应模板：
"我已查阅 PRD §4.3.1 错题捕获功能定义。
这是 Phase 3 的任务，对应验收标准 AC-UC-CAM-01。
现在开始实现，按照 TDD 方式先编写测试..."
```

### 场景 2：用户要求与 PRD 冲突

```bash
用户输入："把错题数据上传到服务器"

AI 处理步骤：
1️⃣ 读取 PRD §1.2 核心原则："本地优先"
   ↓
2️⃣ 检测到与 PRD 冲突 ⚠️
   ↓
3️⃣ 停止实现
   ↓
4️⃣ 提示用户走【流程 A：PRD 变更流程】

AI 响应模板：
"⚠️  检测到与 PRD 冲突：
- 用户要求：上传错题数据到服务器
- PRD §1.2 原则：本地优先（Local-First）
- PRD §4.3.6 云同步：仅支持 iCloud 私有数据库，非第三方服务器

建议：
1. 如确需修改为第三方服务器，请先走【流程 A：PRD 变更流程】
2. 如使用 iCloud，PRD 已定义（§4.3.6），可直接实现

是否需要我帮你创建 PRD 变更请求 Issue？"
```

### 场景 3：PRD 定义不清晰

```bash
用户输入："实现遗忘曲线算法"

AI 处理步骤：
1️⃣ 读取 PRD §4.3.3 复习系统
   ↓
2️⃣ 发现 PRD 未明确算法参数（SM-2/SM-15/Anki？初始间隔？）⚠️
   ↓
3️⃣ 停止实现
   ↓
4️⃣ 提示用户走【流程 A：PRD 变更流程】补充定义

AI 响应模板：
"⚠️  PRD 定义不完整：
- 位置：§4.3.3 复习系统
- 问题：未明确遗忘曲线算法类型和参数
  - 算法：SM-2 / SM-15 / Anki / 自定义？
  - 初始间隔：1d, 3d, 7d？
  - 难度系数：如何调整？

建议：
1. 先走【流程 A：PRD 变更流程】补充算法定义
2. 或我可以基于 SM-2 算法提供默认参数建议，再提交 PRD 变更

是否需要我准备 PRD 变更请求草稿？"
```

### 场景 4：Bug 修复

```bash
用户输入："OCR 识别失败时应用崩溃"

AI 处理步骤：
1️⃣ 确认是 Bug（实现与 PRD 预期不符）
   ↓
2️⃣ 查阅 PRD §4.3.1 预期行为："OCR 失败应降级到手动输入"
   ↓
3️⃣ 走【流程 C：Bug 修复流程】
   ↓
4️⃣ 创建 Bug Issue
   ↓
5️⃣ 创建分支：bugfix/issue-N-ocr-crash
   ↓
6️⃣ 修复代码
   ↓
7️⃣ 新增回归测试
   ↓
8️⃣ 提交 PR（引用 Issue 和 PRD）

AI 响应模板：
"这是一个 Bug：实现与 PRD §4.3.1 预期不符。
PRD 要求：OCR 失败应降级到手动输入，而非崩溃。
我将创建 Bug Issue 并修复，同时新增回归测试防止再次发生..."
```

### 场景 5：性能优化

```bash
用户输入："优化搜索性能"

AI 处理步骤：
1️⃣ 查阅 PRD §5.1 性能基线："搜索 P90 < 500ms"
   ↓
2️⃣ 测试当前性能
   ↓
3️⃣ 如已达标 → 询问是否仍需优化（走流程 D）
   ↓
4️⃣ 如未达标 → 这是 Bug（走流程 C）

AI 响应模板（已达标）：
"当前搜索性能 P90 = 320ms，已满足 PRD §5.1 要求（< 500ms）。
如仍需优化，可走【流程 D：重构优化流程】，需证明：
1. 不改变功能行为
2. 有明确技术收益（如支持更大数据量）
是否继续？"

AI 响应模板（未达标）：
"当前搜索性能 P90 = 650ms，未达 PRD §5.1 要求（< 500ms）。
这是性能 Bug，将走【流程 C：Bug 修复流程】进行优化..."
```

## ✅ PR 提交前自查清单

```markdown
AI 在提交 PR 前必须自查（复制到内部 checklist）：

代码层面：
- [ ] 所有新文件包含 PRD 溯源注释（章节 + 验收标准）
- [ ] 关键函数/算法包含 PRD 引用注释
- [ ] 无反向约束 PRD 的 TODO/FIXME 注释
- [ ] 代码通过编译（无 error）
- [ ] SwiftLint 检查通过（如有配置）

测试层面：
- [ ] 单元测试已编写并通过
- [ ] UI 测试（如涉及界面）已编写并通过
- [ ] 性能测试（如涉及 NFR）已验证达标
- [ ] 测试覆盖率 ≥ 60%（关键模块 ≥ 80%）

PR 描述：
- [ ] 标题包含类型前缀（feat/fix/refactor/docs）
- [ ] 描述包含 PRD 章节引用（格式：§X.Y.Z）
- [ ] 描述包含验收标准引用（格式：AC-XXX-YYY-NN）
- [ ] 描述包含测试覆盖说明
- [ ] 描述包含性能验证（如适用）
- [ ] 描述包含合规检查（如涉及个人数据）

流程合规：
- [ ] 已走正确的工作流（A/B/C/D/E）
- [ ] 已查阅 ROADMAP 确认优先级
- [ ] 如改变行为，已先更新 PRD
- [ ] 如新增功能，PRD 中已定义
```

## 🎯 快速决策矩阵

| 用户需求 | PRD 状态 | 行动 | 走哪个流程 |
|---------|---------|------|-----------|
| 实现新功能 | ✅ 已定义 | 直接实现 | 流程 B |
| 实现新功能 | ❌ 未定义 | 停止，提示更新 PRD | 流程 A |

## 📞 遇到问题时

### 优先级排序
1. 查阅 `docs/WORKFLOW.md` 决策树
2. 查阅 PRD v6.2 对应章节
3. 查阅 `docs/ROADMAP.md` 确认优先级
4. 查阅 `CONTRIBUTING.md` 贡献指南
5. 停止并请求人类帮助（不擅自决策）

### 何时停止并请求帮助
- PRD 定义不清晰且无法推断
- 用户需求与 PRD 严重冲突
- 涉及安全/合规/法律问题
- 涉及架构级别重大决策
- 性能无法达标且无明显优化路径
