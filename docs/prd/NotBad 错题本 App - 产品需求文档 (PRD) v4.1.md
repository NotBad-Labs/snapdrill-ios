## 1. 项目概述（Project Overview）

### 1.1 产品愿景（Product Vision）
打造一个安全、简洁、智能的 K12 学习复习应用，通过科技赋能，帮助学生科学高效地管理与复习错题，最终形成自主、高效、完整的学习闭环。

### 1.2 目标与非目标
- 目标（可度量）
  - T1：新用户首日完成"拍照创建首个复习项"的比例 ≥ 60%
  - T2：7 日留存 ≥ 25%，30 日留存 ≥ 12%
  - T3：学习会话平均时长 ≥ 6 分钟；每会话完成复习卡片 ≥ 12 张
  - T4：核心链路成功率（拍照→识别→编辑→保存）P95 ≥ 98%
  - T5：Crash-Free Users ≥ 99.9%
- 非目标（当前阶段不覆盖）
  - 不做跨 Android/网页端的多端同步（短期）
  - 不做开放社区/题库分享（短期）
  - 不做教师端的完整布置/批改闭环（短期）

## 2. 用户与场景

### 2.1 用户画像
- 学生（小学高年级-高中）：以提高成绩/巩固薄弱点为主
- 家长：关注学习进度与自律、必要的监管授权
- 教师（后续）：轻量协作、导入导出（中期评估）

### 2.2 核心用户故事（User Stories）
- US-001 学生拍照录入：我想拍照记录错题并自动识别题干/公式，3 秒内进入编辑校对
- US-002 学生复习闭环：我想按系统推荐优先级进行卡片式复习，并标记掌握度与重做
- US-003 学生进度反馈：我想看到一段时间内的掌握提升和薄弱知识点
- US-004 家长监管（可选）：我希望在不查看具体内容的情况下了解孩子复习时长/频率
- US-005 弱网/离线：我希望在没有网络时也能完全使用核心功能，并在联网后自动同步

## 3. 范围与版本

### 3.1 MoSCoW
- Must：拍照创建（OCR）、基础管理、专注复习、错题重做、基础统计
- Should：Pro 订阅、家长模式、AI 诊断/解析增强
- Could：教师协作、知识点知识图谱增强
- Won't（当前）：跨平台（非 iOS）客户端

### 3.2 里程碑（建议）
- V0.1（内部 Dogfood，2-3 周）：拍照→识别→编辑→保存，离线可用，最小复习流
- V0.2（TestFlight 私测，+3 周）：学习会话（卡片）、基础统计、CloudKit 同步
- V0.3（公测，+3 周）：可观测性完善、稳定性达标、Onboarding A/B、隐私合规复核
- V1.0（上架）：Pro 首发最小包、家长模式 MVP、SLO 锁定、回滚/降级预案演练

## 4. 功能性需求（带编号，与 RTM 对齐）

- REQ-001 拍照创建复习项（Vision OCR，3 秒内进入编辑）

- REQ-006 家长模式（授权/撤销、只读统计）
- REQ-007 基础统计（周/月复习量、重做完成率、掌握度趋势）
- REQ-008 本地存储与 CloudKit 同步（冲突解决、配额监控）
- REQ-009 权限申请（相机/相册）用途说明与最小化时机
- REQ-010 数据导入导出（最小）与恢复（iCloud 备份）
- REQ-011 埋点体系（L1/L2/L3 事件，核心漏斗）
- REQ-012 Pro 订阅最小包（占位：后续细化）

## 5. 非功能需求（NFR）

### 5.1 性能 SLO
- 基线机型：iPhone 15 Pro（A17 Pro）；最低覆盖：iPhone 13 Pro（A15）
- 低端机 SLO 放宽：相对基线放宽 30%
- 指标：
  - 冷启动：P50 ≤ 600ms，P95 ≤ 1200ms
  - 首次拍照到进入编辑：P50 ≤ 1800ms，P95 ≤ 3000ms（包含 OCR）
  - 学习卡片首帧：P50 ≤ 150ms，P95 ≤ 300ms
  - 同步延迟（前后台端到端）：P95 ≤ 30s（网络可用时）

### 5.2 稳定性与错误预算
- Crash-Free Users ≥ 99.9%，ANR 次数趋零
- 核心链路错误率（拍→识→编→存）≤ 2%（P95）
- OCR 识别准确率官方目标 ≥ 85%，可重识别触发率 ≤ 15%

### 5.3 资源与能耗
- 包体积：≤ 100MB（不含可选资源），下载后首次启动额外资源 ≤ 10MB
- 峰值内存：P95 ≤ 600MB（拍照/OCR 峰值）
- 电量消耗：10 分钟学习会话 ≤ 3%

### 5.4 隐私与安全（占位文案先落地，后续润色）
- 数据路径：默认本地（SwiftData 加密）→ iCloud 私有数据库（CloudKit）
- 不采集题目原图到第三方服务；OCR 在端侧完成（除非用户明确加入 Pro 云增强）
- 权限时机：按需申请；用途文案临时版见 [docs/privacy/usage-descriptions.md](../privacy/usage-descriptions.md)
- 数据保留与删除：用户可一键导出与彻底删除数据；家长授权流程可撤销
- 合规：遵循地区隐私法规与 App Store 审核指南（详见隐私检查清单）

### 5.5 可观测性（口径与阈值详见 Observability 文档）
- L1（核心漏斗）：拍照→识别→编辑→保存→开始复习→完成复习
- L2（质量）：OCR 时长、识别置信度、重识别触发、同步冲突
- L3（调试）：错误码与上下文、设备/系统版本、网络类型
- 指标与告警阈值：参见 [docs/observability/metrics-and-alerts.md](../observability/metrics-and-alerts.md)

### 5.6 可测试性与可访问性
- 自动化覆盖：核心 UseCase 单测 ≥ 80%，关键 UI 流程 UI 测试 ≥ 20 条
- 无障碍（a11y）：动态字体、VoiceOver 描述、对比度、触控目标 ≥ 44pt
- 本地化：至少支持简体中文与英文；日期/数字格式适配

## 6. 平台与兼容

- 最低 iOS 版本：iOS 26.0
- Xcode / Swift：Xcode 26.x，Swift Language Version = 6（Swift 6.2 工具链）
- 设备覆盖：iPhone 主力机型优先；性能基线按 iPhone 15 Pro；最低覆盖 iPhone 13 Pro；iPad 适配延后（可读/可用保证）
- 系统能力依赖：Vision、SwiftData、Cloud Kit、Core ML（Pro 增强占位）

---

## 7. 外部依赖与接口

- 第三方 SDK：默认零埋点第三方；如需接入（崩溃/分析）需在隐私章节登记用途与最小化策略
- 后端接口：第一阶段仅用 CloudKit；为中期混合架构预留 ServerRepository 接口（见 ADR-002）
- 配额监控与降级：QuotaMonitor 规则，超阈时延迟同步/压缩/去重/用户提示（详见 ADR-002）

## 8. 风险与假设

- R-001 OCR 对手写/公式识别不足 → 降级：手动框选/模板/二次识别，引导"清晰度提示"，评估 CoreML 增强（见 ADR-003）
- R-002 CloudKit 配额或冲突 → 降级：延迟/去重/批量、只保留摘要字段、提示重试
- R-003 Swift 6 并发规则收紧致工期波动 → 预案：严格并发诊断开关仅在 dev/CI 开启，发布构建进行豁免点审计
- R-004 旧设备性能瓶颈 → 预案：机型分层优化、开关关闭耗时增强能力（如实时预览）

假设：目标早期用户已升级 iOS 26；用户可接受 iCloud 私有库作为唯一云备份通道。

## 9. 度量与验收

### 9.1 成功指标（与 1.2 对齐）
- 激活：首日完成首拍创建 ≥ 60%
- 留存：D7 ≥ 25%，D30 ≥ 12%
- 质量：核心链路 P95 成功率 ≥ 98%，OCR 准确率 ≥ 85%
- 稳定：Crash-Free Users ≥ 99.9%

### 9.2 验收标准（示例）
- REQ-001：在 5 种光照场景测试集上，拍照→进入编辑 P95 ≤ 3s；失败重试提示明确
- REQ-004：卡片切换 P95 ≤ 300ms；掌握度点击反馈 ≤ 100ms；重做流程 ≤ 3 步
- REQ-008：离线新增 50 条→联网后 30s 内第二台设备可见；冲突率 ≤ 2%，有用户提示
- REQ-011：核心 L1 事件 24h 内出现在看板，漏报率 ≤ 1%

## 10. 新用户引导（Onboarding）流程（精简版）
1) 价值展示（3-4 页：拍照录入、科学复习、隐私安全）
2) 权限申请（相机/相册）：仅在首次需要时申请，文案明确用途与不上传承诺
3) 引导完成第一次"拍照创建复习项"（可 A/B）
4) 账户创建（Apple ID 一键注册）
5) 目标设置（可选）：显示在首页并用于个性化提醒
