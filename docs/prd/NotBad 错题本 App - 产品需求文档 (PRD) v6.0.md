### 1\. 项目概述 (Project Overview)

### 1.1 产品愿景 (Product Vision)

打造一个**安全、简洁、智能**的K12教育应用，通过技术赋能，帮助学生科学高效地管理和复习题目。

### 1.2 问题陈述 (Problem Statement)

- **学生痛点**: 传统纸质错题本整理繁琐、检索困难、易于丢失，且无法提供科学复习规划，使用效率低下。
- **家长痛点**: 难以客观、无侵入性地了解孩子的学习薄弱点，无法提供精准有效的辅导，常常陷入**管太多**或**管不了**的焦虑。
- **市场问题**: 现有应用普遍功能臃肿、广告干扰严重、过度社交化，缺乏一个真正以**学习效率**和**隐私安全**为核心的纯粹工具。
- **教师痛点**: 缺乏高效工具了解学生错题分布和学习进度，难以进行班级层面的分析与针对性辅导。

### 1.3 技术约束与要求 (Technical Constraints & Requirements)

### 1.3.1 平台要求 (Swift 6.2前沿技术)

- **最低支持**: iOS 26.0+ (充分利用最新技术栈与前沿特性)
- **开发环境**: Xcode 26+, **Swift 6.2**
- **并发模型**: 利用Swift 6.2最新的并发模型保证线程安全和高性能
- **UI框架**: SwiftUI (充分利用iOS 26最新特性和API)
- **架构模式**: Clean Architecture + 现代化并发编程模式

### 1.3.2 性能要求 (基于Swift 6.2 & iOS 26优化)

- **应用启动**: < **0.8秒** (iOS 26 超快启动 + Swift 6.2并发优化)
- **响应时间**: < **100ms** (核心交互响应时间)
- **内存使用**: < **150MB** (iOS 26 高级内存管理 + Swift 6.2 ARC优化)
- **并发安全**: **100%编译时保证** + Enhanced Sendable Checking
- **滚动流畅度**: > **120fps** (iOS 26 ProMotion Max + Swift 6.2性能优化)
- **编译时间**: **减少50%** (Swift 6.2编译器优化)
- **OCR准确率**: > **95%** (中文), > **90%** (数学公式) 🆕

### 1.3.3 Swift 6.2 & iOS 26 新特性利用 🆕

- **先进并发处理**: 提升并发处理能力，优化OCR和数据同步性能
- **增强模式匹配**: 复杂数据筛选和分类，提升AI分析准确率
- **改进错误处理**: 更优雅的错误处理机制，提升应用稳定性
- **高性能集合操作**: 高性能数据操作，加速搜索和统计

### 1.4 核心价值主张 (Core Value Propositions)

### 1.4.1 学生价值 (iOS 26 赋能) 🚀

- **智能OCR录入**: 基于系统级Vision能力的超高精度文字识别，快速数字化错题

### 3\. 用户画像与需求分析 (User Personas & Requirements)

### 3.1 用户场景 (User Scenarios)

> 本章节取代传统用户画像，通过场景化叙事定义核心需求，使团队更好地共情用户。

### 3.1.1 场景一：考后错题整理 (学生)

- **用户**: 小明，初二学生
- **背景**: 数学月考刚结束，小明拿着满是红叉的试卷，心情有点沮丧。他想把错题整理下来，但一想到要抄半天题、画图，就觉得很烦。
- **核心期望 (Job to be Done)**: "我希望能有一种方法，**拿出手机对着试卷拍一下，错题就能方便地存进App里**。这样他就能马上开始复习，而不是把时间浪费在抄写上。"
- **关联需求**: `F-UC-01` (拍照创建)

### 3.1.2 场景二：睡前高效复习 (学生)

- **用户**: 小明，初二学生
- **背景**: 晚上10点，小明准备睡觉前进行今日错题复习。他不想再翻看厚重的错题本，希望能有更轻松、专注的复习方式。
- **核心期望 (Job to be Done)**: "我希望App能像单词卡片一样，**自动把今天的错题推送给我**。我只需要在床上滑动卡片，就能快速回顾。对于掌握的题，向右滑过；没掌握的，向左滑重点标记，明天再练。"
- **关联需求**: `F-RR-01` (卡片式复习), `F-AI-01` (智能复习计划)

### 3.1.3 场景三：了解学习状况 (家长)

- **用户**: 李妈妈，小明的妈妈
- **背景**: 李妈妈工作很忙，但非常关心小明的学习。她不想通过翻看作业本或频繁追问来给孩子压力，但又迫切想知道“他到底哪里没学会？”
- **核心期望 (Job to be Done)**: "我希望能**每周收到一份简单清晰的学习报告**，告诉我小明最近在哪些知识点上反复出错。如果能给出一些具体的辅导建议，那就更好了。我希望这一切都在尊重孩子隐私的前提下进行。"
- **关联需求**: `F-PG-01` (家长报告), `F-PG-02` (隐私授权)

### 3.1.4 场景四：班级教学提效 (教师)

- **用户**: 张老师，初中数学老师
- **背景**: 张老师希望提高教学的针对性。他发现班里总有几个知识点，每次考试都有接近一半的学生出错。
- **核心期望 (Job to be Done)**: "如果我能**匿名地看到班级学生的高频错题和薄弱知识点统计**，我就可以在课堂上重点讲解，或者设计针对性的练习题。这比我一道道题去统计要高效得多。"
- **关联需求**: `F-TE-01` (班级学情分析)

### 4\. 产品功能需求 (Product Functional Requirements)

### 4.1 核心功能模块 (Core Function Modules)

### 4.1.1 错题录入模块 (Capture Module)

- **功能描述**: 通过拍照和OCR技术快速录入错题信息
- **主要功能**:
- 📷 **拍照录入**: 支持单张/批量拍照，手动裁剪
- 🔤 **OCR识别**: 基于Vision框架的文字识别，支持数学公式
- ✏️ **手动编辑**: OCR结果可编辑，支持富文本格式
- 📁 **批量处理**: 支持批量导入和处理

- **技术要求**:

- OCR准确率 > 95%（中文）, > 90%（数学公式）
- 单张照片处理时间 < 2秒
- 支持图片格式：JPEG, PNG, HEIC
- 最大图片尺寸：8MB

### 4.1.2 错题管理模块 (Management Module)

- **功能描述**: 对录入的错题进行分类、搜索和管理
- **主要功能**:
- 📊 **分类体系**: 按学科、难度、掌握度分类
- 🔍 **搜索功能**: 支持关键词、标签、时间范围搜索
- 🏷️ **标签系统**: 自定义标签，支持多标签
- 📈 **统计分析**: 错题数量、掌握度分布统计
- 🗂️ **收藏夹**: 重要错题收藏和快速访问

### 4.1.3 复习模块 (Review Module)

- **功能描述**: 基于遗忘曲线的智能复习系统
- **主要功能**:
- 🧠 **智能算法**: 基于艾宾浩斯遗忘曲线的复习时机
- ⏰ **复习提醒**: 个性化的复习通知和计划
- 📝 **重做功能**: 生成空白模板，验证掌握程度
- 📊 **进度跟踪**: 复习次数、正确率统计
- 🎯 **自适应调整**: 根据表现调整复习频率

### 4.1.4 分析报告模块 (Analytics Module)

- **功能描述**: 基于学习数据的智能分析和建议
- **主要功能**:
- 📈 **学习趋势**: 错题数量、掌握度变化趋势
- 🎯 **薄弱分析**: 识别薄弱知识点和题型
- 💡 **改进建议**: AI生成的个性化学习建议
- 📊 **对比分析**: 与同年级平均水平对比
- 📅 **学习报告**: 周报、月报生成和分享

### 5.3.2 未成年人隐私保护强化 (Enhanced Privacy for Minors)

  - 具体成绩和详细学习记录
  - 家长联系方式和授权信息

  - 学习行为模式（聚合统计）
  - 社区互动记录（完全匿名）

  - 匿名应用性能统计
  - 功能使用偏好分析
  - 崩溃日志（去除个人信息）
  - 保护措施：聚合统计 + 7天自动删除

- **13岁以下用户**:
  - 默认关闭"发现"社区功能

  - 严格限制数据收集范围

  - 可选择性开启社交功能

### 10.3 风险管控 (Risk Management)

### 10.3.1 技术风险 (Technical Risks)

- **Swift 6.2兼容性风险**: 新版本可能存在未知问题
  - 缓解措施: 早期技术验证，保留降级方案

- **OCR识别精度风险**: 复杂公式识别可能不达标
  - 缓解措施: 多算法对比，手动编辑备选

- **性能优化风险**: 新特性可能带来性能问题
  - 缓解措施: 持续性能监控，及时优化调整

### 10.3.2 业务风险 (Business Risks)

- **用户接受度风险**: 目标用户可能不接受新产品
  - 缓解措施: MVP早期验证，快速迭代调整
- **竞品压力风险**: 市场竞争激烈，差异化不足
  - 缓解措施: 强化技术优势，注重用户体验
- **合规风险**: 隐私保护法规可能变化
  - 缓解措施: 严格遵循最高标准，法务审核
