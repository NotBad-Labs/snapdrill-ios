## 全局设计规则

### 价值链与优先级（Kano 模型对标）

```
┌─────────────────────────────┐
│   智能复习（锦上添花）          │  ← Kano: Excitement / Could
├─────────────────────────────┤
│   增强导出打印（价值链增值）     │  ← Kano: Performance / Should
├─────────────────────────────┤
│   整理管理（核心体验）          │  ← Kano: Performance / Should
├─────────────────────────────┤
│   基础导出 + 数字化录入（生命线）│  ← Kano: Basic / Must
└─────────────────────────────┘
```

**导出分层**：基础导出（PDF/JSON/CSV）是 P4 数据所有权的 Must，缺失 = 数据被锁在 App 中。增强导出打印（去答案、留白、组卷）是 Performance/Should。

**设计铁律**：任何功能如果损害了"录入"和"管理"的简洁性，就不该做。导出/打印是价值链终点（纸质练习卷），复习是免费附加值。

**产品价值链**：采集 → 存储 → 整理 → 导出/打印。iCloud 多设备同步是付费核心引擎（Bear 模式），组卷排版打印是配套杀招。

**Kano 分类指导决策**：
- Basic 缺陷 → S0/S1（立即修复，MoSCoW: Must）
- Performance 优化 → S2（提升体验，MoSCoW: Should）
- Excitement 延期 → 不影响核心交付（MoSCoW: Could）

### 情绪基调

SnapDrill 是纯粹的效率工具。全局文案、Onboarding、成功反馈、设置页均遵循：
- **客观冷静**：不向家长贩卖教育焦虑（不做"今日仅剩 X 题额度"、不做连续天数打卡、不弹成就渲染）
- **成熟语气**：界面面向成年家长，不幼稚、不卡通
- **尊重节奏**：把选择权交给用户，不主动推送、不施加压力

### 原则冲突裁决

当设计决策涉及多条 Vision 原则冲突时，按编号优先级裁决：
1 录入体验 > 2 简洁 > 3 免费 > 4 数据安全 > 5 家长友好 > 6 原生优先。
额外约束：任何降低免费层现有能力的设计，必须经产品负责人显式批准。

### 原则追溯标注

本文档每个设计章节标题后标注 `[PX]`，表示该设计服务于哪条 Vision 原则。下游文档（requirements/cases）引用时使用章节标题（含 `[PX]` 标注）。

## 采集入口设计 [P1 录入体验, P6 原生优先]

（2026-03-09 更新，经 Apple HIG 研究修正）

底部 Tab 栏常驻（首页/题库/采集/复习/设置），采集入口作为标准 Tab 始终可达。
复习既有独立 Tab（主入口），也在 Dashboard 提供"今日待复习 N 题"快捷入口（旅程 4 验证），两者并存。
Apple HIG 明确规定 Tab Bar 用于导航而非执行动作，自定义突出按钮（大号/居中/突出色）违反原生设计规范，
且与最新 iOS 原生 Tab Bar 样式冲突，因此不采用。
如未来用户反馈可发现性不足，可评估 FAB（Floating Action Button，浮动操作按钮）方案——
参考 Apple Reminders / Journal 的做法，将采集作为独立于 Tab Bar 的浮动元素。

**iOS 26 Tab Bar 适配备注**：
- Liquid Glass 材质自动应用，无需额外适配
- 当前 5 Tab 设计（首页/题库/采集/复习/设置）不受影响，编译 iOS 26 SDK 后自动获得新外观

## OCR 定位 [P1 录入体验, P6 原生优先]

（2026-03-07 确立）

**核心定位**：OCR 是辅助展示 + 搜索索引 + 可复制文本，原图是真相。

SnapDrill 依托 Apple Vision 原生识别能力（18 种语言含中文专用模型，端上实时运行），
在印刷体文字识别方面已优于大多数竞品（竞品多依赖第三方或云端 API）。

**录入流程中的 OCR 策略**：
- OCR 文字**展示但不强迫校对**——用户看到识别结果，可以修正也可以直接保存
- 不制造「必须校对完才能保存」的心理负担
- OCR 文字的核心价值是**全局搜索**（旅程 3 中"搜索抛物线"的场景）
- OCR 结果可**复制到剪贴板**，方便用户将识别文字粘贴到其他 App
- OCR 识别失败时**自动重试**，超时显示稳定性提示引导用户调整拍摄姿势

**物理环境鲁棒性**（承接 Vision P1）：
家长的真实拍摄场景远比实验室恶劣——夜晚昏暗光线、揉皱的试卷、红蓝黑笔交错、阴影和折痕。
Apple Vision 框架对这些边缘 case 的处理优先级必须拉到最高。
具体策略：高精度识别模式 + 稳定性指示器引导用户对准 + 自动框选降低手动裁剪负担。

**这是 SnapDrill 相对竞品的技术优势**：纯原生端上识别、隐私在端、无需联网、零数据外传。

**产品影响澄清**（技术能力边界见 `../../.claude/rules/apple-limits.md`）：
- 照片中的手写文字识别（区别于屏幕手写输入）能力有限，手写体增强列为探索性
- 数理化公式无 Apple 原生识别 API，需依赖第三方方案，与隐私优先定位存在张力
- 数理化公式识别与渲染列入「待评估」，待第三方端上方案成熟后重新评估

## 图片存储策略 [P1 录入体验, P4 数据安全]

（2026-03-07 确立，2026-03-26 HIG 对标修订）

题目图片**必须保存**，包括文字部分和图形部分。
OCR 识别出的文字是辅助（方便搜索和编辑），图片是真相。

**存储策略**：
- 采集时对裁剪后的图片进行高质量压缩：限制分辨率（~1200-2000px 长边），JPEG 质量 0.8，保证公式/图形清晰可辨
- 注意：这不是"原图保存"——用户的原始照片不被修改，但 SnapDrill 内存储的是压缩后的副本
- 200-2000 道题 × ~200KB/张 ≈ 40-400MB，在 iPhone 128GB 起步的时代可接受
- 存储管理基础版已实现（空间占用统计、缓存清理）

## 字段可配置系统 [P1 录入体验, P2 简洁]

（2026-03-07 确立）

**核心理念**：题目需要多少分类字段，由用户决定，而非开发者硬编码。

### 字段分层

| 层级 | 字段 | 行为 |
|---|---|---|
| 固定字段 | 题目内容（文字/图片） | 永远存在，不可关闭 |
| 默认开启 | 学科 | 新用户开箱仅此一项，可在设置中关闭 |
| 默认关闭 | 难度、来源、年级、答案 | 用户按需在设置中开启 |
| 自定义标签 | 用户自由创建的标签（如"易错""考前必看"） | 始终可用，不可关闭 |

### 配置入口

- **首次录入后引导**：用户完成第一次录入保存后，弹出引导提示「下次录题时要不要多填学科？」，引导用户按需开启字段。首次启动 Onboarding 不要求配置（Apple HIG："Avoid asking for setup information up front"）
- **设置阶段**：设置中提供"字段管理器"，随时开关
- **录入阶段**：录入界面只显示用户已开启的字段
- **补充阶段**：题库中编辑已有题目时，可随时扩展新字段

### 系统字段 vs 用户标签的区别（2026-03-07 确立）

- **系统字段**（学科、年级、难度、来源等）：预定义选项，在设置中开关
- **用户自定义标签**（"易错"、"考前必看"、"老师强调"等）：用户输入文字、按空格生成，完全自由创建
- 标签是个性化的核心体现——每个学生的标签体系都是独一无二的
- 当前已支持：自由输入 + 历史标签建议

### 系统字段选项管理（2026-03-16 补全）

系统字段（学科、来源、年级）的**选项列表**支持用户增删改。
**按需无感创建优先**：用户在录入界面输入一个新来源即自动创建选项（颜色/图标赋予默认随机值），无需跳转到设置页走完整 CRUD 流程。设置页的选项管理器属于深度设置，入口需克制。

- **增**：用户可新增学科（如"信息技术"）、来源（如"竞赛真题"）、年级
- **删**：已被题目使用的选项不可删除（保护数据完整性）
- **改**：重命名时级联更新所有引用该选项的题目
- **颜色**：每个选项可选择一种颜色，用于过滤胶囊和列表中的视觉区分
- **图标**：从预设教育图标集（~70 个，按学科分 14 类）中选择，不开放全量 SF Symbol 访问。预设已覆盖所有学科场景，支持搜索过滤

设计原则：不同用户有不同的学科体系（小学 vs 初中 vs 竞赛），硬编码选项无法覆盖。

### 自动推断（与字段配置互补）

字段配置决定"字段是否存在"，自动推断决定"字段的默认值"：
- 上次选了"数学"→ 这次默认"数学"
- 上次选了"期中模拟卷三"→ 这次默认同来源
- 用户只需要改有变化的字段，其余自动填好

两者结合 = 用户只看到自己关心的字段，每个字段还自动填好了，录入摩擦降到最低。

## 多 Profile 设计 [P5 家长友好]

（2026-03-30 确立）

**核心场景**：多孩家庭的家长需要在同一台设备上管理不同孩子的题库。

**设计决策**：
- 参考 Obsidian 的 Vault 切换模式——轻量、本地、零注册
- Profile 切换入口在设置页或 Dashboard 头像区域，非高频操作不占主路径
- 每个 Profile 拥有独立的题库、统计、复习进度
- 切换 Profile 不需要密码——家长场景下无安全隔离需求
- Profile 数据随备份文件一起导出/恢复
- **初始创建**：首次启动时自动创建默认 Profile（用户无感），后续可在设置中新增/删除 Profile

**不做什么**：
- 不做家长-孩子关联账号体系
- 不做权限控制（家长视图 vs 孩子视图）

## 删除撤销设计 [P4 数据安全]

（2026-04-01 确立）

**核心理念**：误删是高代价操作，必须提供安全窗口。承接 Vision P4 数据安全子条款"删除必须可撤销"。

**设计决策**：
- **软删除 + Toast 撤销**：删除后不立即永久删除，而是标记为软删除，底部弹出 Toast 提供 5 秒撤销窗口
- **5 秒倒计时**：参考 Gmail 的撤销发送（5-30 秒可选），5 秒足够用户意识到误操作并点击撤销，又不会让 UI 长时间显示 Toast
- **超时永久删除**：5 秒后自动永久删除，不保留回收站（回收站增加管理复杂度，不符合简洁原则）
- **单级撤销**：仅支持最近一次删除的撤销，不做多级撤销栈（奥卡姆剃刀）

**不做什么**：
- 不做 iOS 标准摇一摇撤销（不适合删除场景，且摇一摇容易误触发）
- 不做回收站 / 最近删除文件夹（增加信息架构复杂度）
- 不做确认弹窗（高频操作用弹窗确认违反 HIG，Apple Notes 删除也无确认弹窗）

## 批量操作设计 [P2 简洁]

（2026-04-01 确立）

**核心理念**：题库积累到一定量后，逐条操作效率太低。

**设计决策**：
- **选择模式**：通过编辑按钮进入选择模式，勾选多题后执行批量操作
- **当前支持**：批量打标签、批量删除（软删除 + Toast 撤销复用单条删除机制）
- **交互流程**：进入选择模式 → 勾选题目 → 点击批量操作按钮 → 选择操作 → 完成

## 导出与打印设计 [P4 数据属于用户]

（2026-04-02 新增，承接 Vision 价值链终点）

**核心理念**：导出/打印是产品价值链的终点——家长录题的最终目的是让孩子在纸上练习。"数据属于用户"不是口号，而是可导出、可打印、可带走。

**设计决策**：
- **PDF 导出**：面向"整理一份错题卷"的完整场景。过滤后批量导出，支持预览（PDFKit）、分享、保存
  - 去答案打印模式：隐藏答案，只留题目，面向考前练习
  - 留白答题区：题目下方留白供孩子手写作答
  - 页眉页码：打印后纸质卷可翻阅定位
- **快速打印**：面向"临时打一道题"的轻量场景。选中 1-N 题，选择每页题数（1/2/4），直接调用系统打印
- **数据导出（JSON/CSV）**：从隐私设置页触发，定位是「数据可携带权」（GDPR 合规），非日常操作
- **免费层全覆盖**：PDF/JSON/CSV/快速打印全部免费。付费的是 Word 导出和组卷排版打印（Pro）

**不做什么**：
- 不做导出水印（产品不应该有水印，`product-requirements.md` Won't Have 明确）
- 不在导出中嵌入广告或 Pro 引导

## 备份与恢复设计 [P4 数据安全]

（2026-04-02 新增，承接 Vision P4 数据安全子条款"备份必须可用"）

**核心理念**：本地存储意味着 App 是用户数据的唯一守护者。免费用户没有 iCloud 同步，换机或卸载 = 数据永久丢失。手动备份是免费用户的生命线。

**设计决策**：
- **`.snapdrill` 文件**：ZIP 格式打包全部 Profile（题目、图片、元数据、复习进度），通过系统分享面板导出
- **全 Profile 覆盖**：备份覆盖设备上所有 Profile，不支持单 Profile 导出（简化操作，避免用户漏备）
- **恢复前校验**：先验证文件完整性和版本兼容性，校验失败拒绝恢复，现有数据不变
- **向后兼容铁律**：`.snapdrill` 备份的 Schema 必须保证向后兼容——新版本 App 必须能恢复旧版本备份。备份包必须包含足够的元数据（Schema 版本号、Migration Plan）以触发本地迁移逻辑。违反此规则 = 免费用户换机数据永久丢失，属于 P4 数据安全的硬性约束
- **恢复原子性**：不留"部分 Profile 已替换、部分未替换"的半恢复状态
- **卸载提醒**：设置页和适当时机提醒用户"纯本地存储，卸载 = 数据永久丢失，建议定期备份"

**不做什么**：
- 不做自动备份到本地（增加存储负担，且用户可能不知道备份在哪）
- 不做云端备份（那是 Pro iCloud 同步的职责）

## 复习设计 [P3 免费附加值, P5 家长友好]

### 克制原则（2026-03-07 确立）

- 复习是"锦上添花"，不能喧宾夺主
- **默认不推送通知**，但用户可在设置中自行开启并选择频率
- 不做打卡机制、不搞连续天数、不弹成就弹窗
- 这不是"学习打卡工具"，这是"存档工具"——复习只是附带福利
- 把选择权交给用户：有人需要提醒，有人不需要，我们尊重每个人的节奏

### 复习交互规则（2026-03-26 HIG 对标补充）

- **卡片形式**：正面 = 原题（图文），背面 = 答案。复习时**必须能看到图片**，尤其数学几何题
- **滑动评估**：左滑 = 不记得，右滑 = 记得（全屏卡片上下文，与系统返回手势的 edge swipe 物理起点不同，冲突可控）
- **按钮 fallback**：滑动手势必须有对应的"记得/不记得"按钮作为非手势替代方案。HIG Mobility 硬性要求："Offer alternatives to gestures"——不是所有用户都能执行滑动操作
- 需确保复习界面正确管理 `interactivePopGesture`，避免与系统返回手势冲突

## iCloud 同步设计 [v1.5, P4 数据安全, P6 原生优先]

（2026-04-02 新增，付费核心引擎预设计）

**核心理念**：iCloud 同步是 Pro 付费的核心引擎——打通"妈妈手机拍 + 孩子 iPad 练 + 打印机印"的多设备闭环。基于 Apple CloudKit，利用设备已有的 Apple ID 凭证，无需单独注册（与 Bear 模式一致）。

**设计决策**：
- **同步范围**：全部 Profile（与备份策略对齐）。同步是数据层面的——所有设备拥有完整数据副本；UI 层面仍需切换 Profile 才能查看特定孩子的题库。家长在任一设备上切换到"女儿"Profile 即可管理女儿题库，孩子 iPad 上默认显示自己的 Profile
- **冲突策略**：同一题在两设备同时编辑时，采用 last-write-wins + 冲突记录保留（CloudKit 默认行为），v1.5 实现时细化
- **iCloud 空间风险**：2000 题 ~400MB 可能占满 5GB 免费 iCloud 空间。需在设置页提供 iCloud 空间占用状态提示，空间不足时引导用户清理或升级 iCloud+
- **中国区注意**：中国大陆 iCloud 由云上贵州运营，数据存储在中国境内。合规责任在 Apple 侧，但同步体验可能与其他市场有差异，v1.5 实现时做针对性测试

**活跃状态管理铁律**：当侦测到当前活跃 Profile 被 iCloud 远端删除时，UI 会话自动 fallback 至默认 Profile 并给予断开提示，避免触发崩溃。此场景属于 S0 数据安全。

**不做什么**：
- 不做自建服务器同步（违反 P6 原生优先 + P4 隐私）
- 不单独售卖同步功能（与其他 Pro 功能打包，避免 App Store 审核指引 3.2.2 风险）

## 设置与个性化设计概要 [P5 家长友好, P2 简洁]

（2026-04-02 新增）

**核心理念**：设置服务于个性化，不服务于复杂度。家长不需要理解 App 内部概念。

**设计决策**：
- **用户资料纯本地**：昵称/座右铭/头像/每日目标不外传，与 P4 零注册一致
- **通知权限延迟请求**：仅在用户主动开启提醒开关时触发系统授权弹窗（HIG: 用户理解价值后才请求）
- **外观三选项**：跟随系统（默认）/ 浅色 / 深色。行业惯例，Apple 不因此拒审
- **Analytics 可关闭**：匿名使用数据默认开启，用户可随时关闭。单一开关控制
- **语言 App 内直选**：中文/英文直选，不依赖系统设置（海外华人场景核心需求，旅程 7 验证）

## 引导与帮助设计概要 [P5 家长友好, P2 简洁]

（2026-04-02 新增）

**核心理念**：让用户尽快开始录题，不用"学习怎么用"。

**设计决策**：
- **Onboarding 快进不配置**：首次启动多页引导介绍核心功能，不在 Onboarding 中要求字段配置（HIG: "Avoid asking for setup information up front"）。首个 Profile 自动创建，用户无感
- **字段引导延后**：首次录入保存后弹出引导提示，而非首次启动
- **TipKit 提示**：首次使用某功能时轻量提示气泡，每个只显示一次
- **帮助中心外链**：设置页提供 FAQ 链接跳转外部网页。不在 App 内构建搜索系统（Bear/Things 3/Notion 验证此模式）
