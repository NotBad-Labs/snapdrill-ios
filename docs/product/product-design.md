## 全局设计规则

### 价值链与优先级（Kano 模型对标）

```
┌─────────────────────────────┐
│   智能复习（锦上添花）          │  ← Kano: Excitement / Could
├─────────────────────────────┤
│   增强导出打印（价值链增值）     │  ← Kano: Performance / Should
├─────────────────────────────┤
│   整理管理（核心体验）          │  ← Kano: Performance / Should
├─────────────────────────────┤
│   基础导出 + 数字化录入（生命线）│  ← Kano: Basic / Must
└─────────────────────────────┘
```

**导出分层**：基础导出（PDF/JSON/CSV）是 P4 数据所有权的 Must，缺失 = 数据被锁在 App 中。增强导出打印（去答案、留白、组卷）是 Performance/Should。

**设计铁律**：任何功能如果损害了"录入"和"管理"的简洁性，就不该做。导出/打印是核心价值链终点（纸质练习卷）。复习是可选留存层，智能组卷是导出/打印的 Pro 增值延伸。

### 情绪基调

SnapDrill 是纯粹的效率工具。全局文案、Onboarding、成功反馈、空状态、付费提示均遵循：
- **客观冷静**：不向家长贩卖教育焦虑（不做"今日仅剩 X 题额度"、不做连续天数打卡、不弹成就渲染）
- **成熟语气**：界面面向成年家长，不幼稚、不卡通
- **尊重节奏**：把选择权交给用户，不主动推送、不施加压力

### 原则冲突裁决

冲突裁决规则见 `product-vision.md`§原则冲突裁决（含免费层能力不得降级的额外约束）；本文档不重复列出，只在具体设计场景中引用。

## 信息架构 [P1 录入体验, P2 简洁]

### 导航结构

底部 Tab 栏常驻（首页/题库/采集/复习/设置），采集入口作为标准 Tab 始终可达。
为保持导航架构的极致简洁（P2 简洁）和降低认知负荷，采集入口作为标准 Tab 而非自定义突出按钮。
如未来用户反馈可发现性不足，可评估 FAB 方案——参考 Apple Reminders / Journal 的做法。

复习是可选留存层（非核心价值链），但因其使用频率足以支撑独立 Tab，故既有独立 Tab（主入口），也在 Dashboard 提供"今日待复习 N 题"快捷入口（旅程 5 验证），两者并存。

### Dashboard 设计角色

Dashboard 是用户打开 App 后的第一屏，定位是**状态总览 + 快捷入口**，不是功能操作界面：
- 展示当前 Profile 的核心统计（题目总数、待复习数、已复习数、今日新增）
- 展示待复习数量和快捷入口
- 问候语 + 用户昵称（个性化但不过度）
- 不在 Dashboard 做录入或管理操作——录入走采集 Tab，管理走题库 Tab

### 题库信息架构 [P1 录入体验, P2 简洁]

**为什么默认按录入时间倒序**：最新录入的题目最可能需要编辑补充（加答案、改难度），倒序让它们最先出现。

**为什么过滤维度是学科/标签/难度**：
- 学科：最粗粒度的分类，所有用户都用
- 标签：个性化语义过滤（"易错""考前"），每个学生独特
- 难度：考前复习场景高频（只看难题）
- 不做来源/年级过滤——使用频率低，加入过滤会增加 UI 复杂度（P2 简洁）

**搜索基于 OCR 文本**：用户记得题目中的关键词，搜索匹配 OCR 识别出的文字内容。

## OCR 定位 [P1 录入体验, P6 原生优先]

**核心定位**：OCR 是辅助展示 + 搜索索引 + 可复制文本，原图是真相。

SnapDrill 依托 Apple Vision 原生识别能力（端上实时运行，无需联网，零数据外传）。

**录入流程中的 OCR 策略**：
- OCR 文字**展示但不强迫校对**——用户看到识别结果，可以修正也可以直接保存。用户无需逐字校对，但如发现明显错误（如几何符号 △ 被识别为 A）可随时修正——校对是可选的，不是强制的
- 不制造「必须校对完才能保存」的心理负担
- OCR 文字的核心价值是**全局搜索**（旅程 4 中"搜索抛物线"的场景）
- OCR 结果可**复制到剪贴板**，方便用户将识别文字粘贴到其他 App
- OCR 识别失败时提供**手动重试**选项，并显示稳定性提示引导用户调整拍摄姿势

**物理环境鲁棒性**（承接 Vision P1）：
家长的真实拍摄场景远比实验室恶劣——夜晚昏暗光线、揉皱的试卷、红蓝黑笔交错、阴影和折痕。
具体策略：高精度识别模式 + 稳定性指示器引导用户对准 + 自动框选降低手动裁剪负担。

**产品影响澄清**：
- 手写体识别能力有限，手写体增强列为探索性 [需 PoC: 识别率 >= 70%]——**为什么当前不做**：Apple Vision 对中文手写体的识别率未达到"不强迫校对"的基线，强行上线会违反 P1（增加摩擦）
- 数理化公式无 Apple 原生识别 API，与隐私优先定位存在张力，列为探索性 [需 PoC: 端上方案可用且 SDK < 50MB]

**双语 / 多脚本 OCR（海外华人场景）**：
- 海外华人用户（北美 / 欧洲 / 东南亚）日常题目可能是简体中文、繁体中文、中英混排
- Apple Vision 默认语言列表已含简繁中英（`recognitionLanguages: ["zh-Hans", "zh-Hant", "en-US"]`），不需要独立设计决策
- 当前 OCR 调用按 Profile 优先语言传入 recognitionLanguages（系统默认从 Profile 推断）
- 重审触发：用户反馈繁体识别率明显低于简体 / 出现日韩文等其他脚本需求 → 走 vision §市场策略豁免讨论

## 图片存储策略 [P1 录入体验, P4 数据安全]

通过图片入口（Camera/Photos/PDF/Share Extension）录入的题目，图片**必须保存**，包括文字部分和图形部分。
OCR 识别出的文字是辅助（方便搜索和编辑），图片是真相。
**例外**：Manual edit（纯文本录入）允许无图保存——用户手动输入的文字本身就是真相源，此时不存在"OCR 与原图冲突"的场景。"Image is Truth" 原则的核心是"当 OCR 文本与原图不一致时以原图为准"，不是"每道题必须有图"。

**为什么压缩副本而不是原图**：用户拍摄的原图可能 5-10MB，若不压缩 200 道题就占 1-2GB，对 iPhone 存储压力大。高质量压缩后 ~200KB/张（200 道题仅约 40MB），公式和图形仍清晰可辨，存储负担降低 25 倍。用户的原始照片不被修改——SnapDrill 只存储裁剪压缩后的副本。

## 字段可配置系统 [P1 录入体验, P2 简洁]

**核心理念**：题目需要多少分类字段，由用户决定，而非开发者硬编码。

### 字段分层

| 层级 | 字段 | 行为 |
|---|---|---|
| 固定字段 | 题目内容（文字/图片） | 永远存在，不可关闭 |
| 默认开启 | 学科 | 新用户开箱仅此一项，可在设置中关闭 |
| 默认关闭 | 难度、来源、年级、答案 | 用户按需在设置中开启 |
| 自定义标签 | 用户自由创建的标签（如"易错""考前必看"） | 始终可用，不可关闭 |

**为什么学科是唯一默认开启字段**：家长基线（P5）要求首次录入零负担。学科是最粗粒度的分类，几乎所有用户都需要；难度/来源/年级对小学家长来说太重，默认关闭避免首次录入界面拥挤。首次保存后引导用户按需开启。

### 系统字段 vs 用户标签

- **系统字段**（学科、年级、难度、来源等）：预定义选项，支持过滤和排序
- **用户自定义标签**（"易错"、"考前必看"等）：自由创建，用于个性化语义分类
- **分界原则**：需要结构化过滤/排序/统计的用系统字段；纯个人语义的用标签

### 配置入口

- **首次录入后引导**：用户完成第一次录入保存后，弹出引导提示「要不要开启更多字段（难度、来源等）？」。首次启动 Onboarding 不要求配置（Apple HIG："Avoid asking for setup information up front"）
- **设置阶段**：设置中提供"字段管理器"，随时开关
- **录入阶段**：录入界面只显示用户已开启的字段
- **补充阶段**：题库中编辑已有题目时，可随时扩展新字段

### 系统字段选项管理

系统字段（学科、来源、年级）的**选项列表**支持用户增删改。
**按需无感创建优先**：用户在录入界面输入一个新来源即自动创建选项（颜色/图标赋予默认随机值），无需跳转到设置页走完整 CRUD 流程。设置页的选项管理器属于深度设置，入口需克制。

- **增**：用户可新增学科（如"信息技术"）、来源（如"竞赛真题"）、年级
- **删**：已被题目使用的选项不可删除（保护数据完整性）
- **改**：重命名时级联更新所有引用该选项的题目
- **颜色/图标**：每个选项可选颜色和图标，用于过滤胶囊和列表中的视觉区分

设计原则：不同用户有不同的学科体系（小学 vs 初中 vs 竞赛），硬编码选项无法覆盖。

### 自动推断（与字段配置互补）

字段配置决定"字段是否存在"，自动推断决定"字段的默认值"：
- 上次选了"数学"→ 这次默认"数学"
- 上次选了"期中模拟卷三"→ 这次默认同来源
- 用户只需要改有变化的字段，其余自动填好
- 自动推断按 Profile 隔离——切换 Profile 后推断基于该 Profile 的历史

两者结合 = 用户只看到自己关心的字段，每个字段还自动填好了，录入摩擦降到最低。

## 连续录入设计 [P1 录入体验]

保存题目后，默认跳转回采集界面（摄像头），而非 Dashboard。
一张试卷可能错 3-5 题，连续录入是高频场景，每多一次跳转就多一份摩擦。

连续录入原则适用于所有入口：Camera 保存后回到 Camera，Photos 连续裁剪保存后同图再次出现。

---

## 一图多题设计原则 [P1 录入体验]

真实场景：一张试卷照片上可能有多道题，用户只想录其中几道。

**为什么当前选择手动裁剪而不是 AI 拆题**：AI 辅助拆题依赖 Apple 文档结构识别能力，识别准确率未达到"用户无需逐题确认"的基线。手动裁剪 + 连续裁剪已覆盖核心场景，AI 拆题列为探索性（需 PoC 验证）。

具体版本能力见 `product-requirements.md`§一图多题演进路线。

## 草稿恢复设计 [P4 数据安全]

**核心理念**：录入过程中用户意外退出（来电、误触 Home 键）时，已输入的内容不应丢失。这是 S0 级数据丢失防护。

**为什么只保留最近一份**：多份草稿增加恢复时的选择负担（P2 简洁），且意外退出场景下用户几乎只关心最近一次编辑。

**为什么 7 天过期**：草稿不是正式数据，长期保留会占用存储且可能误导用户。7 天足够用户下次打开 App 恢复。

**为什么恢复提示在重新进入采集时出现**：而不是首页弹窗——因为只有进入采集界面才意味着用户要录新题，此时提示恢复最相关。

## 多 Profile 设计 [P5 家长友好]

**核心场景**：多孩家庭的家长需要在同一台设备上管理不同孩子的题库。

**设计决策**：
- 参考 Obsidian 的 Vault 切换模式——轻量、本地、零注册
- Profile 切换入口在设置页或 Dashboard 头像区域，非高频操作不占主路径
- 每个 Profile 拥有独立的题库、统计、复习进度、草稿、自动推断历史
- 切换 Profile 不需要密码——家长场景下无安全隔离需求
- Profile 数据随备份文件一起导出/恢复
- 备份覆盖设备上所有 Profile（#531 已修复）
- **初始创建**：首次启动时自动创建默认 Profile（用户无感），后续可在设置中新增/删除 Profile

**切换中断策略**：
- 存在未保存编辑或草稿时：提示保存/放弃，不静默切换
- 存在进行中的 OCR/导出/打印：等待完成或提示中断
- 切换失败：保持原 Profile 不变，不进入混合状态

**最后一个 Profile 删除策略**：
- 禁止删除最后一个 Profile——删除按钮 disabled 并提示「至少保留一个 Profile」
- 为什么阻止而不是自动创建空 Profile：自动创建导致"删不掉"的困惑体验，且新 Profile 缺少个性化信息，不如直接阻止（奥卡姆剃刀）

**全局状态 vs Profile 隔离**：
- **TipKit tooltip 状态**：按 Profile 隔离（#532 已修复，#563 合并）
- **VoiceOver / 辅助功能**：全局（系统级，App 不控制）
- **Onboarding 完成状态**：全局——首次引导只展示一次，不因切换 Profile 重新触发
- **Per-Profile 隔离**：题库、统计、复习进度、草稿、自动推断历史、字段配置、卡片字号、每日复习目标、题库排序偏好

**不做什么**：
- 不做家长-孩子关联账号体系
- 不做权限控制（家长视图 vs 孩子视图）

## 删除撤销设计 [P4 数据安全]

**核心理念**：误删是高代价操作，必须提供安全窗口。承接 Vision P4"删除必须可撤销"。

**设计决策**：
- **软删除 + Toast 撤销**：删除后不立即永久删除，底部弹出 Toast 提供 5 秒撤销窗口
- **5 秒倒计时**：参考 Gmail 撤销发送，5 秒足够用户意识到误操作
- **超时永久删除**：不保留回收站（回收站增加管理复杂度，不符合 P2 简洁）
- **单级撤销**：仅支持最近一次删除的撤销，不做多级撤销栈（奥卡姆剃刀）
- **后台/被杀收敛**：App 在 undo window 内进入后台或被杀死时，下次启动必须收敛到确定状态，不出现幽灵记录

**不做什么**：
- 不做摇一摇撤销（不适合删除场景，且易误触发）
- 不做回收站（增加信息架构复杂度）
- 不做确认弹窗（高频操作用弹窗确认违反 HIG）

## 批量操作设计 [P2 简洁]

**核心理念**：题库积累到一定量后，逐条操作效率太低。

**为什么只做批量打标签和批量删除**：这两个是题库管理中最高频的批量需求。批量编辑系统字段（学科/难度等）场景少且交互复杂，暂不支持。批量操作能力随用户反馈渐进扩展。

**设计决策**：
- 通过编辑按钮进入选择模式，勾选多题后执行批量操作
- 批量删除复用单条删除的 soft delete + Toast 撤销机制

## 导出与打印设计 [P4 数据属于用户]

**核心理念**：导出/打印是产品价值链的终点——家长录题的最终目的是让孩子在纸上练习。"数据属于用户"不是口号，而是可导出、可打印、可带走。

**设计决策**：
- **PDF 导出**：面向"整理一份错题卷"的完整场景。过滤后批量导出，支持预览、分享、保存
  - 去答案打印模式：隐藏答案，只留题目，面向考前练习
  - 留白答题区：题目下方留白供孩子手写作答
  - 页眉页码：打印后纸质卷可翻阅定位
- **快速打印**：面向"临时打一道题"的轻量场景。选中 1-N 题，选择每页题数（1/2/4），直接调用系统打印
- **数据导出（JSON/CSV）**：JSON 从隐私设置页触发；CSV 可从隐私设置页或题库导出面板触发——**为什么 JSON 不放主路径**：定位是数据可携带权（GDPR 合规），不是日常操作。放在隐私设置页强调"这是你的数据权利"
- **结构化数据导出**：以实际导出字段清单为准；如有未覆盖字段，需在帮助文档说明

**不做什么**：
- 不做导出水印（产品不应该有水印）
- 不在导出中嵌入广告或 Pro 引导

**"去答案打印"与"图片处理增强"的区分**：
- **去答案打印**（免费）：隐藏答案文字字段导出 PDF，是布局层面的操作，属于基础导出能力
- **图片处理增强**（Pro）：AI 去手写/去批改痕迹/试卷还原，是对题目图片本身的智能处理，属于增值能力。两者技术层面完全不同，不应混淆

**版权合规边界（承接 `product-vision.md` §版权合规边界）**：
- 导出与分享面向**个人使用**：自家孩子复习用的 PDF / 打印 / 分享卡片不受版权限制
- 不公开传播：不在导出文件嵌入「上传到云盘 / 分享到社交网络」类引导
- 分享卡片定位：家长间一对一交流的样张图片，不是「社交分享」（vision §不是社交产品）
- ShareSheet 用系统 ShareSheet 保留路径自由，但 App 内 UI 文案不引导公开传播

## 智能组卷设计 [Pro Hybrid] [已实现, #566] (ADR-001)

**核心理念**：家长录题的最终目的是让孩子在纸上练习。智能组卷把"导出 PDF"从手动选题升级为算法驱动的精准选题——基于 SM-2 复习数据自动推荐薄弱题目，排版生成可打印的练习卷。

**定价模型**（ADR-001 决策）：
- **免费层**：有限次/月 + 基础模板
- **Pro 层**：无限生成 + 精准选题（weakness/difficulty/recency 多维度）+ 多版式

**选题策略**：
- **基础选题**（免费）：按学科过滤 + 随机抽取
- **精准选题**（Pro）：SM-2 weakness 权重 + 难度分布均衡 + 近期错误优先 + 学科交叉筛选

**输出格式**：PDF，复用现有 PDFExportService 管线（去答案模式 / 留白答题区 / 页眉页码）。

**交互流程**：
1. 用户从题库或 Dashboard 进入智能组卷
2. 选择学科范围和题目数量
3. 免费用户使用基础模板；Pro 用户可选精准选题策略和版式
4. 预览生成的 PDF
5. 分享 / 打印 / 保存

**与高级统计联动**（Codex 洞察）：Analytics 让家长看到薄弱点 → 一键生成针对性练习卷 → 打印 → 练习 → 再次统计。两个 Pro 功能转化力叠加。

**配额机制**：
- 免费配额按自然月重置
- 配额耗尽后展示 Pro 引导（不阻断已有功能）
- 与图片处理增强的配额模式统一

## 高级统计设计 [Pro Hybrid] [已实现, #567] (ADR-001)

**核心理念**：为家长提供决策依据——补习哪里、练什么难度的题。Dashboard 基础统计是免费的"成就感"层，深度分析是 Pro 的"专业感"层。

**设计决策**：

- 统计数据基于当前 Profile（Profile 隔离）
- 入口在 Dashboard（快捷入口）和设置/统计页（完整视图）
- Pro 图表区域免费用户可见模糊预览 + Pro 引导（展示价值再转化）

## 图片处理增强设计概要 [Pro 增值] [未实现, 需 PoC]

**核心理念**：家长拍摄的试卷/作业上有孩子的手写答案和老师的批改痕迹。去掉这些痕迹，还原干净试卷，是"导出打印练习卷"场景的自然延伸——让打印出来的练习卷像全新的一样。

**设计决策**：

**技术前提**：需第三方端上方案 PoC，Go/No-Go 条件见 `product-requirements.md`§探索性功能评估框架。

**不做什么**：
- 不做云端图片处理（违反 P4 隐私）
- 不在免费层完全锁死此功能（限次体验是转化关键）

## 备份与恢复设计 [P4 数据安全]

**核心理念**：本地存储意味着 App 是用户数据的唯一守护者。免费用户没有 iCloud 同步，换机或卸载 = 数据永久丢失。手动备份是免费用户的生命线。

> 产品规范（S0 级承诺）见 `product-requirements.md`§备份与恢复。

**设计决策**：
- **`.zip` 文件**：ZIP 格式打包全部 Profile（题目、图片、元数据、复习进度），通过系统分享面板导出
- **全 Profile 覆盖**：备份覆盖设备上所有 Profile，不支持单 Profile 导出（简化操作，避免用户漏备）
- **恢复前校验机制**：恢复入口先验证文件完整性和版本兼容性，校验失败直接拒绝恢复并保持现有数据不变
- **兼容机制**：为满足 `product-requirements.md`§备份与恢复中的向后兼容规范，`.zip` 备份包必须包含 Schema 版本号、Migration Plan 等元数据，供恢复流程判定直接导入、触发本地迁移或拒绝恢复
- **恢复目标**：元数据恢复必须原子（完整成功或完整失败）；图片恢复为 best-effort（个别图片缺失不阻断恢复）。恢复完成后显示结果摘要与失败项提示
- **恢复前安全网（自动备份）**：执行恢复前，App 自动将当前数据快照到沙盒临时目录（一份 `.zip` 命名带时间戳）。恢复失败时一键回滚到操作前状态；成功后保留临时备份至下次启动自动清理。用户在 UI 看不到这一步，但失败 Alert 文案明确告知「您的原数据已自动备份在内部临时目录」
- **卸载提醒**：设置页和适当时机提醒用户数据风险

**不做什么**：
- 不做自动备份到本地（增加存储负担）
- 不做云端备份（那是 Pro iCloud 同步的职责）

## 复习设计 [P3 免费附加值, P5 家长友好]

### 克制原则

- 复习是"锦上添花"，不能喧宾夺主
- **默认不推送通知**，但用户可在设置中自行开启并选择频率——**为什么既然默认不推送仍做完整通知设置**：把选择权交给用户。有人需要提醒，有人不需要，产品不替用户做决定
- 不做打卡机制、不搞连续天数、不弹成就弹窗
- 复习入口在信息架构中不得压过采集和题库

### SM-2 定位

已实现完整的 SM-2 间隔重复复习（翻卡 + 滑动评估）。**SM-2 的双重角色**：
- **免费层**：基础复习功能，吸引用户留存，让用户感受到"题目录了不白录"
- **Pro 层**：SM-2 驱动智能选题 → 组卷排版打印，是 Pro 的核心增值能力

**为什么是 SM-2 而不是更轻的待复习列表**：SM-2 自动安排复习间隔，用户不需要自己判断"该复习哪道"。算法负担在后台，用户界面极简（只需"记得/不记得"），与 P5 家长友好一致。

### 复习交互规则

- **卡片形式**：正面 = 原题（图文），背面 = 答案。复习时**必须能看到图片**，尤其数学几何题
- **滑动评估**：左滑 = 不记得，右滑 = 记得（全屏卡片上下文，与系统返回手势的 edge swipe 物理起点不同，冲突可控。按冲突裁决规则 P1(录入体验) > P6(原生优先)，复习交互的简洁性权重更高）
- **按钮 fallback**：滑动手势必须有对应按钮（HIG Mobility 要求）
- **答案缺失仍可评估**：翻面显示空答案，用户仍可完成"记得/不记得"——因为用户可能心里知道答案但没录入

## 空状态与错误处理设计 [P2 简洁, P4 数据安全, P5 家长友好]

### 空状态原则

- 空状态先解释"这里为什么是空的"，再给一个最近动作入口，不做教育式说教
- 空题库、无搜索结果、无到期复习题属于三类不同空状态：首次未开始、过滤后为空、当前阶段已完成，文案必须区分
- 空状态 CTA 只给一个主动作，避免把用户带回复杂选择题
- 空状态不得借机强推订阅；免费层空状态优先指向采集、恢复、帮助而非付费墙

### 错误分级

| 级别 | 场景 | 处理原则 |
|---|---|---|
| **L1 可忽略提示** | OCR 识别不准、搜索无结果、无到期复习题 | 内联说明 + 可继续当前流程，不打断任务 |
| **L2 可恢复错误** | 权限缺失、导出失败、恢复校验失败、网络/CloudKit 暂时异常 | 明确原因 + 给重试或替代路径，不静默吞错 |
| **L3 数据风险错误** | 保存失败、恢复半成功、活跃 Profile 丢失、图片文件缺失 | 必须醒目提示结果摘要和后果，优先保护现有数据 |

### 可访问性基线

- 所有空状态图示和错误图标都必须有可读文本，不依赖颜色单独传递信息
- 错误反馈既要有视觉呈现，也要有 VoiceOver 可读文案和必要的 announcement
- 错误文案优先说人话，先描述结果和下一步，再补技术原因
- 可点击修复动作的命名必须直接对应用户意图，如"重试""去设置""恢复备份"，避免抽象按钮文案

## iCloud 同步设计 [P4 数据安全, P6 原生优先] [未实现, 阻塞: #485]

**核心理念**：iCloud 同步是 Pro 付费的核心引擎——打通多设备闭环。基于 Apple CloudKit，利用设备已有的 Apple ID 凭证，无需单独注册。

**设计决策**：
- **同步范围**：全部 Profile（与备份策略对齐）。同步是数据层面的——所有设备拥有完整数据副本；UI 层面仍需切换 Profile 才能查看特定孩子的题库
- **冲突策略**：同一题在两设备同时编辑时，采用 last-write-wins + 冲突记录保留（CloudKit 默认行为），实现时细化
- **iCloud 空间风险**：2000 题 ~400MB 可能占满 5GB 免费 iCloud 空间。需在设置页提供空间占用提示

**活跃状态管理铁律**：当侦测到当前活跃 Profile 被 iCloud 远端删除时，UI 会话自动 fallback 至默认 Profile 并给予提示，避免崩溃。

**不做什么**：
- 不做自建服务器同步（违反 P6 原生优先 + P4 隐私）

## Share Extension 设计 [P1 录入体验] [已实现, #477 已关闭]

**为什么 Share Extension 是次级入口而非主入口**：主录入入口（Camera/Photos/PDF/Manual/Clipboard）覆盖了绝大多数场景。Share Extension 解决的是"从微信/QQ 直接分享图片到 SnapDrill"的特定场景——免去保存相册步骤，减少一次跳转。

**在入口体系中的位置**：Share Extension 不污染主导航（不改变 Tab 结构），作为系统级扩展独立于 App 主界面。进入后直接进入裁剪/编辑 → 保存流程。

## 设置与个性化设计概要 [P5 家长友好, P2 简洁]

**核心理念**：设置服务于个性化，不服务于复杂度。家长不需要理解 App 内部概念。

> 使用数据（Analytics/Crashlytics）opt-in 规格见 `product-requirements.md`§使用数据。

**设计决策**：

- **通知权限延迟请求**：仅在用户主动开启提醒开关时触发系统授权弹窗（HIG: 用户理解价值后才请求）
- **外观三选项**：跟随系统（默认）/ 浅色 / 深色
- **语言 App 内直选**：中文/英文直选，不依赖系统设置（海外华人场景核心需求，旅程 7 验证）

## 引导与帮助设计概要 [P5 家长友好, P2 简洁]

**核心理念**：让用户尽快开始录题，不用"学习怎么用"。

**设计决策**：
- **Onboarding 快进不配置**：首次启动多页引导介绍核心功能，不要求字段配置。首个 Profile 自动创建，用户无感
- **字段引导延后**：首次录入保存后弹出引导提示，而非首次启动
- **TipKit 提示**：按 Profile 隔离（见上文§多 Profile 设计）
- **帮助中心外链**：设置页提供 FAQ 链接跳转外部网页。不在 App 内构建搜索系统（Bear/Things 3/Notion 验证此模式）
