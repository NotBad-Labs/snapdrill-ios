## 录入方式优先级

| 优先级 | 方式 | 说明 | 版本 |
|---|---|---|---|
| P0 | 摄像头拍照（智能相机） | 最高频场景：看到题 → 拍一张 → 存档。实时文字区域检测 + 稳定性指示器 + 自动框选 | v1.0 ✅ |
| P0 | 相册导入 | 已有照片（截图、微信图片等）的导入。**iPad 上这是主要录入方式**——举 iPad 拍试卷体验笨重 | v1.0 ✅ |
| P0 | 文档扫描 | 系统级文档扫描（自动透视校正、边缘检测、多页扫描） | v1.0 ✅ |
| P0 | PDF 导入 | 试卷、作业的批量数字化。选择 PDF 文件后逐页预览、选择页面、裁剪 | v1.0 ✅ |
| P1 | 手动编辑 | 兜底方案：用户自己输入文字和图片 | v1.0 ✅ |
| P1 | iOS Share Extension | 从微信/QQ/浏览器直接分享图片到 SnapDrill，免去保存相册步骤 | v1.5 |
| P2 | 其他载体 | 未来扩展（如网页剪藏等） | — |

> **注**：P1 表示重要性仅次于 P0，不等于 v1.0 必须实现。具体版本归属见底部「版本路线图」。

## 导出与打印能力（2026-04-02 版本归属修正）

| 版本 | 格式 | 说明 | 付费 |
|---|---|---|---|
| v1.0 | PDF | 基础 PDF 导出，含导出前预览（PDFKit 内嵌查看器） | 免费 |
| v1.0 | JSON | 全字段数据导出（隐私设置页，支持 GDPR 数据可携带权） | 免费 |
| v1.0 | CSV | 全字段数据导出（隐私设置页，可用 Excel 打开） | 免费 |
| v1.0 | PDF 增强 | 去答案打印模式、留白答题区、页眉页码 | 免费 |
| v1.0 | 单题快速打印 | 选中题目直接打印，支持每页题数可选（1/2/4 题） | 免费 |
| v1.5 | Word | 高级导出格式，支持家长调整排版后打印 | Pro 付费 |

JSON 和 CSV 均从隐私设置页触发，定位是「数据属于用户」的体现，非日常高频操作。
PDF 是日常导出入口（题库页过滤后导出），支持分享和打印。

**打印 vs 导出的区分**：
- **快速打印**（v1.0 免费）：选中 1-N 道题，选择每页题数，直接调用系统打印。面向「考前临时打一道题」的轻量场景
- **PDF 导出**（v1.0 免费）：过滤后批量导出为 PDF 文件，支持预览、分享、保存。面向「整理一份错题卷」的完整场景
- **组卷排版打印**（v1.5 Pro 付费）：SM-2 驱动智能选题 → 自动排版 → 打印。面向「智能复习卷」的进阶场景

## 草稿恢复（2026-03-16 补全，2026-04-02 版本归属修正）

录入过程中用户意外退出（如来电、误触 Home 键），已输入的内容不应丢失。
- 采集页面退出时自动保存草稿（图片 + OCR 文字，或纯文本）
- 下次进入采集时检测到草稿，弹窗提示用户恢复或放弃（含草稿内容摘要）
- 草稿仅保留最近一份，保存新题目后自动清除
- 草稿 7 天过期后自动清理
- 支持纯文本草稿保存（无图片的手动录入场景）

这是 S0 级数据丢失防护，不是功能特性。

## 引导与帮助（2026-03-16 补全）

### Onboarding（首次启动引导，2026-03-18 #304 终审修订）

首次启动展示多页引导流（~3-4 页），介绍核心功能。**不在 Onboarding 中要求字段配置**——
Apple HIG 明确反对首次启动时要求用户配置（"Avoid asking for setup information up front"）。
字段选择延后到首次录入保存后，通过引导提示触发（见 `product-design.md`§字段可配置系统 → 配置入口）。
完成后不再显示。设计原则：快速、不啰嗦，让用户尽快开始录题。

### Feature Tooltips（功能提示）

首次使用某功能时弹出轻量提示气泡（如首次进入过滤页提示「可多选学科」）。
每个提示只显示一次，不打扰。

技术实现：评估迁移到 Apple TipKit 框架。TipKit 提供标准化的提示气泡样式、频率控制和持久化，替代当前自定义的 OnboardingManager + FeatureTooltip。迁移后可删除自定义实现，减少维护成本。

### 帮助中心（2026-03-18 #304 终审修订）

设置页提供帮助入口，跳转到外部网页 FAQ。行业验证：Bear、Things 3、Notion、Day One 全部使用外部网站 FAQ，不在 App 内构建搜索系统。
优势：内容更新不需要发版、开发维护成本低、v1.0 阶段用户量小无需重投入。

## 设置与个性化（2026-03-16 补全）

### 用户资料（纯本地，不上传）

- **昵称**：显示在 Dashboard 问候语中
- **座右铭**：个人激励文字
- **头像**：从预设头像组中选择，或从相册上传自定义照片
- **每日复习目标**：用户自由设定，无硬性范围限制

所有资料纯本地存储，不外传，与 PV-4「不收集可识别个人信息」一致。
这不是注册信息，是本地个性化定制。

### 复习卡片外观（2026-03-18 #304 终审修订）

- 字号：正面和背面独立设置，范围相同（题目和答案内容密度天然不同，独立字号是合理需求）
- 对齐方式：左对齐 / 居中 / 右对齐三选项，正反面均默认左对齐
- 提供实时预览

### 通知细节

- 通知权限请求时机：**仅在用户主动开启提醒开关时触发**系统授权弹窗（HIG: 用户理解价值后才请求，不在首次启动时请求）
- 每日复习提醒：开关 + 时间选择（小时/分钟）
- 通知声音开关
- App 图标角标开关（角标 = 图标右上角红色数字气泡，显示待复习数）

### 外观

- 外观模式：跟随系统（默认）/ 浅色 / 深色。HIG 建议跟随系统，但三选项是行业惯例（Telegram、Bear、Notion），Apple 不因此拒审

### 存储维护

- 媒体缓存清理：清理 App 运行产生的临时文件（OCR 临时图片、PDF 渲染缓存等），不影响用户题目数据

### 使用数据（Analytics + 崩溃报告）

- 单一开关控制匿名使用数据收集（Firebase Analytics + Crashlytics）
- **默认开启**，用户可随时在设置中关闭
- 收集的是匿名事件计数和崩溃堆栈，不含任何可识别个人信息或用户内容

### 语言设置

- 支持 App 内直接切换语言（中文/英文直选，不依赖系统设置）

## 功能边界

### 功能边界（MoSCoW 分类）

> **MoSCoW** 优先级框架：Must = 没有就不能发布；Should = 重要但可延期；Could = 锦上添花；Won't = 明确不做。
> 与 Kano 模型对应：Must ≈ Basic（缺失导致不满）；Should ≈ Performance（越好越好）；Could ≈ Excitement（惊喜功能）。

#### Must Have（缺失 = 产品不可用）

- 多种方式录入题目（拍照、导入、手动）
- OCR 文字识别（降低手动输入成本）
- 题目分类管理（学科、来源、年级、标签、难度）
- 搜索和过滤
- 导出（PDF / JSON / CSV）
- 本地数据存储（隐私优先）
- 多 Profile（多孩家庭核心场景）
- 草稿恢复（S0 数据丢失防护）
- 删除撤销（数据安全信任）

#### Should Have（缺失 = 有摩擦但可用）

- PDF 增强（去答案、留白、页眉页码）
- 单题快速打印
- 批量打标签
- 批量删除（选择模式 + 软删除）
- 难度过滤
- App 内语言切换
- 手动备份/恢复
- iOS Share Extension

#### Could Have（锦上添花）

- 基于遗忘曲线的间隔重复复习（附加值定位，非核心能力）
- iCloud 同步（Pro 付费）
- Word 导出（Pro 付费）
- 组卷排版打印（Pro 付费，SM-2 驱动）
- 高级统计 + 趋势图（Pro 付费）
- 题目分享（单题生成卡片分享）
- 批量导出原图（ZIP）
- 数据导入（CSV 导入）
- iPad 大屏优化
- 一图连续裁剪
- 批量导入增强（AI 辅助拆题，探索性）
- 手写体识别增强（探索性）
- 端上 AI 集成（探索性）
- 角色预设套件

#### Won't Have（明确不做）

- 提供题库内容（我们是工具，不是内容平台）
- 社交功能（不是社区）
- 排行榜 / 竞争机制（不是游戏）
- 限制免费录入数量（不做竞品最恶心的事）
- 去水印（产品本身不应该有水印）
- 注册/登录（零注册是核心差异化）

#### 待评估（需技术可行性确认）

- 公式识别与渲染（LaTeX/MathML，无 Apple 原生 API）
- 去手写 / 试卷还原（AI 笔迹清除，无 Apple 原生 API）
- iPad + Apple Pencil 深度集成（依赖第三方 App 支持）
- 多科目模板（不同学科结构化字段）
- AI 解题提示（远期探索，需明确边界——辅助提示 vs 直接生成答案，与"效率工具"定位的平衡）

### 家长模式：边界讨论（待定）

**背景**：中国低年级学生的错题整理由家长代劳，家长是实际操作者。

| 年龄段 | 实际使用者 | 家长模式需求 |
|---|---|---|
| 小学（6-12 岁） | 家长为主 | 强需求：家长全权操作，可能需要管理多个孩子 |
| 初中（12-15 岁） | 学生为主，家长偶尔介入 | 中等：家长可能想看学习数据，但不代劳 |
| 高中（15-18 岁） | 学生独立使用 | 弱/无：学生自主管理 |

**可能的形态**：
- **最轻方案**：多 Profile 切换（家长帮不同孩子管理不同的题库）
- **中等方案**：家长账号 + 孩子账号关联，家长可查看统计数据
- **最重方案**：独立的家长 App / 家长视图

**决策（2026-03-07 确立，2026-03-30 提升到 v1.0）**：多 Profile（本地多题库隔离）提升为 **v1.0 必须（P1）**。
理由：旅程 5 已证明多孩家庭没有 Profile = 产品不可用（不是体验差，是不可用）。
实现参考 Obsidian 的 Vault 切换，开发成本低。v1.0 必须包含此功能以覆盖小学家长核心场景。
