## 使命

**愿天下没有难数字化存档的练习题。**

从小到大，老师都告诉我们整理错题很重要。但抄题、剪贴、分类、归档的过程枯燥、重复、低效。SnapDrill 要做的，就是把这个过程的成本降到最低：**拍一张照片，剩下的交给工具。**

---

## 核心问题

纸质习题、作业、试卷天然分散。学生和家长想记录高价值练习题，却缺少一个**简单、低成本、体验好**的数字化工具。

现有方案的三个致命缺陷：

| 缺陷 | 具体表现 |
|---|---|
| **贵** | 订阅制**高收费 + 限制核心录入**（如每天只能免费录入 10 道题）。SnapDrill 本身采用 Freemium（核心录入永久免费且不限量，Pro 层为 iCloud / 高级统计 / 智能组卷等增值；状态见 `product-requirements.md`§功能状态总表）——批评的不是付费本身，而是把核心闭环锁在付费墙后的做法 |
| **杂** | 功能冗余，偏离"记录"这个核心需求 |
| **糙** | 交互体验不够好，流程不够简洁 |

SnapDrill 的存在意义：**用最简交互、零成本核心功能和极致体验，解决"纸质练习题数字化存档"这一个问题。**

**核心价值链**：采集 → 管理 → 导出/打印。复习是可选留存层，智能组卷是导出/打印的 Pro 增值延伸（利用 SM-2 复习数据提升选题质量）。iCloud 多设备同步定位为付费核心引擎（实现状态见 `product-requirements.md`§功能状态总表；免费用户通过 .zip 手动备份实现数据迁移，详见 `product-business.md`§免费层定义）。

## 产品定位

**面向家庭教育场景的简洁、私有、原生效率工具。**

- **简洁**：功能克制，界面干净，录入路径最短——对标竞品「杂」和「糙」
- **私有**：所有数据由用户主动提供，平台不提供内容，数据归用户所有，不收集可识别个人信息
- **原生体验**：深度依赖 Apple 平台原生能力，不做跨平台妥协

**不是什么**：
- 不是 Anki 式记忆工具——SnapDrill 是存档工具，复习只是附带福利。SM-2 和智能组卷是可选功能，不应侵蚀核心采集/管理/导出路径的简洁性（**Pro/Free 划分**：基础 SM-2 复习是免费层，智能组卷是 Pro 增值；详见 `product-business.md`§免费层定义）
- 不是内容平台——不提供题库、课本、试卷，所有内容来自用户
- 不是学习打卡工具——不做连续天数、成就弹窗、排行榜
- 不是社交产品——不做分享社区、不做云端 / 社交意义上的「推荐算法」（**澄清边界**：禁的是「跨用户协同过滤 / 个性化内容推送 / 行为信号采集驱动的算法 feed」，**不禁**用户本机端上的 SM-2 选题、Smart Paper 选题策略、weakness/recency 排序——这些是**功能算法**，不是「推荐算法」）

## 目标用户

### 用户画像的真实权重（2026-03-07 确立，待发布后数据验证）

**Operating assumption**（假设，待首批用户画像验证）：小学生通常不能自由使用手机。在小学阶段，家长就是唯一用户。App 的第一批真实用户很可能不是学生，而是关心孩子学习的家长。

| 年龄段 | 实际操作者 | 用户身份 |
|---|---|---|
| 小学（6-12 岁） | **家长** | 家长是唯一用户，孩子不碰手机 |
| 初中（12-15 岁） | **学生为主**，家长偶尔辅助 | 学生开始独立使用 |
| 高中（15-18 岁） | **学生独立使用** | 家长几乎不参与 |

**设计推论**（假设，待验证）：App 默认体验以"不熟悉教育科技产品的家长"为基线——界面语气、引导文案、功能复杂度都先满足家长。这个选择基于"学生能适应更简单的界面，反之不成立"的假设，该假设同样待发布后验证。

> 注：requirements 中用户旅程的"张敏，35 岁，杭州，两个孩子的妈妈"是具体测试场景人物，不代表全局设计基线。

### 细分群体

- **家长**（小学阶段的核心用户）：帮孩子录入错题
- **多孩家庭**：同一台设备管理多个孩子的独立题库，Multi-Profile 是刚需（旅程 1 验证）
- **中学生**（初高中）：自主录入和复习
- **竞赛群体**（奥数等）：小众但高粘性，题目来源多样，需要更灵活的来源分类和快速录入
- **海外华人学生**：周末中文学校或家长自用中文教材场景，差异主要在双语 OCR 和界面语言偏好

### 市场与平台

SnapDrill 面向全球发布，中国大陆和美国为核心市场。**iOS / iPadOS 是唯一平台**，不考虑 Android 和 HarmonyOS。

## 平台策略与取舍

**iOS-only 是体验、隐私、原生能力与个人资源约束下的取舍，不是市场覆盖最大化策略。**

选择 iOS-only 的理由：
- Apple 平台提供端上 OCR、文档扫描、AI、同步等深度集成的原生能力，这些能力的组合构成了 SnapDrill 的体验基线
- 零注册 + 纯本地 + iCloud 的隐私架构在 Apple 生态内有系统级支撑
- 单人开发团队的资源约束决定了专注一个平台比跨平台更能保证质量

明确承认的代价：
- 中国大陆市场 iOS 市占率有限（约 25-30%），Android/HarmonyOS 用户无法触达
- 多设备家庭场景中，如果家庭成员的设备跨生态（妈妈用 iPhone、爸爸用安卓），无法协同
- 这不是理想状态，是当前约束下的最优选择。若未来产品验证成功且资源允许，可以重新评估

GTM 执行细节见 `product-business.md`§发布策略。

**iPad + Apple Pencil 价值定位**：
- iPad 大屏适合「整理 + 复习」场景（家长在客厅或孩子在书桌上完整翻阅题库）
- Apple Pencil 暂不深度集成（PoC 阶段），优先级低于 iPhone 录入主路径
- 未来 PoC 可能方向：在 ReviewCard 反面用 Pencil 批注 / 在 Capture 完成后用 Pencil 圈选 OCR 区域
- 当前阶段 iPad 体验通过自适应布局（compact/regular）自动兼容，不做 iPad 专属功能

## 产品原则（排序即优先级）

### 1. 录入体验是生命线

用户从打开 App 到存好一道题，步骤越少、耗时越短越好。
任何增加录入摩擦的设计都是反模式。
对复杂物理环境的鲁棒性（夜晚昏暗光线、揉皱的试卷、红蓝黑笔交错、阴影和折痕）是核心技术考量——家长的真实拍摄场景远比实验室恶劣。

**主路径必须是图片**：核心录入路径是「拍照 / 选图 / 扫描」，因为 OCR 文字是辅助、图片是真相（含公式、图形、批注）。CSV 导入存在但定位为**数据可携带权场景**（从其他工具迁移到 SnapDrill），不是主推路径，不应在 UI 上与拍照同级展示。`product-design.md` §图片存储策略 详述图片为真相的技术含义。

### 2. 简洁即正义

功能克制。宁可少做，不可做杂。
每新增一个功能前，先问：这会让"录入→管理→导出/打印"的主路径变复杂吗？

SM-2 复习和智能组卷是可选功能，不应侵蚀核心路径的简洁性。如果复习功能的复杂度开始挤压采集和管理体验，以本原则裁决。

### 3. 免费即门槛

核心功能永久免费。免费层 = 完整的单设备产品体验（完整价值链闭环，见上文§产品价值链）。
商业化时绝不限制录入数量——限制录入是竞品用户流失的主要原因之一。
付费只解锁增值体验，不锁基础能力。详见 `product-business.md`。

### 4. 数据属于用户（隐私是核心差异化）

用户的题目、图片、笔记是私有财产。
支持导出，详见 `product-requirements.md`§导出与打印能力。
不做社交、不做内容平台、不做推荐算法。
SnapDrill **默认不收集个人信息**：无需注册、不要求姓名、手机号、学校或年级。
匿名使用数据与崩溃报告——**国内版不适用**（Firebase-Free，ADR-004）；**海外版**（C 路径）仅在用户明确授权后启用，且不关联真实身份。字段与开关规格见 `product-requirements.md`§使用数据，商业定位见 `product-business.md`。

> ⚠️ **隐私表述的准确边界**：上述"不收集可识别个人信息"指不收集姓名、手机号、邮箱等直接身份信息。**国内版** Firebase-Free，无任何分析标识符（ADR-004）。**海外版**（C 路径）启用 opt-in Analytics 后，Firebase SDK 会生成 app-scoped identifier（`app_instance_id`），在 COPPA/GDPR 语境下属 persistent identifier / pseudonymous personal data，故海外版不宜使用"零 PII"的绝对化表述。详见 `../decisions/ADR-004-china-build-firebase-free.md`。

**数据安全子条款**：本地存储意味着 App 是用户数据的唯一守护者。保存必须可靠，删除可撤销，备份可用。
**iCloud 同步隐私边界**：iCloud 同步完全基于系统级 CloudKit，数据由 Apple 加密存储在用户个人 iCloud 账户中。SnapDrill 不接触、不存储、不可访问用户的 Apple ID 或 iCloud 数据。开发者无法查看任何用户的个人内容。

### 5. 家长友好（可能比"学生友好"更重要）

小学阶段家长是唯一用户（假设，待验证），App 默认体验以家长为基线：
- 界面语气成熟、不幼稚（家长不想用"儿童App"）
- 零学习曲线，打开就会用
- 不假设用户理解"间隔重复""SM-2"等概念
- 保持客观冷静，做纯粹的工具，不向家长贩卖教育焦虑

**不贩卖焦虑的具体边界**（design 层硬约束）：
- 不做连续天数打卡、不做今日额度倒计时、不做成就 / 徽章渲染
- 「每日复习目标」是被动参考数值，不主动提醒「还差 X 题」「连续 X 天未达成」等焦虑文案
- Dashboard「今日新增 N」等数字只显示事实，不附带「比昨天少了 / 完成度 X%」类比较
- Pro 模糊预览不暗示「再不订阅就看不到」类焦虑诱导，详见 `product-business.md` §防焦虑条款

**无障碍主张（accessibility 价值）**：
- 全模块 VoiceOver 是基线，不是可选优化——小学阶段家长可能照顾视障家庭成员，或祖父母代替家长操作
- 具体规格见 `tech/non-functional-requirements.md` §无障碍 + `product-requirements.md` §无障碍

### 6. 原生优先

深度依赖 Apple 平台原生能力，**优先 Apple first-party**——OCR / 文档扫描 / 同步 / 通知等核心能力必须用 Apple 原生 API（Vision / VisionKit / CloudKit / UserNotifications），不引入跨平台框架（React Native / Flutter）也不引入第三方 OCR / 第三方同步层。
**边界**：Analytics / Crashlytics 等**非核心、可降级**的可观察性能力允许使用成熟第三方 SDK（如 Firebase）——这不违反「原生优先」，因为：
- Analytics/Crashlytics 不是用户面核心体验
- 已 Protocol 隔离（`AnalyticsServiceProtocol`），替换实现只需改 Infrastructure 层——**国内版正是据此注入 `NoOpAnalyticsService`、零 Firebase（ADR-004）**；海外版（C 路径）才启用 Firebase
- 启用时默认 opt-out（vision §4 隐私优先）

Apple 原生能力（Vision OCR、CloudKit、TipKit、文档扫描）是体验基线而非独占壁垒——任何 iOS 竞品也能使用这些 API。
SnapDrill 真正的差异化在于：题目工作流设计 + 离线隐私架构 + 免费完整闭环 + 原生体验组合。

### 原则冲突裁决

当原则冲突时，按编号优先级裁决（1 > 2 > 3 > 4 > 5 > 6）。
额外约束：任何降低免费层现有能力的决策，必须经产品负责人显式批准。

| Multi-Profile 可用性 | 跨 Profile 数据泄漏事件 = 0 | 定性验证（用户测试）+ 自动化：跨 Profile 数据泄漏作为 S0 级 Bug | 已实现，持续监控 |
| 成果分发 | 家长能导出或分享孩子的整理成果（通过系统分享菜单，非社交功能） | 系统分享 sheet 触发（非 Analytics 事件，依赖 iOS UIActivityViewController 路径） | 待发布后测定 |
| 价值链完成率 | 完成"管理 → 导出/打印"闭环 | Analytics 事件：`pdf_exported` 至少 1 次的用户占 D30 活跃用户比例（系统打印为非事件源） | 待发布后测定 |

## 待验证的关键假设

以下假设在发布前不作为事实，发布后 90 天内逐条复核。复核标准：有 Analytics/App Store Connect/用户访谈数据支持则升级为事实；数据推翻则修正或撤销。

| # | 假设 | 复核方式 | 推翻信号 |
|---|---|---|---|
| H1 | 不熟悉教育科技产品的家长能在首次使用中独立完成录入 | 首次录入成功率 + TestFlight 反馈 | 完成率 < 50% 或反馈"不知道怎么用"占比高 |
| H2 | 小学阶段的主要操作者是家长，不是孩子 | Analytics 年龄/行为数据 + 用户访谈 | 独立使用的 12-15 岁用户占比远超预期 |

| H3 | 用户的核心需求是"存档并打印/导出"，不是搜题、讲题 | 功能使用分布 + 用户反馈 | 导出/打印使用率极低，用户频繁要求题库/解题 |
| H4 | 免费不限量录入能显著降低试用门槛并形成口碑 | App Store 转化率 + 用户来源 | 下载量不达预期，或用户反馈"不需要无限" |
| H5 | 用户愿意接受 iOS-only，目标市场足以支撑早期增长 | App Store Connect 地区下载分布 | iOS 市占率限制导致下载量不足 |
| H6 | 零注册、纯本地、隐私承诺能成为真实留存理由 | 用户访谈 + 竞品对比反馈 | 用户因"缺少同步/多端"而流失，且不关心隐私 |
| H7 | iCloud 同步足以成为 Pro 核心付费理由 | Trial 转化率 + 付费用户调研 | 付费率远低于预期，用户反馈"手动备份够用" |
| H8 | 智能组卷和图片处理增强能补强 Pro 转化，不破坏简洁主路径 | Pro 功能使用率 + 用户反馈 | Pro 功能使用率极低，或用户反馈"变复杂了" |
| H9 | SM-2 复习能提升留存或组卷质量，但不把产品拖向 Anki 式复杂度 | 复习功能使用率 + 功能蔓延检测 | 复习功能占据开发/设计资源超过采集和管理 |
| H10 | 用户翻拍教材/试卷的版权风险可控 | 法律顾问评估 + 实际投诉 | 收到版权方投诉或 App Store 审核质疑 |

## 已知风险与张力

### 免费完整 vs Pro 转化

免费层越完整，付费转化越依赖 iCloud/组卷/图片增强的真实价值。如果免费用户发现手动备份 + 单设备足够满足需求，Pro 转化率会极低。发布后前 3 个月验证此张力。

### 纯本地 vs 增长

不做社交、不做内容、不做打卡、不做推荐，意味着没有网络效应驱动的增长引擎。增长完全依赖 App Store ASO + 口碑。需验证"零摩擦工具"本身是否能驱动足够的自然传播。

### 隐私 vs 数据驱动

**（海外版）** Analytics 默认 opt-in，意味着行为数据只覆盖愿意授权的用户子集；如果 opt-in 率过低（< 10%），成功信号将严重偏向早期 adopters，可能误判产品方向。**国内版** Firebase-Free、零采集，无此偏差，但也因此完全依赖 App Store Connect / 访谈 / TestFlight 信号（ADR-004）。

### iCloud 变现的承载能力

iCloud 同步作为 Pro 核心引擎，受限于：用户已有 iCloud 空间（5GB 免费易击穿）、中国区 CloudKit 性能、用户可能只用单设备不需要同步。如果 iCloud 不足以支撑付费转化，需要准备替代或补充的变现路径（如高级导出格式、批量打印排版、专业 OCR 增强等）。

## 版权合规边界

SnapDrill 不提供题库、教材、试卷或任何第三方内容。所有题目由用户主动录入，存储在本地，App 不公开分发用户内容。

用户翻拍教材、试卷、教辅等受版权保护的材料是个人使用行为，SnapDrill 作为工具提供方：
- 不鼓励、不引导用户翻拍受版权保护的内容
- 不提供"题库分享"或"公开上传"功能
- 导出功能面向个人使用场景（打印练习、换机迁移），不面向公开传播

如果收到版权方投诉或 App Store 审核质疑，以"纯本地工具 + 用户自有内容 + 不公开分发"为边界回应。若未来引入社区或分享功能，需重新评估版权风险。
