# SnapDrill 用户旅程

> **上游依赖**：`vision.md`（使命、产品原则）、`positioning-and-audience.md`（通用受众定位）。
>
> 本文件用“处理结构化纸张 / PDF 的成年人”这一首个切口，验证产品是否支撑采集、整理 / 找回、导出 / 打印。
> 用户是管理自己资料的成年人；产品也服务成年人整理家庭资料，但不建立儿童独立账户、儿童模式或儿童专属体验。
>
> 旅程内容变更由开发者维护；新增旅程或修改验证结论需产品负责人确认。

---

## 旅程 1：首次采集与保存（first capture）

**人物**：方哲，自由职业设计师，第一次打开 SnapDrill。
**触发**：桌上有一份纸质参考资料，他想验证「拍一张就能存下来」。

**步骤**：

1. **首次打开**。系统准备一个本地资料库，不要求注册、不要求填身份信息、不要求先配置字段。Onboarding 只用几页说明：这是一个把纸张、照片和 PDF 变成可搜索、可整理、可打印资料的效率工具。
2. **进入采集**。普通启动进入 Dashboard，并从 Dashboard 一次操作进入 Capture；deep link 与阻塞性 store 恢复可以覆盖默认目的地。
3. **拍第一项**。举起手机拍照，自动框选基本正确，他微调边缘后确认。
4. **OCR 展示结果**。识别出文字，界面不强迫他逐字校对，也不堆一屏字段。
5. **直接保存**。点保存，得到成功反馈，内容已入库。从进入采集页到保存完成控制在 30 秒内（不含 Onboarding）。
6. **轻量引导下一步**。保存后可提示进入资料库查看或继续采集，不要求先配置更多字段。

**结束状态**：本地资料库已可用，第一项内容完成录入，用户确认这是一个零学习成本就能开始的工具。

**关键设计验证**：
- 首次启动不索取额外信息，零注册不挡门外
- Onboarding 只解释价值、不要求配置
- 默认字段极少，首次即可完成录入
- 进入采集页到保存成功 < 30 秒，符合愿景成功信号

## 旅程 2：长期考试/题目归档（long exam/problem archive）

**人物**：陈澜，在职备考研究生入学考试的成年人，已积累一段时间。
**触发**：做完一套模拟卷，要把需要回看的几道题归档，并把老师在群里发的练习图也存进来。

**步骤**：

1. **连续拍照录入**。试卷铺在桌上，对准第一道需要回看的题拍照、裁剪、OCR、保存；保存后自动回到摄像头，连续录入下一道，无需每次重新进入采集。
2. **一图多题裁剪**。群里转发的一张图含 4 道题，她从相册导入后框住第 1 道保存，同一张图再次出现，继续框住第 3 道保存——一张图连续裁剪多题，零重复选图。
3. **PDF 导入**。教辅 PDF 共 8 页，她选中含重点题的几页，逐页裁剪录入；用户确认裁剪与方向后的 App-managed 图片保持可读，公式与图形不依赖 OCR 才能找回。
4. **基础元数据按需确认**。通用分类默认可见但可跳过，标签作为次级入口；每条资料由用户明确选择，不自动沿用上一条的值。来源 / 级别只有用户在设置中开启后才出现。

**结束状态**：资料库持续增长，每条记录保留用户确认后的 App-managed 可读图片与可检索 OCR 文本，元数据一致。

**关键设计验证**：
- 采集入口一步可达，保存后连续录入无摩擦
- 一图多题、PDF 多页选择不重复操作
- 用户确认后的 App-managed 可读图片是内容真相，OCR 不完美不阻塞保存；不承诺来源原始字节或完整分辨率
- 基础分类 / 标签入口不依赖预先配置，未选择元数据仍可保存；来源 / 级别不构成 Must 前置

## 旅程 3：职业证书/培训资料整理（professional certification / training material）

**人物**：林越，职场人士，正在备考一门职业证书（如 PMP / CPA）。
**触发**：培训机构发来一批讲义与真题 PDF，他想按基础分类 / 标签归档，便于冲刺阶段按主题调取。

**步骤**：

1. **PDF 导入 + 逐页选择**。从文件 App 打开培训讲义 PDF，逐页预览，选中要归档的页。
2. **裁剪录入 + 基础分类**。裁剪某道真题，选择已有的基础分类后保存。
3. **打标签**。给重点资料加标签「高频」「重点」，便于后续按主题过滤。
4. **混合内容 OCR**。讲义含中英文术语，OCR 同时识别；个别符号识别不准时手动修正关键术语，其余以 App-managed 可读图片兜底。

**结束状态**：证书备考资料按基础分类 / 标签结构化归档，可在冲刺阶段按主题快速调取。

**关键设计验证**：
- PDF 导入支持多页选择，覆盖培训资料场景
- 基础分类 / 标签满足专业整理需求
- 中英文混合 OCR 可用，修正只需补对自己有价值的关键词
- 工作流对试卷 / 题目保持专业锐度，但不绑定任何特定人群

## 旅程 4：单资料库内整理多个主题（organize multiple topics in one library）

**人物**：苏宁，同时整理两门考试资料，也偶尔保存一份家庭资料。
**触发**：她希望快速区分不同主题，但不想先理解或维护 Workspace / Profile。

**步骤**：

1. **按主题归类**。她在同一个资料库中使用基础分类和标签区分两门考试与家庭资料。
2. **组合过滤**。需要专注某一主题时，使用过滤和搜索收窄结果；退出过滤即可回到全部资料。
3. **继续整理**。新导入一组资料后按主题添加标签，不创建或切换顶层资料空间。
4. **统一找回与备份**。搜索覆盖整个资料库，手动备份一次即可带走全部资料。

**结束状态**：多类资料在一个资料库中可区分、可找回、可整体备份，用户无需理解额外身份或工作区模型。

**关键设计验证**：
- 用户只看到一个资料库，不出现 Profile / Workspace 管理负担
- 分类、标签、过滤和搜索足以处理首批多主题需求
- 全局操作的范围清晰，不因隐藏资料空间遗漏导出或备份
- 若真实用户反复需要强隔离且现有整理方式无法解决，按 `assumptions.md` H12 重新 shaping

## 旅程 5：搜索 / 过滤 / 编辑（search / filter / edit）

**人物**：陈澜（同旅程 2），距考试两周，已积累 80+ 条记录，想按主题整理重点。
**触发**：想按分类和薄弱点把重要题目挑出来，考前重点看。

**步骤**：

1. **进入资料库**。默认按录入时间倒序，看到全部记录。
2. **组合过滤**。按分类过滤缩减列表，再叠加标签「几何」与「考前重点」，缩小到一组需要集中整理的资料。
3. **查看与编辑**。打开一条资料查看 App-managed 主图、OCR 文字与元数据；发现缺答案，点编辑补上解题思路与一张手写过程照片，保存。
4. **改分类与标签**。把另一条资料改为「重点」分类并添加「考前」标签。
5. **搜索**。记得某题含「抛物线」，搜索框输入关键词，命中 OCR 识别过的文字。
6. **误删与撤销**。整理中误删一道题，底部 Toast「已删除，5 秒内可撤销」，点撤销立即恢复。

**结束状态**：约 20 分钟完成整理——补答案、调整基础分类与标签、按需检索。

**关键设计验证**：
- 过滤支持基础分类 + 标签组合
- 搜索基于 OCR 文字
- 编辑完整：补答案（文字 + 图片）、改基础分类、加标签
- 软删除 + 5 秒撤销兜底误删，不做回收站

## 旅程 6：导出 / 打印（export / print）

**人物**：林越（同旅程 3），冲刺阶段，想把一组题打印成纸质练习。
**触发**：把「高频」标签的题目过滤出来，导出成可打印资料。

**步骤**：

1. **过滤结果集**。在资料库按标签 / 分类过滤形成结果集。
2. **PDF 导出 + 预览**。发起基础多选 PDF 导出，进入系统预览，确认所选每条资料恰好出现一次且内容可读。
3. **打印**。确认后生成 PDF，通过系统打印（AirPrint）输出纸质资料；也可分享 / 保存 PDF。

**结束状态**：导出一份资料 PDF 并完成系统打印；原始数据不被导出修改。

**关键设计验证**：
- 过滤 → 导出 PDF → 打印路径通畅，打印是价值链一等终点
- 去答案、留白、页眉页码和单条快速打印属于 Candidate optional，默认隐藏，不是本 Must 旅程前置条件
- 导出 / 打印是只读操作，范围与当前过滤结果一致
- 导出不嵌水印 / 广告 / 公开传播引导

## 旅程 7：备份 / 恢复（backup / restore）

**人物**：方哲（同旅程 1），换新 iPhone。
**触发**：旧手机换新，他希望资料库完整迁移，且不依赖账号、IAP 或云同步。

**步骤**：

1. **旧设备手动备份**。在设置页导出一个正式完整备份（打包资料、图片、元数据和相关本地状态），通过系统分享面板保存到文件 App 或用户选择的位置。
2. **新设备安装并恢复**。新机设置中提供恢复入口；选中备份后系统先校验文件完整性与版本兼容性。
3. **执行恢复**。校验通过后恢复单一资料库的资料、标签、相关状态与图片，不依赖账号登录或云同步。
4. **异常透明兜底**。任何必需图片或 metadata 缺失、损坏、非法或不一致时，整包拒绝且新机现有资料库不变；损坏 store 的部分 salvage 只能走单独、明确标识的恢复路径。

**结束状态**：用户完成换机迁移，数据可带走、不被平台或付费层绑定。

**关键设计验证**：
- 免费用户有永久、可执行的数据迁移路径，正式备份是完整恢复入口而非象征性导出
- 恢复前先校验，失败时不破坏现有数据
- 正式完整备份 all-or-nothing；部分 salvage 不得伪装成完整恢复
- 备份覆盖整个单一资料库，不因隐藏空间或账户状态遗漏内容
