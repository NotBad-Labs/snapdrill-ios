# 待验证假设登记

> 假设不是产品原则，也不是事实。每条假设必须可证伪；被推翻时修改产品策略或功能，而不是修改证据。

## 复核原则

- 当前没有后端行为采集，不使用年龄画像或逐事件用户追踪验证假设。
- 优先使用 PO dogfood、TestFlight 定性反馈、支持请求、App Store Connect 聚合数据和明确的可用性测试。
- 样本不足时标记“未验证”，不把缺少反例当成验证通过。

## 产品假设

| # | 假设 | 复核方式 | 推翻信号 |
|---|---|---|---|
| H1 | 不熟悉专业扫描或归档工具的成年人能在首次使用中完成一次采集与保存 | 任务式可用性测试、TestFlight 反馈 | 多数参与者无法在无指导下完成，或主要障碍集中在同一步 |
| H2 | 用户需要的不只是扫描图片，还需要搜索、分类、标签和编辑形成可管理资料库 | dogfood、用户访谈、功能反馈 | 用户持续把 SnapDrill 当一次性扫描器，管理能力几乎不被使用 |
| H3 | 导出和打印是资料归档后的高价值终点 | 导出/打印任务测试、支持请求 | 用户完成采集后几乎没有输出需求，且更需要其他下游流程 |
| H9 | 可选回顾能提升资料复用价值，但不应把产品拖向复杂记忆工具 | 回顾可用性测试、资源投入复盘 | 回顾长期无人使用，或其复杂度持续挤压核心价值链 |
| H10 | 用户仅保存其有权处理的个人资料，产品的版权提示与工具边界足以控制风险 | 法律复核、审核反馈、投诉记录 | 收到版权投诉、平台质疑或出现明显的内容分发用途 |
| H11 | “处理结构化纸张 / PDF 的成年人”足以形成清晰的首个工作流切口，同时不需要把公开定位缩窄为考试或教育 App | 任务式可用性测试、TestFlight 定性反馈、App Store 搜索与转化聚合信号 | 用户无法理解产品用途，或高价值反馈持续集中在与结构化纸张 / PDF 无关的另一类工作流 |
| H12 | 一个可见资料库足以满足首批用户，不需要 Workspace / Profile 模型 | TestFlight 反馈、支持请求、任务观察 | 多名独立用户反复要求隔离资料集合，且标签、过滤或其他低复杂度方式无法解决 |
