## 复核口径

以下假设在发布前不作为事实，发布后 90 天内逐条复核。复核标准：有 Analytics / App Store Connect / 用户访谈数据支持则升级为事实；数据推翻则修正或撤销。

## 待验证假设（产品侧）

| # | 假设 | 复核方式 | 推翻信号 |
|---|---|---|---|
| H1 | 不熟悉教育科技产品的家长能在首次使用中独立完成录入 | 首次录入成功率 + TestFlight 反馈 | 完成率 < 50% 或反馈"不知道怎么用"占比高 |
| H2 | 小学阶段的主要操作者是家长，不是孩子 | Analytics 年龄/行为数据 + 用户访谈 | 独立使用的 12-15 岁用户占比远超预期 |
| H2-SM2 | 即使 H2 成立，**SM-2 翻卡的「记得/不记得」主观评估必须由孩子完成**（家长无法凭空判断孩子记忆状态）。复习功能在小学 Profile 下定位为「家长打开 → 交给孩子操作 → 孩子自评」的协作流程，UI 必须支持低龄儿童独立操作（大字体 + 清晰按钮）。Design 侧负责保证翻卡 UI 在小学 Profile 下可独立使用（见 [feat-review.md](../features/active/feat-review.md)） | 复习功能在小学 Profile 下的实际使用率 + 用户访谈 | 家长报告「孩子不会用复习」或复习功能在小学 Profile 下空置率 >80% |
| H3 | 用户的核心需求是"存档并打印/导出"，不是搜题、讲题 | 功能使用分布 + 用户反馈 | 导出/打印使用率极低，用户频繁要求题库/解题 |
| H9 | SM-2 复习能提升留存或组卷质量，但不把产品拖向 Anki 式复杂度 | 复习功能使用率 + 功能蔓延检测 | 复习功能占据开发/设计资源超过采集和管理 |
| H10 | 用户翻拍教材/试卷的版权风险可控 | 法律顾问评估 + 实际投诉 | 收到版权方投诉或 App Store 审核质疑 |
