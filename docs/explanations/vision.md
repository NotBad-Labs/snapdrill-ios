# SnapDrill Product Constitution v1（产品宪章）

> 本文件是 SnapDrill 第一层产品 SSOT，也是仓库内当前产品意图的最高权威。它在分支或 PR 中只是已批准候选，合入 `develop` 后才成为 effective baseline。
>
> 第二层是一个有界、带日期的 Release Product Contract；第三层是各 feature spec。代码、测试、构建与真机证据只证明当前实现，不能反向改写这三层规范。

PO 于 2026-07-12 逐项批准 Gate B 的 B1-A 至 B7-A。下表是审阅索引，具体约束由后续同名章节承担：

## 使命

**以最低摩擦，把纸张、照片和 PDF 变成可搜索、可整理、可打印的个人资料库。**

纸张、图片、PDF 和聊天附件天然分散。SnapDrill 不提供平台内容，而是帮助用户忠实采集自己的材料，在需要时快速找回、整理、导出和打印。

## 首个工作流切口

当前首个切口是：**处理结构化纸张或 PDF 材料的成年人，需要完成采集、整理、稍后找回和打印。**

- 考试、职业认证、培训和成年人管理的家庭资料都是实例，不是唯一允许的内容。
- 这是中等置信度的学习假设。当前没有外部用户、获客或付费证据，不得写成已经验证的市场事实。
- “通用受众”仍是公开定位与合规姿态；首个切口只为默认工作流、示例和产品学习提供焦点。
- 新的外部证据可以触发重新 shaping，但在新裁决 effective 前，本切口持续有效。

## 产品定位

SnapDrill 是面向通用受众的原生成人效率工具，扫描、归档和整理用户自己的资料与文档。

- 试卷、题目和学习资料是产品擅长处理的内容类型，但产品不对外呈现为儿童教育 App。
- 产品服务成年人管理自己的资料，也可服务成年人整理家庭资料；不建立儿童独立账户、儿童模式或儿童专属体验。
- 产品不是题库、搜题、解题、内容社区或内容分发平台。
- 产品不以社交、游戏化、焦虑文案或增长机制代替真实工具价值。

具体受众信号与合规 guardrail 见 [positioning-and-audience.md](positioning-and-audience.md)。

## 核心价值链

```text
采集 -> 整理 / 找回 -> 导出 / 打印
```

- **采集**：从用户已有的纸张、照片、PDF 或系统入口获得忠实材料。
- **整理 / 找回**：让资料可搜索、可编辑、可分类，并在需要时快速出现。
- **导出 / 打印**：让资料离开 App，进入纸张、文件或用户选择的其他工作流。
- **回顾与 SmartPaper**：可以提供附加复用价值，但不得占据、阻塞或复杂化主路径。

具体输入渠道、字段、输出格式和附加功能是否属于某次发布，由 Release Contract 和 feature spec 决定，不能从当前代码数量反推。

## 数据与身份定位

1. **Local-first**：无需 SnapDrill 账户即可完成核心价值链，用户内容默认保存在设备本地。
2. **一个资料库**：用户只看到一个资料库。没有外部证据前，不规划 Workspace / Profile 产品模型。
3. **永久可携带备份**：手动备份与恢复是长期数据所有权承诺，不得成为付费门槛。
4. **无开发者内容云**：默认不建立开发者可访问的内容后端，不上传用户内容或逐事件行为数据。
5. **同步另行验证**：未来可选的 Apple 私有同步只是独立假设；启用前必须重新通过产品、隐私、数据兼容和商业 contract。

“一个资料库”不是对未来的永久技术禁令。只有外部证据支持、PO 重新 ratify 且新权威合入 `develop` 后，Workspace / Profile 才能回归。工程内部是否暂存某个抽象，不得改变用户可见产品行为。

## 商业定位

- Release 1 免费、无广告、无 IAP。
- 当前没有有效的 Pro 层、价格、试用期、付费配额、CloudKit 或 Word 商业承诺；不可用的购买、升级和“即将推出 Pro”界面必须隐藏。
- 核心价值链不得靠限制录入数量、锁定用户资料、阻断手动备份或添加水印来变现。
- Pro、Apple 私有同步、Word 和其他高级输出可以保留为候选假设，但需要外部价值证据、新的商业裁决、StoreKit / 隐私 contract 和独立 Release Contract 才能生效。

现行商业政策与候选假设见 [business-model.md](business-model.md)。历史 Hybrid 配额和订阅定价不得作为当前产品依据。

## 平台与区域

- Release 1 shipping target 为 iPhone-only。
- 当前生产主体为美国 NotBad Labs L.L.C.，维护一个全球发行版。
- Release 1 产品语言为英文与简体中文。
- iPad 与中国大陆专项发行路线均已退出当前范围；任何恢复都必须重新立项，补齐产品、UI、测试、签名、元数据、隐私和发布证据。
- 已挂起的账号、Bundle、App Group 或其他资源可以保留作为可逆资产，但不构成当前承诺。

生产 Team、Bundle、签名和已验证构建属于实证事实，以根 `AGENTS.md`、代码和发布证据为准。

## 耐久非目标

- 不提供平台题库、答案搜索、自动解题或内容分发服务。
- 不建立社交关系、排行榜、连续签到、虚拟奖励或焦虑驱动的增长系统。
- 不要求 SnapDrill 账户才能使用核心价值链。
- 不建立开发者可访问的用户内容后端，也不恢复第三方行为分析作为默认能力。
- 不以当前实现、历史 ADR、候选 roadmap 或 Draft PR 反向定义产品。

## 产品原则

原则按编号排序；发生冲突时，较小编号优先。

### P1. 采集摩擦最低

从看到材料到完成保存，步骤越少、等待越短越好。图片是内容真相，OCR 是可搜索、可编辑的辅助表达。复杂光线、折痕、批注和长文档属于真实输入，不是异常用例。

### P2. 简洁优于功能堆叠

每个新增功能都必须证明它不会让核心价值链更难理解或更难完成。附加能力可以存在，但不能抢占采集、整理、找回、导出和打印的注意力。

### P3. 免费层完成核心闭环

免费用户必须能在单设备上完整完成核心价值链。未来付费能力只能增加独立增值，不限制基础录入，不把用户自己的资料锁在付费墙后。

### P4. 用户拥有数据

用户内容属于用户。产品必须支持查看、编辑、删除、导出和备份；保存可靠、删除可恢复、迁移可执行。任何未来同步或商业化都不能撤销这些权利。

### P5. 冷静、清晰、成人生产力工具

界面和文案成熟、中性、无低龄化信号。产品呈现事实，不评价用户，不贩卖焦虑，不假设用户理解专业术语。无障碍是基础质量，不是附加优化。

### P6. Apple 原生优先

在已批准的平台范围内优先采用 Apple 平台能力和交互惯例。第三方依赖必须解决明确问题，不能削弱隐私、可维护性或依赖边界。

## 耐久取舍

1. **主干优于附加完整性**：先保证采集、整理 / 找回、导出和打印，再决定回顾、统计或智能增强。
2. **忠实归档优于替用户判断**：自动化只预填可确认的信息，不替用户作能力判断。
3. **中性事实优于转化压力**：不使用焦虑、倒计时、连续记录或损失暗示推动使用或付费。
4. **打印是一等终点**：打印不是分享菜单中的偶然副作用，而是核心价值链的正式出口。
5. **朴素分享优于增长机制**：分享用于交付资料，不做水印、裂变任务或社交关系链。
6. **信任优于省事**：自动化不确定时留白；任何自动结果必须可见、可改、可撤销。

## 三层 SSOT 与变更生命周期

```text
exploration
  -> shaped candidate
  -> PO ratified
  -> 归属权威合入 develop（effective）
  -> superseded

Product Constitution
  -> Release Product Contract
  -> Feature Spec
  -> 验收标准
  -> 代码与测试
```

1. Product Constitution 只定义耐久产品身份、原则和跨功能边界。
2. Release Contract 定义一次发布的目标产物、Must outcomes、明确非目标和结果级验收。
3. Feature spec 定义单功能的可观察行为，不得创造上游产品不变量。
4. 下游规范必须引用上游依据；找不到依据的需求是孤儿需求。
5. 分支、PR、聊天、当前代码和测试都不能自行使产品裁决生效。
6. 跨 feature、数据 / wire、公开承诺、商业或平台边界的变更，合并前必须先有 effective 的上游产品或 release contract。
7. 旧 tracked 规范持续有效，直到新权威明确 supersede；历史材料保留指针但不能驱动新工作。
