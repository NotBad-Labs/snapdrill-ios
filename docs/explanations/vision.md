# SnapDrill 产品愿景

> 本文件是 PO 当前产品意图在仓库中的最高层持久化表达。PO 的最新明确意图始终高于本文；本文不是 PO 的上级，也不能替代 PO 对新产品问题的裁决。
>
> 本文件只保存耐久的使命、定位、价值链和产品原则。实现状态、市场数字、阶段任务、具体功能设计与待验证假设必须下沉到对应文档。

## 使命

**让任何题目与文档都能以最低摩擦完成扫描、归档、整理与复用。**

纸张、图片、PDF 和聊天附件天然分散。用户真正需要的不是另一个内容平台，而是一个可靠、安静、随手可用的工具，把有价值的材料变成可检索、可整理、可导出、可打印的个人资料库。

## 产品定位

SnapDrill 是一款面向通用受众的原生效率工具，扫描、归档、整理任何题目与文档。

- 产品对试卷、题目和学习资料工作流保持专业锐度，但不对外呈现为儿童教育 App。
- 产品服务成年人管理自己的资料，也服务成年人整理家庭资料；不建立儿童独立账户、儿童模式或儿童专属体验。
- 产品不是题库、搜题、解题或内容社区，不提供平台内容，也不以社交传播为核心。
- 产品不通过签到、积分、勋章、排行榜、虚拟奖励或焦虑文案制造使用压力。

具体受众信号与合规 guardrail 见 [positioning-and-audience.md](positioning-and-audience.md)。

## 核心价值链

```text
采集 -> 管理 -> 导出 / 打印
```

- **采集**：从相机、相册、PDF、剪贴板或系统分享入口获取内容。
- **管理**：搜索、分类、标签、编辑和组织个人资料。
- **导出 / 打印**：让资料离开 App，进入纸张、文件或其他工作流。
- **回顾**：可选附加价值，不得侵蚀核心价值链的简洁性。

功能状态以代码、构建实证和自动生成的 [feature-status.md](../reference/feature-status.md) 为准，不写入 Vision。

## 产品原则

原则按编号排序；发生冲突时，较小编号优先。

### P1. 采集摩擦最低

从看到材料到完成保存，步骤越少、等待越短越好。图片是内容真相，OCR 是可搜索、可编辑的辅助表达。复杂光线、折痕、批注和长文档属于真实输入，不是异常用例。

### P2. 简洁优于功能堆叠

每个新增功能都必须证明它不会让核心价值链更难理解或更难完成。附加能力可以存在，但不能抢占采集、管理、导出和打印的注意力。

### P3. 免费层完成核心闭环

免费用户必须能在单设备上完整完成采集、管理、导出和打印。付费解锁跨设备、智能增强或高级输出，不限制基础录入数量，不把用户自己的资料锁在付费墙后。

### P4. 用户拥有数据

用户内容属于用户。产品必须支持查看、编辑、删除、导出和备份；保存可靠、删除可恢复、迁移可执行。默认不建立开发者可访问的内容云，不上传用户内容或逐事件行为数据。

### P5. 冷静、清晰、成人生产力工具

界面和文案成熟、中性、无低龄化信号。产品呈现事实，不评价用户，不贩卖焦虑，不假设用户理解专业术语。无障碍是基础质量，不是附加优化。

### P6. Apple 原生优先

优先采用 Apple 平台能力和交互惯例，保持 iPhone 与 iPad 的原生体验。第三方依赖必须解决明确问题，不能削弱隐私、可维护性或依赖边界。

## 耐久取舍

以下取舍用于具体冲突裁决，不代表新的功能承诺：

1. **主干优于附加完整性**：先保证采集、管理、导出和打印，再完善回顾、统计或智能增强。
2. **忠实归档优于替用户判断**：工具保存和组织用户材料；自动化只预填可确认的客观信息，不替用户作能力判断。
3. **中性事实优于转化压力**：不使用焦虑、倒计时、连续记录或损失暗示推动订阅。
4. **打印是一等终点**：打印不是分享菜单中的偶然副作用，而是核心价值链的正式出口。
5. **朴素分享优于增长机制**：分享用于交付资料，不做水印、裂变任务或社交关系链。
6. **信任优于省事**：自动化不确定时留白；任何自动结果必须可见、可改、可撤销。

## 意图派生规则

```text
PO 最新明确意图
  -> Vision
  -> 产品政策 / 设计原则 / 商业模型 / ADR
  -> Feature Spec
  -> 验收标准
  -> 代码与测试
```

1. 下游规范必须说明承接了哪条上游意图。
2. 找不到上游依据的需求是孤儿需求，不应直接实现。
3. 代码和测试证明当前实现，不能反向覆盖产品意图。
4. 实现与规范冲突时，记录为偏差并修复，或提交 PO 重新裁决。
5. 私有记忆、历史研究、旧 pitch 和关闭任务只用于追溯，不参与当前产品裁决。
