# 个人开发者友好的CI配置说明

## 🎯 当前CI策略：学习优先

作为个人开发者和初学者，当前CI配置采用**宽松策略**，优先帮助您快速发现问题和学习。

### 📋 工作流触发范围

#### 1. **主CI流程** (`ci-selfhosted.yml`)

- ✅ **触发分支**: `develop`, `release/**`, `feature/**`
- ✅ **触发时机**: 每次push + PR
- ⚠️ **忽略内容**: 只忽略markdown文档
- 🎯 **目的**: 让您在任何代码变更时都能及时发现问题

#### 2. **文档检查** (`link-check.yml` + `markdownlint.yml`)

- ✅ **触发分支**: `main`, `develop`, `release/**`, `feature/**`
- ✅ **检查内容**: 所有文档链接和格式
- 🎯 **目的**: 保持文档质量，养成良好习惯

### 🚀 学习优势

1. **即时反馈**: feature分支也会触发CI，快速发现编译问题
2. **全面检查**: 除了文档，所有代码变更都会验证
3. **错误学习**: 通过CI失败学习Swift最佳实践
4. **质量养成**: 从一开始就建立代码质量意识

### 📊 资源使用预估

**自托管Mac mini M4 (16GB)**:

- **轻度使用** (每天5-10次push): 完全够用
- **中度使用** (每天10-20次push): 依然流畅
- **重度使用** (每天20+次push): 可能需要调整

### 🔧 灵活调整

如果发现CI运行过于频繁，可以随时：

1. **临时跳过**: 在commit message中加入 `[skip ci]`
2. **分支策略**: 将某些实验性分支排除在外
3. **路径忽略**: 针对特定文件类型跳过检查

### 💡 初学者建议

- **享受绿色勾号**: CI通过时的成就感是学习动力
- **分析失败原因**: 每次CI失败都是学习机会
- **逐步严格化**: 随着经验增长，可以逐步调整策略
- **监控资源**: 关注Mac mini的CPU和内存使用情况

---

记住：**学习阶段，宽松的CI比严格的CI更有价值**！ 🎓
