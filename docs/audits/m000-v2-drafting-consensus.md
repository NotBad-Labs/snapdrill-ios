## 分歧项 (帅哥 N2 裁决)

### V1: layer 枚举 — 3 类还是 4 类?

| 阵营 A (3 类) | 阵营 B (4 类,Codex 独家) |
|---|---|
| Claude / DS / GM | Codex |
| `principle` / `decision` / `archive` | `root_rule` / `operating_rule` / `state_record` / `archive_record` |
| 简单,容易迁移 | 更精细,区分「最高规则」vs「可复用规则」 |

**我的判断**: Codex 的 4 类更精确(root_rule vs operating_rule 的区分实际有用,M-000 是 root_rule,M-001~M-006 是 operating_rule),但**迁移成本高**(下游脚本要改)。**推荐 A 3 类**,operating_rule 概念可在 M-001~M-006 起草时再考虑。

### V2: 主文档字数 — 2900/3000/3500/4611 之间挑

Codex 4611 nwc 最深但接近 v1.2 的 2 倍,可能违反 §5 字数预算精神(虽然 override_rationale 充分)。建议折中:**目标 ~3000-3500 nwc**,既能落实 R1-R7 又不无限膨胀。

### V3: 双核同意默认通过 — 是否在 v2.0 显式定义适用域?

| 阵营 A (定义) | 阵营 B (沉到 M-002) |
|---|---|
| DS §4.1 / GM §4.3 / Codex §6 (隐含) | Claude (沉到 M-002) |
| 双核同意 + 任一不可用即失效 | M-000 只说默认多方异源,适用域归 M-002 |

**我的判断**: M-000 应承载「双核默认通过权失效条件」(任一方不可用 / 异源辅助方强反对),具体适用域(哪些任务可双核通过)沉 M-002。**推荐 A 定义底线 + B 沉具体清单**(混合)。

### V4: 用户长期不可达降级 — M-000 还是 M-004?

GM §4.4 + Codex §12 写在 v2.0 / Claude+DS 沉 M-004。

**推荐**: 写一句兜底原则在 M-000(「用户长期不可达时只可执行可逆/局部/低外部副作用动作」),细则沉 M-004。
