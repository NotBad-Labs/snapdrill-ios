# M-000 第一性原理审计 — Codex

## 总评 (≤ 200 字)

本轮审计 12 项：PRIMARY 4、INHERITED 2、ANALOGY 5、UNDETERMINED 1。M-000 最强部分是“独立趋同”和“用户最高裁决”；最脆弱部分是把宪法、ADR、layer taxonomy、字数预算等外部治理形式搬入系统后，部分机制尚未回推到可观察退化。

## 待审项明细

### [I001] “任何任务默认多方协作”

- 范围: Layer 1 / Layer 4
- 路径: `docs/meta/M-000-meta-vision.md` §2、§3
- **目的**: 降低单一智能体稳定复现错误、训练偏差、上下文污染导致的误判风险。
- **机制**: 把多方协作设为默认，使差异化判断在任务入口就出现，而不是等到事故后补救。
- **替代**: 更朴素的方式是按风险触发：不可逆、跨文档、用户承诺、外部事实、模型能力边界不明时强制多方；低风险机械任务默认单方。
- **来源**: “独立趋同优于单点复现”接近第一性；但“任何任务默认”更像从安全工程的 fail-safe 默认值类比而来，并未证明所有任务的边际收益大于 token/时间/注意力成本。
- **破坏测试**: 删除后，高风险判断会回到单点偏差；但若改成风险触发，低风险任务不一定退化，反而可能减少治理疲劳。
- **Verdict**: ANALOGY
- **改造建议**: 重写。保留“高风险默认多方”的第一性内核，把“任何任务”改成可被 M-001/M-005 归纳出的风险触发默认；用户仍可显式升级任意任务为多方。

### [I002] “用户最高裁决”

- 范围: Layer 1 / Layer 5
- 路径: `docs/meta/M-000-meta-vision.md` §4.3、§5；`docs/meta/user-decision-log.md`
- **目的**: 解决多智能体系统没有最终价值函数的问题。质量、成本、速度、风险接受度无法由模型自行终局决定。
- **机制**: 把最终裁决权绑定到用户，并要求冲突裁决进入 append-only 日志，形成可追溯先例。
- **替代**: 让多数模型投票或让主笔裁决更直接，但无法表达用户偏好、风险承受和产品所有权。
- **来源**: 从底层事实推出：项目目标、风险偏好、外部承诺都属于用户，不属于智能体。
- **破坏测试**: 删除后，智能体会在“应声虫”和“自作主张”之间摆动；#005 归档路径失误已经给出实证。
- **Verdict**: PRIMARY
- **改造建议**: 保留。后续只需在 M-002/M-005 细化哪些结构性动作必须显式批准。

### [I003] “双核同意默认通过”

- 范围: Layer 1
- 路径: `docs/meta/M-000-meta-vision.md` §4.3
- **目的**: 在用户不被频繁打扰的前提下，让 Claude + Codex 两个主要执行体能推进普通事项。
- **机制**: 两个指定智能体同意即视为足够置信；任一方不可用时自动通过权失效。
- **替代**: 更直接的方式是“可逆普通事项单家可做，高风险事项双核或用户裁决”；或者“双核只作为升级前过滤器，不作为默认通过器”。
- **来源**: 部分来自第一性（至少两条路径能降低单点错误），但“双核默认通过”本身是组织流程类比，缺少对任务风险分布和误判代价的推导。
- **破坏测试**: 若删除，低风险推进效率下降；若放宽，跨边界/外部副作用可能被两个同源或同上下文污染的智能体共同误判。
- **Verdict**: UNDETERMINED
- **改造建议**: 暂缓。M-002 应把“双核默认通过”的适用域限制为普通、可逆、低外部副作用事项，并定义连续误判后的熔断条件。

### [I004] “同源 vs 异源”与伪共识破局

- 范围: Layer 1 / Layer 4
- 路径: `docs/meta/M-000-meta-vision.md` §7.2；`docs/meta/user-decision-log.md` #004/#006/#007
- **目的**: 防止多个看似独立的智能体因为训练谱系、提示词形态、上下文来源相似而给出同向错误。
- **机制**: 区分模型权重、训练谱系、运行实例、上下文可见性；异源强反对会触发用户裁决。
- **替代**: 只要求“多家模型”更简单，但无法识别同源伪共识；只要求“独立上下文”也不足以覆盖训练谱系同源。
- **来源**: 从底层事实推出：错误相关性决定冗余质量，数量本身不等于冗余。#004 身份误识别、#006/#007 同源主笔盲点提供实证。
- **破坏测试**: 删除后，多家一致会被误读为强证据；保留但不验证异源事实，则会退化成模型品牌崇拜。
- **Verdict**: PRIMARY
- **改造建议**: 保留。M-005 需要把“异源事实必须外部验证”机械化，不允许依赖模型自我宣称。

### [I005] B+ 字数硬上限（2500 non-whitespace + 代码块独立）

- 范围: Layer 1 / Layer 5
- 路径: `docs/meta/M-000-meta-vision.md` §5；`docs/meta/user-decision-log.md` #001/#003
- **目的**: 防止最高宪法膨胀成知识库，同时给复杂理念保留足够表达空间。
- **机制**: 用 non-whitespace chars 做物理预算；代码块独立预算；新增条款必须证明无法下沉。
- **替代**: 更直接的方式是“每条新增必须删除或下沉一个旧条款”，或按章节设置目标长度而非硬上限。
- **来源**: “防膨胀”是第一性问题；但具体 2500/400/4000 数值来自经验折中和古德哈特反规避论证，不是从不可再拆事实推导出的常数。
- **破坏测试**: 删除后 M-000 会吸收太多执行细则；保留硬数值过久则可能诱发压缩黑话或为过线争论耗费注意力。
- **Verdict**: ANALOGY
- **改造建议**: 保留但标为可复审启发式。M-005 可增加“压缩损伤”检查：若为了字数牺牲可判定性，允许触发用户复核上限。

### [I006] append-only user-decision-log + Overrule 必填

- 范围: Layer 1 / Layer 5
- 路径: `docs/meta/M-000-meta-vision.md` §5；`docs/meta/user-decision-log.md` #001~#008
- **目的**: 保留裁决链条，防止新裁决悄悄覆盖旧裁决，导致智能体无法判断当前规则为何成立。
- **机制**: 日志 append-only；冲突时必须显式声明 Overrule，否则新裁决无效。
- **替代**: 维护单一最新版规则表更短，但会丢失裁决原因和撤回链条。
- **来源**: 目的来自第一性：多轮协作需要可追溯状态；形式上借用了法律/ADR 的判例链条。
- **破坏测试**: 删除后 #001/#003 字数演化、#007/#008 STATUS_ENUM 撤回会变成互相矛盾的散落事实；智能体容易执行过期方案。
- **Verdict**: PRIMARY
- **改造建议**: 保留。需要补一个机械化检查：新日志条目若含“撤回/覆盖/接管/废弃”但 Overrule 字段为“无”，应告警。

### [I007] frontmatter `layer/status/freshness` schema

- 范围: Layer 3 / Layer 4
- 路径: `Scripts/validate_frontmatter.py`；`docs/decisions/ADR-003-yaml-frontmatter.md`；`docs/meta/user-decision-log.md` #008
- **目的**: 让文档生命周期、时效性和机器检查有结构化入口，减少自然语言状态漂移。
- **机制**: `last_verified`、`layer`、可选 `status`、`freshness` 由 validator 和 docaudit 扫描。
- **替代**: 只用目录位置和标题标注更朴素，但无法统一机械检查；完全自由 YAML 更灵活，但会失去 schema 收敛。
- **来源**: 结构化元数据是工程上第一性需求；但当前 `layer` 六值、`status` 三值是 taxonomy 设计，带有文档系统类比。#008 证明 `status` 语义一旦被下游脚本消费，就不能为了语义纯度随意扩枚举。
- **破坏测试**: 删除 schema，freshness 和归档状态会软腐化；过度扩 schema，则会出现 `supersession_status` 这类侧通道和消费端兼容负担。
- **Verdict**: ANALOGY
- **改造建议**: 重写。保留强 schema，但把“机器消费字段”和“人类解释字段”分层；新字段必须先列出消费端或明确声明仅注释用途。

### [I008] docaudit 11 check 作为文档卫生守门

- 范围: Layer 3
- 路径: `Scripts/audit/docaudit.py`；`Scripts/audit/policy.yaml`；`docs/KNOWLEDGE_MAP.md`
- **目的**: 把链接、孤儿文档、规则引用、skill provenance、verdict drift、gap expiry 等可机械化问题从人工记忆中移出。
- **机制**: `docaudit all` 汇总 10 个结构 check + frontmatter subprocess；policy 控制等级和 legacy whitelist。
- **替代**: 只靠人工 review 更简单，但重复性高且会漏；只靠 CI 链接检查又覆盖不到 verdict-sync/gap_due 等项目语义。
- **来源**: “可机械检查的不要靠人记”是第一性；但当前 11 check 的集合来自历史事故积累，不是完整风险模型。
- **破坏测试**: 删除后 Phase 4/10 已发现的漂移会复发；但若把 docaudit 结果当作语义合规，会产生“结构绿灯 = 事实正确”的错觉。
- **Verdict**: INHERITED
- **改造建议**: 保留并重新命名边界。把 docaudit 明确写成“结构/可机械信号守门”，不得宣称覆盖语义正确性；新增 check 必须附一条真实事故来源或风险模型。

### [I009] Worktree 物理隔离是三方对抗标准

- 范围: Layer 2 / Layer 4
- 路径: `docs/standards/worktree-audit-workflow.md`；`docs/audits/m000-first-principles-task-definition.md`
- **目的**: 防止外审看到主笔中间产物、编号体系、已有 finding 后产生分工、避让或抄袭。
- **机制**: 每家在独立 worktree/分支执行，同一净化任务定义书，完成后只回汇产物。
- **替代**: 只靠提示词“不要参考其他家”更轻，但 Phase 10 已证明文字封堵会失败；完全沙箱更强，但失去 repo 本地实证能力。
- **来源**: 从控制变量实验的底层事实推出：要比较独立判断，必须隔离输入变量。不是单纯类比，已有污染样本直接支撑。
- **破坏测试**: 删除后 Codex/Antigravity 会继续受“Claude 已抓”类语句污染，独立性退化成补充视角。
- **Verdict**: PRIMARY
- **改造建议**: 保留。需要把“启动前清 IDE/Session affinity 缓存”纳入 M-001，否则物理目录隔离仍可能被工具状态穿透。

### [I010] KNOWLEDGE_MAP 文件数量软上限与新增文档门槛

- 范围: Layer 3 / Layer 4
- 路径: `docs/KNOWLEDGE_MAP.md` §文档生命周期
- **目的**: 防止知识库无限增长，降低冷启动和变更传播成本。
- **机制**: 新文档需至少 1 个预期引用方；4 周无 incoming refs 转 archive 候选；活跃文件约 45/50 触线时要求合并或退役。
- **替代**: 更直接的方式是按实际阅读负担和入口层预算度量，而不是按文件数；例如统计 Boot/Action Gate 必读字符数、incoming refs、最近 90 天访问频率。
- **来源**: “知识负担有限”是第一性；但 45/50 文件阈值是经验数，容易继承自仓库当前规模而非认知容量模型。
- **破坏测试**: 删除后会新增无人引用文档；保留硬阈值过强则可能把本该拆分的高内聚文档强行合并，降低可维护性。
- **Verdict**: INHERITED
- **改造建议**: 重写。保留“新增需引用方”和“无 incoming refs 退役候选”，将 45/50 改为软信号，并叠加 Boot 字符预算、引用度、更新时间等指标。

### [I011] M-001~M-006 六分法

- 范围: Layer 1 / Layer 2
- 路径: `docs/meta/M-000-meta-vision.md` §8；`docs/meta/M-001-to-M-006-followup-backlog.md`
- **目的**: 把 M-000 从执行细则中解耦，避免最高原则文档膨胀，同时给下游规则保留归宿。
- **机制**: 将协作工作流、分歧裁决、技能库、降级手册、质量判据、数据治理拆成 6 个派生文档。
- **替代**: 更朴素的方式是按实际触发场景聚类：启动、执行、分歧、收尾、外部事实、数据共享；等 backlog 稳定后再命名。
- **来源**: 下沉原则来自第一性；六个编号类别更像架构分层设计和 RFC 式模块化，未证明刚好这 6 类是最小完备集。
- **破坏测试**: 删除派生层，M-000 会膨胀；固定六分法过早，会让新议题为了归类而扭曲，或让跨域问题被拆散。
- **Verdict**: ANALOGY
- **改造建议**: 保留为 provisional taxonomy。M-001~M-006 起草完成后做一次归并审计：若某文档无独立触发场景或大量依赖另一个文档，应合并。

### [I012] “宪法 / ratified / sign-off”叙事

- 范围: Layer 1 / Layer 5
- 路径: `docs/meta/M-000-meta-vision.md` 标题与 frontmatter；`docs/meta/user-decision-log.md` #004
- **目的**: 明确 M-000 的最高优先级和变更门槛，让智能体知道哪些规则不能随手改。
- **机制**: 使用“最高宪法”“ratified”“sign-off”等强仪式化词汇，建立心理和流程门槛。
- **替代**: 更直接的方式是写成“优先级 0 的规则文档；修改必须用户批准；冲突时按本文件处理”，无需借用政治/法律隐喻。
- **来源**: 这是明显类比：借用宪法/批准仪式的权威感来约束智能体行为。它有沟通价值，但不是底层事实本身。
- **破坏测试**: 删除这些词，若保留机器可检查的优先级和批准流程，系统未必退化；但智能体可能更容易低估变更门槛。
- **Verdict**: ANALOGY
- **改造建议**: 保留但降噪。正文优先使用可执行表述；“宪法/ratified”可作为别名存在，不应承载具体规则语义。
