## 详细 Finding 描述与冲突逻辑剖析

### 🔍 F-D3-001 [HIGH] — H2 (家长唯一操作) 与 H9 (SM-2 端上翻卡复习) 的主体逻辑死锁
*   **防线锚点**：`product-vision.md` line 64/144/187（“目标用户画像重量 H2 — 小学阶段家长是唯一操作者，孩子不碰手机；界面语气以家长为基线，零学习曲线”）。
*   **冲突点**：`product-requirements.md` line 310（“复习 - SM-2 间隔重复复习：翻卡 + 滑动评估”）以及 `product-design.md` line 385/391（“复习设计 - 滑动评估：左滑不记得，右滑记得；复习卡片正面为原题，背面为答案”）。
*   **语义冲突逻辑**：
    1.  **操作主体的死锁**：根据 PV 的核心假设 H2，在错题整理需求最强烈的小学阶段，孩子是不能碰手机的，家长才是 App 的唯一直接用户。
    2.  **交互流的错配**：Requirements 和 Design 照搬了 Anki 的翻卡与滑动评估流程（“记得/不记得”的自我判定）。如果操作者是家长，家长是不可能凭空知道孩子“记不记得”某道题的，必须将手机交给孩子操作，或者由家长逐题念出来询问孩子并手动代扣，这给家长造成了极高的操作摩擦与认知门槛，彻底击穿了 **P5 (零学习曲线，开箱即用)**。
    3.  **两难困境**：如果坚持 H2（孩子不碰手机），则端上翻卡复习在最核心的小学多孩场景中沦为毫无实际意义的“空载功能”；若要让复习功能真正运转，就必须让小学孩子频繁直接玩手机翻卡，这又直接推翻了 PV 极力维持的 H2 核心用户画像假设。
*   **推荐处理方向**：
    *   在 `product-vision.md` 中对复习机制进行**被动化场景澄清**：声明在小学阶段（家长Profile），SM-2 不鼓励直接的端上翻卡操作，其算法数据主要来源于家长在批改后对题目做出的被动“对/错打标”或“掌握度标记”，该打标旨在静默累积复习权重，服务于“智能组卷”选题，而非端上滑卡；
    *   在 `product-design.md` 中增加 Profile 级被动逻辑说明：当 Profile 切换为小学家长时，UI 默认关闭或折叠端上翻卡复习入口，以“生成并打印针对性组卷”作为该复习周期的唯一主路径。

### 🔍 F-D3-002 [MEDIUM] — PV 绝对红线“不做推荐算法”与 Downstream “智能组卷推荐选题”的字面与表述冲突
*   **防线锚点**：`product-vision.md` line 133（“原则 4 - 数据属于用户：不做社交、不做内容平台、**不做推荐算法**”）。
*   **冲突点**：`product-design.md` line 293/301（“智能组卷设计 - 精准选题：自动推荐薄弱题目；基于 SM-2 weakness 权重 + 难度分布均衡的选题算法驱动选题”）以及 `product-requirements.md` line 323（“智能组卷 / Smart Paper：SM-2 驱动选题”）。
*   **语义冲突逻辑**：
    1.  **绝对禁令与技术实现的对冲**：PV 为了在隐私合规上确立绝对差异化，在原则 4 中设立了高度绝对化的排他词汇——“不做推荐算法”。
    2.  **表述冲突**：Downstream 的“智能组卷”却大量使用了“算法驱动精准选题”、“算法推荐薄弱题目”等术语。如果开发或产品宣发不加甄别地在 UI 文案中使用“AI 智能算法推荐今日必刷题”等字眼，将构成对 PV 隐私承诺与红线的字面和实质违反。
*   **推荐处理方向**：
    *   在 `product-vision.md` 针对“不做推荐算法”追加**语义界限说明**（即豁免条款）：澄清所禁止的推荐算法特指“基于云端千人千面用户画像的信息流推送、诱导停留或商业化内容分发算法”，允许且鼓励“纯本地基于用户自身复习数据的提分选题算法与组卷算法”；
    *   下游文档中应避免将选题机制称为“AI/个性化推荐”，统一表述为“本地归档检索选题”或“复习权重选题”，以防隐私语义失控。

### 🔍 F-D3-003 [MEDIUM] — 订阅取消后“数据降级待定策略”与 PV “数据属于用户（私有财产）”及“功能永久免费”的隐性张力
*   **防线锚点**：`product-vision.md` line 125/131/139（“原则 3 - 免费即门槛：核心功能永久免费，免费层 = 完整的单设备产品体验；原则 4 - 用户的题目、图片、笔记是私有财产；数据安全子条款”）。
*   **冲突点**：`product-business.md` line 77-80（“订阅取消后数据降级策略（待定） — 已同步到本机的数据是否保留只读、保留完整可编辑，或转为仅单设备继续使用，需在 StoreKit 落地前明确”）。
*   **语义冲突逻辑**：
    1.  **待定细节留下的合规死锁**：PB 允许在 StoreKit 落地前将订阅取消后的数据降级机制保持“待定”，并且列出了“是否保留只读”、“是否限制编辑”等恶劣选项。
    2.  **原则击穿**：根据 PV，用户的错题数据是用户的绝对私有财产，且单设备体验（采集/管理/编辑/导出）必须**永久且无限制地免费**。一旦用户取消 Pro 订阅后数据被“限制编辑”或“转为只读”，意味着用户已录入的数据在事实上被绑架或锁定，直接击穿了免费门槛原则（P3）与数据属于用户原则（P4）。
*   **推荐处理方向**：
    *   必须在 `product-business.md` 降级策略中**切断降级为只读/限制编辑的任何退路**，补充硬性承诺：“订阅取消后，已同步到本机的数据必须保持完整的可读、可编辑、可管理及可导出权，仅停用 iCloud 云端多设备实时同步通道及图片处理无限使用权，确保用户在任何情况下均享有无损的免费单设备体验。”

### 🔍 F-D3-004 [MEDIUM] — P1 (录入体验是生命线) 与 Pro (图片增强/去手写收费) 的商业化定价张力
*   **防线锚点**：`product-vision.md` line 110-114（“原则 1 - 录入体验是生命线：用户从打开 App 到存好一道题，步骤越少越好；物理环境鲁棒性是核心考量，红蓝黑笔交错、揉皱的试卷、阴影和折痕是核心技术考量”）。
*   **冲突点**：`product-business.md` line 38/50（“付费模式 - 图片处理增强：去手写/去批改痕迹/试卷还原完全锁死在 Pro 订阅层，免费用户仅限次体验”）以及 `product-design.md` line 337（“图片处理增强为 Pro 增值”）。
*   **语义冲突逻辑**：
    1.  **生命线能力被扣为人质**：PV 承诺了“红蓝黑笔交错、揉皱的试卷”等恶劣物理环境的鲁棒性是核心体验 Must。
    2.  **核心体验的付费阻塞**：对于家长的真实录入场景（H2），他们翻拍的练习卷无一例外都写满了孩子已作答的笔迹和老师的红色批改符号。如果免费层不提供去手写和还原试卷能力（将其视为纯粹的 Pro 增值，且完全锁死或极度限次），免费用户在导出打印或复习时，将面临“原图充斥手写脏乱”的极大视觉和交互摩擦。
    3.  **隐性冲突**：这意味着 PV P1 承诺的“恶劣物理环境录入的极致体验（生命线）”，在事实上需要用户通过订阅 Pro 才能完整解锁，导致免费单设备体验完整性（P3）名存实亡。
*   **推荐处理方向**：
    *   在 `product-business.md` 中明确承认这种张力，并在免费层做出体验兜底：为“图片处理增强”中的“去手写”与“还原试卷”提供一份**“低频但稳定”的保底免费配额**（如每月 15 次，满足普通多孩家庭单周最核心的单元测试错题整理），将完全的 Pro 独占降级为 Hybrid 体验，以维护 P1 原则的诚信。

### 🔍 F-D3-005 [LOW] — 商业配额耗尽界面渲染与 PV P5 “防教育焦虑贩卖”的交互边界瑕疵
*   **防线锚点**：`product-vision.md` line 42/148（“情绪基调 - 客观冷静：不向家长贩卖教育焦虑，不做连续天数打卡，不弹成就渲染，做纯粹的工具”）。
*   **冲突点**：`product-design.md` line 316-318（“智能组卷设计 - 配额机制：免费配额按自然月重置；配额耗尽后展示 Pro 引导；与图片增强策略统一”）。
*   **语义冲突逻辑**：
    1.  **配额预警的焦虑化倾向**：Downstream 文档仅规定了配额耗尽后需要展示“Pro 引导”，但完全没有在交互、设计和文案层面对此引导做出“去焦虑化”的任何防护限制。
    2.  **潜在的漂移**：如果开发在配额耗尽时采用亮红色警告框、带有催促性的“仅剩 0 次，您的孩子将无法享受智能选题！”等贩卖教育焦虑的营销文案，将直接突破 PV 的客观冷静红线。
*   **推荐处理方向**：
    *   在 `product-design.md` 中为配额展示与耗尽引导追加**交互铁律约束**：明确规定“免费配额提示与耗尽后的订阅引导必须保持绝对的客观、被动、冷静。禁止使用高对比度红色警告框，禁止通过系统通知主动轰炸配额状态，禁止在引导文案中使用任何带‘落后’、‘无法提分’等贩卖焦虑倾向的词汇，以维护工具的纯粹度。”

### 🔍 F-D3-006 [LOW] — PV “零个人信息收集”与 App Store Age Range API 集成的潜在漂移
*   **防线锚点**：`product-vision.md` line 49/134（“产品定位 - 私有：不收集可识别个人信息；原则 4 - 默认不收集个人信息：无需注册、不要求年级或学校”）。
*   **冲突点**：`product-business.md` line 177-178（“发布策略 - Declared Age Range API：评估是否集成，该 API 允许 App 请求用户分享年龄范围”）。
*   **语义冲突逻辑**：
    1.  **隐私防线对第三方接口的敏感性**：虽然 Age Range API 是 Apple 官方为了年龄核实（COPPA）提供的系统级接口，只返回匿名范围，但调用此接口在实质上属于向用户发起了“个人属性（年龄/年级）的调取请求”。这与 PV 承诺的“不要求年级、绝对隐私、零收集”存在语义张力和信任张力，容易让敏感的家长（P5）产生心理防御。
*   **推荐处理方向**：
    *   在 `product-business.md` 中补充该 API 集成的**隔离性约束说明**：明确若未来为了应对合规而集成该 API，其获取的数据**仅限**在端上内存中用于动态决定是否开启 Analytics（如判定为 <13 岁儿童时在端上彻底切断 Firebase 分析），**绝对禁止**将年龄数据持久化写入本地 SwiftData 数据库、绝对禁止上报到分析云端、也绝对禁止在 UI 界面上有任何显式呈现。

## 维度 3 内部冲突扫描审计结论

通过本轮维度 3 的全量冲突扫描，Antigravity 明确指出：虽然 SnapDrill 在功能和结构层实现了闭环，但在**“底层用户画像逻辑（H2）”与“具体操作实现（SM-2 翻卡/记得评估交互）”之间存在根本性的逻辑自相矛盾（死锁）**。

1.  **用户画像与操作死锁 (F-D3-001)** 是本轮抓到的最致命的真冲突。小学家长的“唯一操作者”定位，使得 Anki 式的“端上滑卡评估”在实际家庭交互场景中根本无法自洽运行。必须通过将小学阶段复习进行“被动打标化”和“去端上滑卡化”，以智能组卷打印为唯一主路径才能解开死锁。
2.  **字面冲突与降级隐患 (F-D3-002 & F-D3-003)** 表现在“不做什么推荐算法”与 Downstream 智能组卷的词汇撞击，以及商业化遗留的“取消订阅降级待定”对“数据属于用户”终极承诺的潜在侵蚀。
3.  **核心体验付费卡点 (F-D3-004)** 则暴露了“录入鲁棒性（P1）”在真实带有手写字迹的练习卷场景下，对“Pro 图片处理增强（去手写）”的隐性依赖，免费单设备完整闭环体验（P3）存在一定虚化，需增设保底免费配额来化解。
