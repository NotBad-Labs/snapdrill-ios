## 阻塞性问题

### B1 — M-006 的 user-decision-log 模板不完整，违反 M-002 §10 schema

- **具体事实错误**：M-002 §10.1 要求八个必填字段缺一不可：`编号 / 时间 / 冲突描述 / 裁决 / 理由 / 是否触发元规则修订 / Overrule 关系 / 元层级注记`。M-006 §9.2 的缺口模板缺 `时间`，并且未把 `编号` 放进 YAML 示例；M-006 §5.3 的授权模板也没有声明“以下只是裁决字段 payload，完整条目仍必须保留 M-002 §10 八字段”。
- **可证伪反假设**：如果 M-006 已完整承接 M-002 §10 schema，那么 §9.2 示例应包含 `编号` 和 `时间`，或明确说明该代码块不是完整日志条目、必须嵌入 M-002 §10.1 八字段模板。当前文本不满足。
- **明确风险路径**：后续智能体按 M-006 §9.2 直接追加缺口记录，会生成缺 `时间` 或缺 `编号` 的裁决日志条目，触发 M-002 §10 schema 违反，并复发 #025 暴露的“数字凑数巧合”类漏审：看似字段数接近，实际漏掉宪法层必填项。

### B2 — §10.1 指向已归档/不存在的 `docs/memory/feedback.md`

- **具体事实错误**：M-006 §10.1 写“项目级治理规则不应私有 memory 化（应入 `docs/memory/feedback.md` 或 `docs/meta/user-decision-log.md`）”。但 user-decision-log #022 已裁决 `docs/memory/` 整目录归档，且当前仓库 `test -e docs/memory/feedback.md` 返回不存在。
- **可证伪反假设**：如果 `docs/memory/feedback.md` 仍是有效治理规则落点，那么该文件应在当前工作树存在，并应在 M-000 §11 注册表中作为 active 非产品文档登记。实际当前 `docs/` 根下无 `memory/` 目录，#022 也把 `docs/memory/` active 状态精化为整目录归档。
- **明确风险路径**：按 M-006 §10.1 执行会把项目级治理规则写向已退役路径，绕开 M-000 §11 SSOT 注册表和 #022 的清理纪律，造成私有 memory 治理规则与项目 active 文档体系再次分裂。
