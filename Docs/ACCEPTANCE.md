## 用例表

| ID | 前置 | 步骤 | 可观察结果 | 失败判定 |
| --- | --- | --- | --- | --- |
| A1 | 全新安装 / 清空数据 | 启动 → 完成「采集 → 保存 → 找回 → 导出」一次闭环 | 全程无注册/登录/Profile/Workspace 入口；普通启动默认 Dashboard；一次操作可达 Capture 与 Library | 出现账户墙；需 >1 次操作才能进入核心路径 |
| A2 | 四种输入源各备一份样本 | 分别用相机、文档扫描、相册、PDF 各存一条；再人为让 OCR 失败后保存 | 4 条均入库；OCR 失败时仍可保存可读图片，OCR 结果可见可编辑 | OCR 失败阻断保存；任一渠道无替代路径 |
| A3 | 预置 3 条含不同字段的资料 | 依次执行浏览、搜索、筛选、查看详情、编辑、分类、删除 | 每步结果与预期一致且可复现；空字符串与 NULL 的区别被保留 | 静默丢字段、篡改 taxonomy、删除不原子 |
| A4 | 存在可删资料 | 删除一条 → 5 秒窗口内撤销；再分别测切后台、杀进程重启后撤销 | 数据恢复且关联完整；撤销窗口不因后台/重启缩短 | 窗口缩短、重启后丢失、撤销产生重复记录 |
| A5 | 选中 N 条资料 | 生成 PDF → 预览 → 系统打印 / 分享 / 保存；中途取消一次 | 物理页数 = `ceil(N / itemsPerPage)`，无空白页、无重复条目；输出可用；取消无副作用 | 页数不符、空选择未提前失败、取消写入状态 |
| A6 | 构造完整备份与损坏 store 各一份 | 导出备份 → 恢复 → 比对 inventory；再导入损坏 store | 恢复后 inventory 一致；损坏 store 有可理解恢复路径，原库不被静默清空 | 静默清空、恢复半途写入、事件材料被自动删除 |
| A7 | 可注入故障的测试构建 | 分别模拟权限拒绝、OCR 失败、存储失败、DB 打不开 | 每种情况都有替代路径与可理解提示；无白屏、无假空库 | 任一路径白屏、假空库或无声失败 |
| A8 | 采集流程可中断 | 采集中途崩溃 / 杀进程 → 重启；再测保存成功与用户明确丢弃 | 草稿可恢复；仅保存成功或明确丢弃才删除；不按时间自动清理 | 崩溃丢草稿、自动过期删除、丢弃不可控 |
| A9 | 带 GPS 的图片样本；网络监控可用 | 导入图片 → 检查入库文件；全程抓包 | 入库图片已移除 EXIF GPS；无非预期网络上传；图片路径在读/写/删边界被校验 | 位置信息残留、出现未授权请求、路径未校验 |
| A10 | 中英文环境、VoiceOver、Dynamic Type 各档、支持的 iPhone 尺寸 | 在每种组合下完成一次核心闭环 | 全部可完成；AX 元素顺序与视觉顺序一致；无截断/遮挡 | 任一组合阻断核心任务、AX 顺序错乱 |
| A11 | 公开候选构建（非 po-only / research） | 逐项检查 Tab、Dashboard、设置、通知、深链、后台任务、Spotlight/Widget、AX 元素、公开元数据 | 未批准能力**零入口、零激活、零副作用**；启动、后台、升级、遗留调度均不执行 | 存在任何可达入口或隐式激活路径 |

## 验证分层映射

| 层 | 覆盖用例 | 说明 |

| T1 单元 / 逻辑 | A3、A4、A8 的逻辑部分；A5 页数计算 | build-for-testing + test-without-building |
