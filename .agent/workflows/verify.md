# V.E.R.I.F.Y. 验证工作流

> 基于专家报告的 V.E.R.I.F.Y. 验证协议，对 AI 生成的代码进行系统性审查。

---

description: 对 AI 生成代码执行 V.E.R.I.F.Y. 六步验证协议
---

## 触发场景

- 完成一个功能实现后
- 在提交代码或发起 PR 前
- 用户请求 `/verify`

---

## 验证步骤

### V - Verbalise (口述解释)

> 让 AI 用自然语言解释生成的代码逻辑

```
请用简洁的中文解释你刚才生成/修改的代码：
1. 核心算法逻辑是什么？
2. 为什么选择这种实现方式？
3. 有哪些边界条件需要注意？
```

**判断标准**：如果解释不清晰或自相矛盾，说明逻辑可能混乱。

---

### E - Examine Dependencies (检查依赖)

> 审查所有新引入的第三方库

```
列出本次变更引入的所有新依赖：
1. 包名和版本
2. 引入原因
3. 是否有更轻量的替代方案？
4. 该包的维护状态如何？（最近更新时间、Star 数）
```

**⚠️ 警示**：AI 倾向于引入冷门或过时的库，必须人工审查。

---

### R - Review Security (审查安全)

> 执行安全扫描

```
对以下安全风险进行自查：
1. SQL 注入风险（是否使用参数化查询）
2. XSS 攻击风险（用户输入是否转义）
3. 敏感信息暴露（API Key、Token 是否硬编码）
4. 权限提升风险（是否存在越权访问）
5. 不安全的反序列化
```

// turbo
运行 `/audit` 工作流进行自动化代码审计。

---

### I - Inspect Edge Cases (检查边界)

> 询问边界情况

```
请回答以下边界场景的处理方式：
1. 如果网络延迟超过 5 秒会怎样？
2. 如果输入为空或 nil 会怎样？
3. 如果输入超出预期范围（如负数、超大数）会怎样？
4. 如果并发调用会怎样？
5. 如果设备内存不足会怎样？
```

---

### F - Functional Validation (功能验证)

> 执行功能测试

```
请验证以下功能点：
1. 主路径（Happy Path）是否正常工作？
2. 错误恢复路径是否有效？
3. UI 变更是否符合设计预期？
```

// turbo
如果涉及 UI 变更，使用浏览器工具截图验证。

// turbo
如果涉及逻辑变更，运行相关单元测试：

```bash
xcodebuild test -scheme SnapDrill -destination 'platform=iOS Simulator,name=iPhone 17' -only-testing:SnapDrillCoreTests
```

---

### Y - Yield Improvements (持续改进)

> 让 AI 自我批判

```
请自我审视这段代码：
1. 有什么可以优化的地方？
2. 是否存在代码重复？
3. 是否符合项目的架构规范（参考 .claude/principles.md）？
4. 性能是否可以提升？
5. 可读性是否足够好？
```

---

## 输出格式

完成验证后，生成验证报告：

```markdown
## V.E.R.I.F.Y. 验证报告

| 步骤 | 状态 | 备注 |
|---|:---:|---|
| V - 口述解释 | ✅/⚠️/❌ | ... |
| E - 检查依赖 | ✅/⚠️/❌ | ... |
| R - 审查安全 | ✅/⚠️/❌ | ... |
| I - 检查边界 | ✅/⚠️/❌ | ... |
| F - 功能验证 | ✅/⚠️/❌ | ... |
| Y - 持续改进 | ✅/⚠️/❌ | ... |

**总体评估**: [通过/需要修复/高风险]
```
