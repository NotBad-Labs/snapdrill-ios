## 用户价值金字塔

```
┌─────────────────────┐
│   智能复习（锦上添花）  │  ← 基于遗忘曲线的间隔重复
├─────────────────────┤
│   整理管理（核心体验）  │  ← 分类、标签、搜索、导出
├─────────────────────┤
│   数字化录入（生命线）  │  ← 拍照、导入、手动编辑
└─────────────────────┘
```

**设计铁律**：任何功能如果损害了"录入"和"管理"的简洁性，就不该做。复习是附加值，不是核心。

## 采集入口设计（2026-03-09 更新，经 Apple HIG 研究修正）

底部 Tab 栏常驻，采集入口作为标准 Tab 始终可达。
Apple HIG 明确规定 Tab Bar 用于导航而非执行动作，自定义突出按钮（大号/居中/突出色）违反原生设计规范，
且与最新 iOS 原生 Tab Bar 样式冲突，因此不采用。
如未来用户反馈可发现性不足，可评估 FAB（Floating Action Button，浮动操作按钮）方案——
参考 Apple Reminders / Journal 的做法，将采集作为独立于 Tab Bar 的浮动元素。

## OCR 定位与识别能力演进（2026-03-07 确立）

**核心定位**：OCR 是辅助展示 + 搜索索引，原图是真相。

SnapDrill 依托 Apple Vision 原生识别能力（18 种语言含中文专用模型，端上实时运行），
在印刷体文字识别方面已优于大多数竞品（竞品多依赖第三方或云端 API）。

**录入流程中的 OCR 策略**：
- OCR 文字**展示但不强迫校对**——用户看到识别结果，可以修正也可以直接保存
- 不制造「必须校对完才能保存」的心理负担
- OCR 文字的核心价值是**全局搜索**（旅程 3 中"搜索抛物线"的场景）

**这是 SnapDrill 相对竞品的技术优势**：纯原生端上识别、隐私在端、无需联网、零数据外传。

**识别能力演进路线**（2026-03-23 修正，基于 Apple 官方文档核实）：

| 版本 | 能力 | 说明 |
|---|---|---|
| v1.0 | 印刷体中英文 OCR + 实时文字区域检测 | Apple Vision 高精度识别模式，中英文 |
| v1.5 | 手写体识别增强（探索性） | Vision 对手写体有一定支持，但无独立中文手写识别模型。需评估实际识别率后决定是否作为正式功能 |

**产品影响澄清**（技术细节见 `architecture.md`§技术声明）：
- 照片中的手写文字识别（区别于屏幕手写输入）能力有限，手写体增强列为探索性
- 数理化公式无 Apple 原生识别 API，需依赖第三方方案，与隐私优先定位存在张力
- 数理化公式识别与渲染列入「待评估」，待第三方端上方案成熟后重新评估

## 原图保存铁律（2026-03-07 确立）

题目的原始图片**必须保存**，包括文字部分和图形部分。
OCR 识别出的文字是辅助（方便搜索和编辑），原图是真相。

- 复习时**必须能看到原图**，尤其数学几何题，没有图就没有意义
- 复习形式：卡片式，正面 = 原题（图文），背面 = 答案，左右滑动 = 记得/不记得

**存储策略**：
- 采集时自动压缩图片：裁剪后限制分辨率（~1200-2000px 长边），JPEG 质量 0.8，保证公式/图形清晰可辨
- 200-2000 道题 × ~200KB/张 ≈ 40-400MB，在 iPhone 128GB 起步的时代可接受
- 存储管理功能（如空间占用统计、旧题压缩）列入 v1.5 考虑
- **iCloud 空间风险（v1.5 考虑）**：Pro 用户开启同步后，2000 题 ~400MB 可能占满 5GB 免费 iCloud 空间。需在设置页提供 iCloud 空间占用状态提示，空间不足时引导用户清理或升级 iCloud+

## 字段可配置系统（2026-03-07 确立）

**核心理念**：题目需要多少分类字段，由用户决定，而非开发者硬编码。

### 字段分层

| 层级 | 字段 | 行为 |
|---|---|---|
| 固定字段 | 题目内容（文字/图片） | 永远存在，不可关闭 |
| 默认开启 | 学科 | 新用户开箱仅此一项，可在设置中关闭 |
| 默认关闭 | 难度、来源、年级、答案 | 用户按需在设置中开启 |
| 自定义标签 | 用户自由创建的标签（如"易错""考前必看"） | 始终可用，不可关闭 |

### 配置入口

- **首次录入后引导**：用户完成第一次录入保存后，弹出引导提示「下次录题时要不要多填学科？」，引导用户按需开启字段。首次启动 Onboarding 不要求配置（Apple HIG："Avoid asking for setup information up front"）
- **设置阶段**：设置中提供"字段管理器"，随时开关
- **录入阶段**：录入界面只显示用户已开启的字段
- **补充阶段**：题库中编辑已有题目时，可随时扩展新字段

### 系统字段 vs 用户标签的区别（2026-03-07 确立）

- **系统字段**（学科、年级、难度、来源等）：预定义选项，在设置中开关
- **用户自定义标签**（"易错"、"考前必看"、"老师强调"等）：用户输入文字、按空格生成，完全自由创建
- 标签是个性化的核心体现——每个学生的标签体系都是独一无二的
- 当前已支持：自由输入 + 历史标签建议

### 系统字段选项管理（2026-03-16 补全）

系统字段（学科、来源、年级）的**选项列表**支持用户增删改：
- **增**：用户可新增学科（如"信息技术"）、来源（如"竞赛真题"）、年级
- **删**：已被题目使用的选项不可删除（保护数据完整性）
- **改**：重命名时级联更新所有引用该选项的题目
- **颜色**：每个选项可选择一种颜色，用于过滤胶囊和列表中的视觉区分
- **图标**：从预设教育图标集（~20 个，如📐数学、📖语文、🔤英语、🧪化学等）中选择，不使用全量 SF Symbol 选择器

设计原则：不同用户有不同的学科体系（小学 vs 初中 vs 竞赛），硬编码选项无法覆盖。

### 自动推断（与字段配置互补）

字段配置决定"字段是否存在"，自动推断决定"字段的默认值"：
- 上次选了"数学"→ 这次默认"数学"
- 上次选了"期中模拟卷三"→ 这次默认同来源
- 用户只需要改有变化的字段，其余自动填好

两者结合 = 用户只看到自己关心的字段，每个字段还自动填好了，录入摩擦降到最低。

## 连续录入设计（2026-03-07 确立）

保存题目后，默认跳转回采集界面（摄像头），而非 Dashboard。
一张试卷可能错 3-5 题，连续录入是高频场景，每多一次跳转就多一份摩擦。

## 一图多题的演进路径（2026-03-07 确立）

真实场景：一张试卷照片上可能有多道题，用户只想录其中几道。

| 版本 | 能力 | 说明 |
|---|---|---|
| v1.0 | 一图一题（手动裁剪） | 用户导入同一张图多次，每次裁剪不同区域 |
| v1.5 | 一图连续裁剪 | 同一张图上连续裁剪多次，每次产出一道题，不用重新选图 |
| v1.5 | AI 辅助拆题（探索性） | 利用 Apple 文档结构识别能力辅助定位题目边界，用户确认后批量生成 |

原则：v1.0 功能完整可用，后续每一步都是体验优化而非功能补全。

## 复习功能的克制原则（2026-03-07 确立）

- 复习是"锦上添花"，不能喧宾夺主
- **默认不推送通知**，但用户可在设置中自行开启并选择频率
- 不做打卡机制、不搞连续天数、不弹成就弹窗
- 这不是"学习打卡工具"，这是"存档工具"——复习只是附带福利
- 把选择权交给用户：有人需要提醒，有人不需要，我们尊重每个人的节奏

| 版本 | 格式 | 说明 | 付费 |

## 草稿恢复（2026-03-16 补全）

录入过程中用户意外退出（如来电、误触 Home 键），已输入的内容不应丢失。
- 采集页面退出时自动保存草稿（图片 + OCR 文字）
- 下次进入采集时检测到草稿，弹窗提示用户恢复或放弃
- 草稿仅保留最近一份，保存新题目后自动清除

这是 S0 级数据丢失防护，不是功能特性。

## 引导与帮助（2026-03-16 补全）

### Onboarding（首次启动引导，2026-03-18 #304 终审修订）

首次启动展示多页引导流（~3-4 页），介绍核心功能。**不在 Onboarding 中要求字段配置**——
Apple HIG 明确反对首次启动时要求用户配置（"Avoid asking for setup information up front"）。
字段选择延后到首次录入保存后，通过引导提示触发（见「字段可配置系统 → 配置入口」）。
完成后不再显示。设计原则：快速、不啰嗦，让用户尽快开始录题。

### Feature Tooltips（功能提示）

首次使用某功能时弹出轻量提示气泡（如首次进入过滤页提示「可多选学科」）。
每个提示只显示一次，不打扰。

### 帮助中心（2026-03-18 #304 终审修订）

设置页提供帮助入口，跳转到外部网页 FAQ。行业验证：Bear、Things 3、Notion、Day One 全部使用外部网站 FAQ，不在 App 内构建搜索系统。
优势：内容更新不需要发版、开发维护成本低、v1.0 阶段用户量小无需重投入。

## 设置与个性化（2026-03-16 补全）

### 用户资料（纯本地，不上传）

- **昵称**：显示在 Dashboard 问候语中
- **座右铭**：个人激励文字
- **头像**：从预设头像组中选择，或从相册上传自定义照片
- **每日复习目标**：用户自由设定，无硬性范围限制

所有资料纯本地存储，不外传，与 PV-4「不收集可识别个人信息」一致。
这不是注册信息，是本地个性化定制。

### 复习卡片外观（2026-03-18 #304 终审修订）

- 字号：正面和背面独立设置，范围相同（题目和答案内容密度天然不同，独立字号是合理需求）
- 对齐方式：固定左对齐，不提供用户配置（绝大多数场景左对齐即可，减少认知负担）
- 提供实时预览

### 通知细节

- 每日复习提醒：开关 + 时间选择（小时/分钟）
- 通知声音开关
- App 图标角标开关（角标 = 图标右上角红色数字气泡，显示待复习数）

### 外观

- 外观模式：跟随系统 / 浅色 / 深色

### 存储维护

- 媒体缓存清理：清理 App 运行产生的临时文件（OCR 临时图片、PDF 渲染缓存等），不影响用户题目数据

### 使用数据（Analytics + 崩溃报告）

- 单一开关控制匿名使用数据收集（Firebase Analytics + Crashlytics）
- **默认开启**，用户可随时在设置中关闭
- 收集的是匿名事件计数和崩溃堆栈，不含任何可识别个人信息或用户内容

### 语言设置

- v1.0：引导用户前往系统设置修改 App 语言
- v1.5：支持 App 内直接切换语言（不依赖系统设置）

## 功能边界

### 做什么（in scope）

- 多种方式录入题目（拍照、导入、手动）
- OCR 文字识别（降低手动输入成本）
- 题目分类管理（学科、来源、年级、标签、难度）
- 搜索和过滤
- 基于遗忘曲线的间隔重复复习
- 导出（PDF / JSON / CSV）
- 本地数据存储（隐私优先）
- iCloud 同步（多设备，v1.5 Pro 付费功能）

### 不做什么（out of scope）

- 提供题库内容（我们是工具，不是内容平台）
- AI 解题 / 答案生成（不是辅导工具）
- 社交功能（不是社区）
- 排行榜 / 竞争机制（不是游戏）
- 限制免费录入数量（不做竞品最恶心的事）

### 待评估（需要用户反馈后决定）

- 题目分享（单道题生成图片/PDF 分享给同学/老师，非社交链接）
- 多科目模板（不同学科的结构化字段，如数学有"解题步骤"）
- 批量导入增强（一张试卷照片自动拆分为多道题，v1.5 探索性）
- 公式识别与渲染（LaTeX/MathML，数理化专用，待第三方端上方案成熟后评估）
- 组卷排版打印（选错题 → 自动排版留白解答区 → PDF/打印，v1.5 付费点；需考虑主流打印机纸宽适配：57mm/80mm/A4）
- 去手写 / 试卷还原（AI 清除笔迹还原空白试卷，行业已验证为刚需，无 Apple 原生 API，需第三方方案）
- iPad + Apple Pencil 深度集成：从 GoodNotes/Notability 直接 Drag & Drop 圈选题目到 SnapDrill（v1.5）
- 批量导出原图（ZIP）— 免费功能，增强"数据属于用户"的安全感
- 角色预设套件（选"我是家长"后自动配置字段组合，低优先级）
- 撤销/回退操作（Undo）— 编辑、裁剪、删除的撤销能力（v1.0 能力清单评审中识别，v1.5+ 再评估）
- 批量操作（批量删除、批量打标签）— 当前仅逐条编辑（v1.0 能力清单评审中识别，v1.5+ 再评估）
- OCR 结果复制到剪贴板 — 文字可编辑但未定义复制能力（v1.0 能力清单评审中识别，v1.5+ 再评估）
- 过滤中按难度过滤 — 排序已支持难度，但过滤维度未包含（v1.0 能力清单评审中识别，v1.5+ 再评估）
- 数据导入（从其他错题 App 迁移）— 竞品用户转移路径（v1.0 能力清单评审中识别，v1.5+ 再评估）
- ~~开源许可展示~~ — **已提升到 v1.0**（见路线图，使用 Firebase SDK 为 App Store 合规硬性要求）

### 家长模式：边界讨论（待定）

**背景**：中国低年级学生的错题整理由家长代劳，家长是实际操作者。

| 年龄段 | 实际使用者 | 家长模式需求 |
|---|---|---|
| 小学（6-12 岁） | 家长为主 | 强需求：家长全权操作，可能需要管理多个孩子 |
| 初中（12-15 岁） | 学生为主，家长偶尔介入 | 中等：家长可能想看学习数据，但不代劳 |
| 高中（15-18 岁） | 学生独立使用 | 弱/无：学生自主管理 |

**可能的形态**：
- **最轻方案**：多 Profile 切换（家长帮不同孩子管理不同的题库）
- **中等方案**：家长账号 + 孩子账号关联，家长可查看统计数据
- **最重方案**：独立的家长 App / 家长视图

**决策（2026-03-07）**：多 Profile（本地多题库隔离）提升为 **v1.5 明确规划（P1）**。
理由：旅程 5 已证明多孩家庭没有 Profile = 产品不可用（不是体验差，是不可用）。
实现参考 Obsidian 的 Vault 切换，开发成本低。
