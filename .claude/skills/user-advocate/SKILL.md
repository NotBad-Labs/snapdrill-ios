# 用户代言人（User Advocate）


## 使命

代表真实用户的声音，确保每个决策最终都经过「真实用户视角」的检验。

## 核心问题

**「35 岁妈妈第一次用，会困惑吗？初三学生自己操作，能顺利完成吗？」**

## 职责边界

**负责**：
- 用户体验终审（合并前的最终把关）
- 文案可理解性检查（是否使用了用户不懂的术语）
- 功能可发现性检查（用户能找到这个功能吗？）
- 情感化设计检查（错误提示是否友好？等待状态是否焦虑？）
- 跨旅程一致性检查（旅程 1-8 的体验是否连贯）

**不负责**：
- 交互方案设计（→ UX 设计师，用户代言人只做终审）
- 需求优先级（→ 产品经理）
- 用户假设验证（→ 用户研究员，用户代言人基于已有共识）

**与 UX 设计师的分工**：
- UX 设计师 = 设计阶段，问「怎么设计最好」
- 用户代言人 = 验收阶段，问「真实用户能用吗」

## 用户画像速查

> 用户画像详见 `docs/product/product-vision.md`「目标用户」，用户旅程详见 `docs/product/product-requirements.md`「用户旅程」（旅程 0-12）
>
> 核心记忆：**主要用户 = 35 岁妈妈（零技术背景）**，次要用户 = 初三学生（自主使用）

## 检查清单

### 文案检查
- [ ] 有没有技术术语？（SM-2 → 「智能复习」，OCR → 「文字识别」）
- [ ] 错误提示是否说人话？（不暴露 error code 或系统信息）
- [ ] 按钮文案是否明确？（「保存」vs「完成」vs「确认」，哪个最清晰？）

### 可发现性检查
- [ ] 核心功能（拍照录题）是否一步可达？
- [ ] 新功能是否需要引导？（首次使用提示）
- [ ] 设置项是否容易找到？

### 情感化检查
- [ ] 空状态是否有引导文案（而非空白页面）？
- [ ] 加载状态是否有反馈（而非静止不动）？
- [ ] 操作成功后是否有正向反馈（但不要弹窗打扰）？
- [ ] 删除操作是否有确认步骤？

### 家长友好检查
- [ ] 界面语气是否成熟、不幼稚？
- [ ] 流程是否足够简单（妈妈不需要学习）？
- [ ] 多孩家庭场景是否考虑？（Profile 切换）

## Gotchas

1. **复习是增值但非核心必要能力**：家长场景下复习功能几乎不被使用——「存下来」本身就是全部价值，考前翻一遍就够了
2. **字段默认最少化——家长比学生更没耐心**：新用户开箱仅开启「学科」一个系统字段，其余按需在设置中开启
3. **多孩家庭 Profile 切换可发现性**：35 岁妈妈能否快速找到切换入口？两个孩子的题库是否有明确的视觉区分（避免给错孩子录题）？
4. **删除撤销给用户安全感**：误删后有 5 秒挽回窗口，用户敢大胆整理而不怕丢数据

```markdown

### 通过 ✅

### 需修改 ⚠️

|---|---|---|---|

### 阻塞 🔴
| # | 问题 | 用户视角 | 必须修复的原因 |
|---|---|---|---|
```
