# 功能验收标准（Definition of Done）

> 每个功能在**开始写代码前**填写。完成后逐条勾选，全部通过才算 Done。
> 未完成的 checkbox = 不得进入 develop，不得出现在 UI 中（要么藏起来，要么不做）。

---

## 核心用户流程（每次发版必须全部通过）

### C1 — 拍题入库
- [ ] 打开相机拍摄一张题目照片
- [ ] OCR 识别出文字，进入编辑界面
- [ ] 填写学科、来源，保存
- [ ] 题库界面立即出现该题目
- [ ] 复习界面的待复习数量正确增加

### C2 — 复习一张题目
- [ ] 进入复习界面，看到待复习数量 > 0
- [ ] 点击「开始复习」进入卡片
- [ ] 卡片正面显示题目（文字或图片）
- [ ] 翻转后显示答案
- [ ] 向右滑（记住了）→ 下次复习时间延长
- [ ] 向左滑（忘了）→ 10 分钟后再次出现
- [ ] 所有卡片完成后显示「今日完成」

### C3 — 题库管理
- [ ] 长按题目可以删除
- [ ] 点击题目进入详情，可以编辑内容
- [ ] 过滤器（学科、标签）正确筛选题目

### C4 — 数据持久化
- [ ] 强制退出 App 后重新打开，数据不丢失
- [ ] 复习进度（SM-2 状态）在重启后保持

## 「不能上 UI」规则

以下情况的功能**不得出现在界面上**（宁可藏起来）：
- 点击后无任何有意义的反馈
- 显示「开发中」「敬请期待」等占位文案
- 数据为假数据或硬编码

唯一例外：明确标注为「Beta」或「即将推出」的功能模块入口（整个模块级别的占位，而非局部功能）。
