## 用户价值金字塔

```
┌─────────────────────┐
│   智能复习（锦上添花）  │  ← 基于遗忘曲线的间隔重复
├─────────────────────┤
│   整理管理（核心体验）  │  ← 分类、标签、搜索、导出
├─────────────────────┤
│   数字化录入（生命线）  │  ← 拍照、导入、手动编辑
└─────────────────────┘
```

**设计铁律**：任何功能如果损害了"录入"和"管理"的简洁性，就不该做。复习是附加值，不是核心。

## 采集入口设计（2026-03-09 更新，经 Apple HIG 研究修正）

底部 Tab 栏常驻，采集入口作为标准 Tab 始终可达。
Apple HIG 明确规定 Tab Bar 用于导航而非执行动作，自定义突出按钮（大号/居中/突出色）违反原生设计规范，
且与最新 iOS 原生 Tab Bar 样式冲突，因此不采用。
如未来用户反馈可发现性不足，可评估 FAB（Floating Action Button，浮动操作按钮）方案——
参考 Apple Reminders / Journal 的做法，将采集作为独立于 Tab Bar 的浮动元素。

## OCR 定位（2026-03-07 确立）

**核心定位**：OCR 是辅助展示 + 搜索索引，原图是真相。

SnapDrill 依托 Apple Vision 原生识别能力（18 种语言含中文专用模型，端上实时运行），
在印刷体文字识别方面已优于大多数竞品（竞品多依赖第三方或云端 API）。

**录入流程中的 OCR 策略**：
- OCR 文字**展示但不强迫校对**——用户看到识别结果，可以修正也可以直接保存
- 不制造「必须校对完才能保存」的心理负担
- OCR 文字的核心价值是**全局搜索**（旅程 3 中"搜索抛物线"的场景）

**这是 SnapDrill 相对竞品的技术优势**：纯原生端上识别、隐私在端、无需联网、零数据外传。

**产品影响澄清**（技术细节见 `architecture.md`§技术声明）：
- 照片中的手写文字识别（区别于屏幕手写输入）能力有限，手写体增强列为探索性
- 数理化公式无 Apple 原生识别 API，需依赖第三方方案，与隐私优先定位存在张力
- 数理化公式识别与渲染列入「待评估」，待第三方端上方案成熟后重新评估

## 原图保存铁律（2026-03-07 确立）

题目的原始图片**必须保存**，包括文字部分和图形部分。
OCR 识别出的文字是辅助（方便搜索和编辑），原图是真相。

- 复习时**必须能看到原图**，尤其数学几何题，没有图就没有意义
- 复习形式：卡片式，正面 = 原题（图文），背面 = 答案，左右滑动 = 记得/不记得

**存储策略**：
- 采集时自动压缩图片：裁剪后限制分辨率（~1200-2000px 长边），JPEG 质量 0.8，保证公式/图形清晰可辨
- 200-2000 道题 × ~200KB/张 ≈ 40-400MB，在 iPhone 128GB 起步的时代可接受
- 存储管理功能（如空间占用统计、旧题压缩）列入 v1.5 考虑
- **iCloud 空间风险（v1.5 考虑）**：Pro 用户开启同步后，2000 题 ~400MB 可能占满 5GB 免费 iCloud 空间。需在设置页提供 iCloud 空间占用状态提示，空间不足时引导用户清理或升级 iCloud+

## 字段可配置系统（2026-03-07 确立）

**核心理念**：题目需要多少分类字段，由用户决定，而非开发者硬编码。

### 字段分层

| 层级 | 字段 | 行为 |
|---|---|---|
| 固定字段 | 题目内容（文字/图片） | 永远存在，不可关闭 |
| 默认开启 | 学科 | 新用户开箱仅此一项，可在设置中关闭 |
| 默认关闭 | 难度、来源、年级、答案 | 用户按需在设置中开启 |
| 自定义标签 | 用户自由创建的标签（如"易错""考前必看"） | 始终可用，不可关闭 |

### 配置入口

- **首次录入后引导**：用户完成第一次录入保存后，弹出引导提示「下次录题时要不要多填学科？」，引导用户按需开启字段。首次启动 Onboarding 不要求配置（Apple HIG："Avoid asking for setup information up front"）
- **设置阶段**：设置中提供"字段管理器"，随时开关
- **录入阶段**：录入界面只显示用户已开启的字段
- **补充阶段**：题库中编辑已有题目时，可随时扩展新字段

### 系统字段 vs 用户标签的区别（2026-03-07 确立）

- **系统字段**（学科、年级、难度、来源等）：预定义选项，在设置中开关
- **用户自定义标签**（"易错"、"考前必看"、"老师强调"等）：用户输入文字、按空格生成，完全自由创建
- 标签是个性化的核心体现——每个学生的标签体系都是独一无二的
- 当前已支持：自由输入 + 历史标签建议

### 系统字段选项管理（2026-03-16 补全）

系统字段（学科、来源、年级）的**选项列表**支持用户增删改：
- **增**：用户可新增学科（如"信息技术"）、来源（如"竞赛真题"）、年级
- **删**：已被题目使用的选项不可删除（保护数据完整性）
- **改**：重命名时级联更新所有引用该选项的题目
- **颜色**：每个选项可选择一种颜色，用于过滤胶囊和列表中的视觉区分
- **图标**：从预设教育图标集（~20 个，如📐数学、📖语文、🔤英语、🧪化学等）中选择，不使用全量 SF Symbol 选择器

设计原则：不同用户有不同的学科体系（小学 vs 初中 vs 竞赛），硬编码选项无法覆盖。

### 自动推断（与字段配置互补）

字段配置决定"字段是否存在"，自动推断决定"字段的默认值"：
- 上次选了"数学"→ 这次默认"数学"
- 上次选了"期中模拟卷三"→ 这次默认同来源
- 用户只需要改有变化的字段，其余自动填好

两者结合 = 用户只看到自己关心的字段，每个字段还自动填好了，录入摩擦降到最低。

## 连续录入设计（2026-03-07 确立）

保存题目后，默认跳转回采集界面（摄像头），而非 Dashboard。
一张试卷可能错 3-5 题，连续录入是高频场景，每多一次跳转就多一份摩擦。

---

## 一图多题设计原则（2026-03-07 确立）

真实场景：一张试卷照片上可能有多道题，用户只想录其中几道。

原则：v1.0 功能完整可用，后续每一步都是体验优化而非功能补全。
具体版本能力见 `product-requirements.md`§一图多题演进路线。

## 复习功能的克制原则（2026-03-07 确立）

- 复习是"锦上添花"，不能喧宾夺主
- **默认不推送通知**，但用户可在设置中自行开启并选择频率
- 不做打卡机制、不搞连续天数、不弹成就弹窗
- 这不是"学习打卡工具"，这是"存档工具"——复习只是附带福利
- 把选择权交给用户：有人需要提醒，有人不需要，我们尊重每个人的节奏
